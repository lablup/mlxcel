# Server prompt-lookup break-even acceptance

Copied from the original 2026-10-11 evidence directory; the historical raw files remain untouched. `m_chat.py` and `m_client.py` preserve the original workload and timing formulas. `run3.sh` runs (a), `run.sh` runs (b), chat-template C=2 (c), and 8192-token paged/dense (d), and `run2.sh` runs the paged 1024/2048/4096 cells. All arms use the exact same `SERVER_BIN`. The original three-build block A and redundant chat rerun in run2 are removed. Child commands fail fast, each measured client group has a 30-minute watchdog, server cleanup runs on failure, and existing evidence cannot be overwritten.

After builds, tests, and remote CI finish, the coordinator records the binary source commit and acquires `gpu-lock`. Run `gpu-lock run --tag pl-break-even -- bash docs/benchmark_results/data/server-prompt-lookup-break-even-gb10-2026-10-11/run_all.sh` from this checkout. Set `BINARY_SOURCE_COMMIT` to the exact 40-character source commit used for the release build. Set `REPO_ROOT`, `SERVER_BIN`, and `MODELS` if using an external release build. The script records checkout state and binary hashes before and after. Capture the native MLX pin and quiet-host/CI checks alongside these outputs. If any cell fails, preserve the entire attempt and use a new directory for any diagnostic/tuning run; do not overwrite it.

The 4-token threshold covers the 3.91-step steady width-8 verify cost, with transition costs amortized over consecutive copy blocks emitting eight tokens. It does not claim to cover an isolated wide verify plus its entire pipeline transition. A width-3 round costs 1.76 plain steps before the switch/re-prime gap; repeated two- or three-token emissions do not amortize this gap. Two actual verify samples, not retracted asks, establish the emission EMA. Both EMA and the latest emission must fall below the floor: a round already meeting break-even can repay startup EMA debt. The floor is capped at max_draft + 1 so explicit narrow blocks can meet it. The acceptance tables must confirm this operating point and the shorter re-prime wait; until measurement completes, neither is a performance claim.

`analyze_break_even.py` rejects missing/duplicate records, invalid rates and incomplete 256-token requests. It gates (a) on median paired round delta >= -1%, (b) each request's median paired gain >= 90% of the corresponding historical gain, (c) C=2 on/off ranges not showing a disjoint regression, and (d) `new_ratio >= 1 + 0.9 * (historical_ratio - 1)` (90% of the gain, not 90% of the ratio). Paged 8192 is a gate-closed control, not a preserved-gain cell. Original `analyze.py` is retained for provenance; use the new analyzer for this reduced concurrency matrix.

`diagnose_context.sh` is a pre-acceptance diagnostic, not part of the final matrix. Its `diagnostic-context-*` artifacts have separate provenance with `purpose: pre-acceptance-context-diagnostic`; the final analyzer accepts only `purpose: final-acceptance`. If diagnostics lead to a cap or governor change, rebuild and pass the new `BINARY_SOURCE_COMMIT` for `run_all.sh`. The native pin is derived through `scripts/ci/mlx_pinned_commit.sh` and checked against the binary-source commit; the coordinator separately checks the fetched native source used by the build.

Arm metadata comes from the running server's `/proc/PID/exe` and `/proc/PID/cmdline`, not from the expected filename. The analyzer rejects a wrong executable, model, draft flag, storage arm, draft kind, inconsistent counters, any off-arm verification, and any paged-8192 verification. Copy cells that are expected to verify must report accepted proposals. `test_analyzer.py` exercises the complete synthetic matrix plus missing/wrong arms, paged-8192 counters, native-pin drift, and threshold edges; its fixtures live in `/tmp`.
