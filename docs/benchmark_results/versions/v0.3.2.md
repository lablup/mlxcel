# Benchmark decision archive — v0.3.2

[Benchmark index](../README.md)

This groups records by the first stable release tag containing the report, verified from Git trees, not by filename dates. It is **not** a benchmark of that release binary. Each linked frozen record preserves the actual measured commits (including dirty/branch builds), hardware, model, flags, repetitions, dispersion, attribution and unmeasured cells. Later corrections present at the consolidation snapshot are included; decisions describe the experiment, not necessarily today's defaults. `unreleased` means no stable tag yet contains the report.

## Fused QKV+QK-norm+RoPE decode path on GB10 (CUDA)

The fused QKV/QK-norm/RoPE primitive was 3.7–7.6% slower on the wired GB10 models. Keep MLXCEL_FUSED_QK_NORM default-off; CUDA did not supply the backend-specific win missing from the earlier M1 Ultra/M5 Max measurements.

[Full record and reproduction](https://github.com/lablup/mlxcel/blob/2dc8ed47b30dc204d892328098e8cc34ec02ddc1/docs/benchmark_results/fused-qk-norm-decode-gb10.md); [#326](https://github.com/lablup/mlxcel/issues/326), [#341](https://github.com/lablup/mlxcel/issues/341).

## Gemma3n decode profile on M5 Max (#329 follow-up)

M5 Max Gemma3n decode was 92–96% GPU-bound with FFI hidden. Raising the command-buffer op budget was at most +1.7% inside noise, unlike M1 Ultra; forcing the existing fused path was neutral rather than the historical -6.3%. No new compiled fusion was justified, and the validated split path remained the default.

[Full record and reproduction](https://github.com/lablup/mlxcel/blob/2dc8ed47b30dc204d892328098e8cc34ec02ddc1/docs/benchmark_results/gemma3n-decode-profile-m5max.md); [#329](https://github.com/lablup/mlxcel/issues/329), [#60](https://github.com/lablup/mlxcel/issues/60), [#345](https://github.com/lablup/mlxcel/issues/345).

## Gemma3n decode profile: is a compiled fusion justified? (#329)

M1 Ultra Gemma3n profiling found GPU dispatch-gap idle rather than a fusable small-op hotspot; Rust graph construction was hidden by async evaluation. A command-buffer knob recovered 11–13%, while existing useful fusions already shipped. Do not build a new compiled fusion on this evidence or apply the buffer setting to M5 without its separate measurements.

[Full record and reproduction](https://github.com/lablup/mlxcel/blob/2dc8ed47b30dc204d892328098e8cc34ec02ddc1/docs/benchmark_results/gemma3n-decode-profile.md); [#329](https://github.com/lablup/mlxcel/issues/329), [#60](https://github.com/lablup/mlxcel/issues/60).
