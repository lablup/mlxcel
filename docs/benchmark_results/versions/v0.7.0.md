[Benchmark index](../README.md)

This groups records by the first stable release tag containing the report, verified from Git trees, not by filename dates. It is **not** a benchmark of that release binary. ## Embedding and rerank throughput on GB10 (epic #1348)

The first GB10 embedding/rerank campaign established the 20-checkpoint workload ladder, including single-image forwards and the transport cost of late-interaction JSON. ## MoE batched decode attribution on M1 Ultra (#1616)

The M1 Ultra Qwen3-MoE bottleneck was serialized per-row graphs, not expert-overlap traffic. A batched fused-kernel prototype lost to gather_qmm from four tokens (11.1 versus 9.3–9.7 ms per 48 layers), so it was rejected. The useful direction was a real model batched forward; op-level deduplication would not solve the measured production limit.

[Full record and reproduction](https://github.com/lablup/mlxcel/blob/2dc8ed47b30dc204d892328098e8cc34ec02ddc1/docs/benchmark_results/moe-batched-decode-m1ultra-2026-09-04.md); [#1616](https://github.com/lablup/mlxcel/issues/1616).

## `qmv` float accumulators below Ampere: V100 before and after

Using float accumulators for pre-Ampere bf16 4-bit qmv raised Qwen3.8 decode from 4.55 to 8.49 tok/s (1.87x) and Gemma 4 12B from 8.05 to 13.95 (1.73x); the 8-bit control stayed 14.98–14.99. These are warm-cache decode slopes across repeated 40/120-token runs, not first-token rates. Generated-code checks showed Ampere-and-later SASS unchanged; GPU/runtime coverage remains that of the measured V100.

[Full record and reproduction](https://github.com/lablup/mlxcel/blob/2dc8ed47b30dc204d892328098e8cc34ec02ddc1/docs/benchmark_results/qmv-float-accum-v100-2026-08-31.md); [#1539](https://github.com/lablup/mlxcel/issues/1539), [#1536](https://github.com/lablup/mlxcel/issues/1536).

## Volta (sm_70) baseline: throughput, roofline attainment, and kernel profile

The Volta baseline separates steady decode, first-token fixed cost and kernel attribution so follow-ups do not optimize the wrong term. A compile-only sm_70 gate was chosen deliberately; no GPU-backed Volta CI runner was added. Its later fixed-cost and accumulator records refine this baseline, which is not a current cross-GPU ranking.

## Volta (sm_70): what the fixed first-token cost is actually made of

The large prompt-independent Volta first-token term was primarily weight materialization: about 78% of short-prompt first-token time was page-cache-to-device transfer inside first eval. Do not attribute it to graph replay or steady decode. The later pinned-staging/eager-load work measures the proposed remedies on GB10 separately.
