# Benchmark decision archive — v0.8.0

[Benchmark index](../README.md)

This groups records by the first stable release tag containing the report, verified from Git trees, not by filename dates. It is **not** a benchmark of that release binary. Each linked frozen record preserves the actual measured commits (including dirty/branch builds), hardware, model, flags, repetitions, dispersion, attribution and unmeasured cells. Later corrections present at the consolidation snapshot are included; decisions describe the experiment, not necessarily today's defaults. `unreleased` means no stable tag yet contains the report.

<a id="adaptive-prefill-chunk-gb10-2026-10-11"></a>

## Adaptive server prefill chunks (GB10, 2026-10-11)

The adaptive server default uses 2048-token prefill chunks alone and 512 while another sequence decodes. On GB10, live-stream admission ITL p95 was 54.1–55.2 ms, matching the 512-token policy, while idle TTFT remained within the explicit-2048 noise floor on both measured families. Explicit overrides pin both states.

[Full record and reproduction](https://github.com/lablup/mlxcel/blob/2dc8ed47b30dc204d892328098e8cc34ec02ddc1/docs/benchmark_results/adaptive-prefill-chunk-gb10-2026-10-11.md); [#2228](https://github.com/lablup/mlxcel/issues/2228), [#2268](https://github.com/lablup/mlxcel/issues/2268).

<a id="b1-decode-overhead-gb10-2026-10-11"></a>

## B=1 terminal decode overhead (GB10, 2026-10-11)

Profiling rejected the proposed B=1 host micro-optimizations because each fell below 0.1%. Skipping two unused terminal lookahead forwards met the -1% no-regression gate in all four Qwen/Llama cells; median deltas ranged -0.16% to +0.57%, overlapping null ranges rather than proving speedup. A mutation test verified the forward count. Qwen prompt-cache miss/hit divergence reproduced with the new guard unreachable and remains outside this optimization.

[Full record and reproduction](https://github.com/lablup/mlxcel/blob/2dc8ed47b30dc204d892328098e8cc34ec02ddc1/docs/benchmark_results/b1-decode-overhead-gb10-2026-10-11.md); [#2227](https://github.com/lablup/mlxcel/issues/2227).

<a id="cuda-graph-budget-gb10-2026-09-12"></a>

## CUDA graph capture budgets on GB10: op and byte limits against model shape (2026-09-12)

Do not expand the CUDA graph-capture allowlist beyond Laguna on this evidence. Qwen3-MoE gained 20.6% in single-stream decode but no resolved batched-serving benefit, with slower prefill and higher peak memory. Qwen3.5-MoE gained 22.5% single-stream but lost 10.7% at concurrency 8 and increased prefill time/memory. A single-stream win is insufficient for a serving default.

Fold shared-weight CUDA QuantizedMatmul inputs from independent batch entries into rows so batched decode can reuse weights. ## Draft block width as a per-device default (GB10, 2026-09-20)

Measured optimal draft width depends on quantization/kernel dispatch, not one universal constant: affine throughput plateaued at widths 2–4 while NVFP4 improved to 7 before its dispatch cliff. Laguna's measurements required the inexact override and its shipping probe declined every width, so no default was justified there. The affine sweep predates the corrected prefill and requires the subsequent remeasurement.

## Fused MoE decode on GB10: a per-process JIT compile, not a slow kernel (2026-10-22)

The GB10 Granite regression was per-process custom-kernel JIT cost, not slower fused decode. Server latency, Metal and ROCm were not measured; a server already amortizes compilation over its lifetime.
