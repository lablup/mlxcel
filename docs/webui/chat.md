# Local chat

The Chat screen uses the existing authenticated `/v1/chat/completions?autoload=false` transport. Choose a model in the conversation header, load it there or in Models if it is not Ready, then send a message. Choosing a model is never a load action. Each turn records the opaque model ID, catalog revision, actual inference ID, start time and numerical request parameters before dispatch. A model change never reroutes the request already running.

## Layout

The route fills the content pane and the page itself does not scroll: below the page header, a conversation list sits beside the conversation. At 961 px and wider the list is a pane of its own; at 960 px and below, the shell's compact breakpoint, it moves into a start-side Drawer opened from a header button, which closes on selection and closes itself if the window widens past the breakpoint. The conversation pane stacks a header (the conversation title and the model picker), the message list, which is the only scrolling region, and a pinned footer with the request error, the composer and the live status line. Windows narrower than 320 px or shorter than 560 px (the 195 px floor, 200 percent zoom, short landscape phones) fall back to normal page flow with a minimum message-list height, still without horizontal scrolling. While a Chat Drawer is open the screen behind it is inert.

The list shows one row per conversation, newest activity first, with its title, the model of its last turn and a relative time that refreshes every 30 seconds. The current row carries `aria-current="true"`. A row is one click to switch; Up, Down, Home and End move between rows and Tab still reaches every control. Each row has Rename, an inline field that commits on Enter or blur, cancels on Escape, ignores both during IME composition and keeps at most 120 characters (a blank name keeps the old one), and Delete, which asks first. Switching, renaming and deleting are disabled while a request, a history operation or an image load is running. The only New conversation button is in the page header; at the 50-conversation cap it is disabled, with the reason in a tooltip and as a visible note above the list.

Each turn is two messages. The prompt sits at the inline end under a "You" label and its send time; the answer sits at the inline start under a badge with the model's display name, a state label and its completion time. Turns imported from version-1 history have no known time and show none. While a turn streams its label counts elapsed seconds once a second; afterwards it reads Done, Stopped, Did not finish or Failed. Status copy never prints the raw status value. Reasoning is a collapsed disclosure rendered as plain muted text with a leading rule, tool calls are cards marked as not executed, and errors are alerts. Each message has a toolbar that appears on hover and keyboard focus with a fine pointer and is always shown for touch and coarse pointers: Copy prompt and Edit and regenerate on the prompt; Copy response, Retry and Response details (finish reason, usage, client timing and the frozen parameters) on the answer. Retry appears only on a conversation's last turn when it failed or did not finish, and is disabled exactly when Send would be refused (a request, a history operation or an image load running, or the selected model not Ready to chat). It re-sends that turn's stored prompt and images through the same path as Send, in place of the failed turn, without touching the composer draft. Automatic scrolling follows new output only while the reader is at the end and not selecting text; otherwise Jump to latest appears.

The composer is an attach button (only when the selected provider confirms vision input), the message field, which grows from one to eight rows and then scrolls, and Send, replaced by Stop while a request runs. Below it one line holds the character counter, which turns to the error color with a "Limit reached" suffix at 32,000 characters, and the keyboard hint as a tooltip.

## Next-turn parameters

Chat reads the canonical memory-only generation defaults saved in Settings. Open the settings drawer (the header's Chat settings button) and use **Parameters for next turn** to override supported numerical fields for one request. While any override is set, the page header shows an "Overrides: max_tokens, seed" badge listing them in field order; it opens the drawer on that section. Nonblank overrides win over Settings; blank overrides inherit Settings, and fields absent from both are omitted so the server supplies its own defaults. Invalid or nonfinite inputs prevent sending rather than silently falling back. Overrides are consumed only after the browser admits the request, even if transport later fails; edits made while a turn is running apply to the next turn. Clear next-turn overrides does not change Settings or the server. These controls never persist a system prompt or secret.

## Interaction and cancellation

Enter and Cmd/Ctrl+Enter send outside IME composition; Shift+Enter inserts a newline. In the composer, Cmd+N on Apple platforms and Ctrl+N elsewhere start a new empty conversation, leaving Ctrl+N as the native caret-movement binding inside a macOS textarea, and nothing fires while composition is active (`isComposing` or keyCode 229). A new conversation is refused at the 50-conversation cap and while a request, history operation or image load is busy. New, rename, delete, system prompt, copy, retry and explicit edit-and-regenerate are local conversation operations. Editing asks before discarding that response and subsequent turns, and deleting a conversation asks before removing it; both confirmations re-check the conversation when answered. Reasoning is collapsed by default; tool calls are inspectable structured text and are never executed. A response must include a finish reason, nonempty content/reasoning/tool data, and a complete SSE stream before it becomes complete. Network errors, authentication loss, navigation and Stop do not retry generation or mark a partial answer successful.

Stop aborts the transport and retains cancelled partial output. A follow-up runtime observation is useful diagnostic context, not a per-request cancellation receipt. The isolated real-browser acceptance harness separately observes the server's request lease count rise and return to zero after Stop. Closing a page never unloads a shared model.

First-delta latency is client-observed send-to-first-content/reasoning/tool-delta time, including transport. Usage is reported by the server, never counted from words. The optional decode rate is explicitly a client estimate: `(reported completion tokens - 1) / (stream duration - first-delta latency)`. Missing usage/timing remains unknown, not zero.

## Settings drawer

One header button opens an end-side Drawer with three sections: the current conversation's name and system prompt (with a hint when no conversation is current), the next-turn parameters and local history and privacy. The shared Drawer keeps its content mounted while closed, so local-history persistence keeps running whether or not it is open. Tab cycles at the panel's currently enabled controls rather than a set fixed when the drawer opened, so a field disabled while a response streams (the system prompt, next-turn parameters and history controls) never stops Tab short of the panel's last usable stop. Escape closes it, except an Escape that only ends an IME composition, and focus returns to the button that opened it, or, if that was the header's overrides badge and clearing the overrides inside the drawer removed it, to the settings button instead. The history confirmations render outside the drawer panel, so their Escape closes the dialog and leaves the drawer open.

## Load from Chat

The model picker in the conversation header lists Ready chat models first, then models that are loading, draining or unloading, then unloaded and failed models, each group by display name. Models with no chat capability are left out, except the current selection, which is always listed last as not available for chat. The shared Select has no option groups, so the group is each option's position plus a state line under its display name, and the trigger shows the display name only. The picker sits in the header rather than the pinned composer because the shared Select always opens its list below its trigger.

Choosing a model only selects it. When the selection is not Ready, the header shows why: a Load button with a short hint for an unloaded or failed chat model, a wait hint while it loads or while a load is already pending, or a link to Models when it cannot load here (unsupported, incomplete, not runnable on this backend, or loading disabled). Load asks first: the confirmation names the model, says that loading starts a server operation that reserves memory and keeps running if you leave Chat, and repeats the pending next-load profile notice when one is set. Confirming re-checks that the model is still in the catalog at the same revision and still loadable, then sends the same request as the Models library through `webui/src/features/models/load-action.ts`: one `load` model action with the model's `expected_revision`, a fresh idempotency key and the next-load profile when it sets a field. A `conflict` response opens the Models capacity dialog, whose eviction choice is validated and sent through the same helper. Errors use the Models library copy. Once the catalog reports the model Ready, the Load button goes away and Send enables; nothing is sent automatically.

## Rendering and local images

Output is untrusted. The deliberately small Markdown subset supports paragraphs, headings, lists, fenced code, inline code/emphasis and safe HTTP(S) links. It does not interpret raw HTML; Markdown images are blocked. The code highlighter is a local lazy-loaded module, not a network dependency. Incomplete streaming code remains plain text. A turn is bounded to 256,000 stored output characters, Markdown display to 65,536 characters and 512 blocks, input to 32,000 characters, and stream updates are batched at 50 ms. Historical immutable turns are memoized; copying/selecting or scrolling away from the end disables automatic scrolling.

Images require a ready provider's `vision_input` capability. Only local PNG, JPEG and non-animated WebP are accepted; no remote URL, SVG, HTML, camera, audio or filesystem path input is exposed. The browser applies additional safety ceilings of four new images per turn, 8 MiB per image, 4096 pixels per dimension and 16 million pixels. These are **browser ceilings**, not claims about server configuration. Signature/header checks precede optional browser decoding; platforms without the decoder API leave full decode validation to the server.

Bootstrap `media_limits` projects the actual resolved image-count, payload, width, height and decoder-allocation authority. Its body budget is the actual inference JSON cap, additionally limited by the router's dispatch buffer in router/model-free mode; the separate 2 MiB administrative control limit does not cap chat. All historical and new image parts are checked together against current server limits. The complete UTF-8 serialized JSON request, including base64, system prompt, transcript and envelope, must fit the lower of the server budget and the explicit 16 MiB browser request ceiling.

## Privacy and storage

History is memory-only unless the user explicitly enables origin-scoped IndexedDB. Signing out clears in-memory chat. No bearer credential is written by chat; browser history does not reuse server Responses stores. Opt-in history must be enabled again after reload before previously saved data is read. Disabling saving stops writes but does not erase old data: Clear All explicitly deletes both saved and in-memory conversations. Imports replace current history only after validation and confirmation.

History uses a strict versioned schema with 50 conversations, 1000 total turns and a 16 MiB aggregate serialized budget. Exports and saves are payload version 2, whose turns carry `startedAt` (epoch milliseconds, a non-negative safe integer no greater than 8.64e15, the largest time a `Date` can hold; an import past that bound is rejected). Version-1 files and saved history still import; their turns get `startedAt` 0, which the UI treats as an unknown time. A conversation's `updatedAt` and a turn's `elapsedMs` keep their own looser bounds, so an import that pushes past what a `Date` can hold still loads: the list keeps that conversation's relative time without a machine-readable timestamp, and the affected message shows no clock, rather than failing to render. The IndexedDB database version stays 1, since only the JSON payload inside it changed and a higher database version would lock older builds out. Save/import/export reject unknown fields and unsupported versions, and report quota/unavailable-storage errors. Restored streaming turns become interrupted. Image bytes are excluded unless separately consented, bounded to 8 MiB total when saved, and revalidated against current image constraints before restoration. Import/load/delete operations fence late callbacks and temporarily prevent conflicting chat actions.

## Component reuse

Chat composes the `@lablup/ui-common@0.1.0-alpha.19` adapters in `webui/src/design-system`: `PageHeader` for the title and header actions, `Button` and `IconButton` for every action (message toolbars, row Rename and Delete, attach, keyboard hint, settings and list toggles), `Select` for the model picker, with the option `description` the adapter forwards, `Badge` for the model and state labels, `Tooltip` for the keyboard hint and the conversation cap, `Drawer` for the settings drawer and the compact conversation list, `EmptyState` for an empty list, `Field` for names and parameters, `ErrorBanner` for request errors and `ConfirmDialog` and the Models `ConfirmAction` for the edit, delete, load, history and capacity confirmations. The Drawer adapter takes `width="medium"` and `side="end"` options, which only add modifier classes over its constant inline width. The conversation rows are native buttons, because a list row needs `aria-current` and a multi-line layout that the shared Button does not forward. Native textareas, hidden file inputs, the reasoning disclosure, transcript sections and download anchors are product-specific semantic compositions, not reimplemented library controls. Styling uses the approved shared shell and tokens; no floating-panel theme, external font, CDN or package source copy is added.

The screen is split by responsibility: `chat.tsx` owns state and the request flow (send, stop, retry, edit, delete, switching and drawer state), and `conversation-list.tsx`, `message-list.tsx`, `composer.tsx`, `model-picker.tsx` and `settings-drawer.tsx` render it.

## Validation boundary

Unit and contract tests are not real-model or native accessibility acceptance. `webui/tests/chat.spec.ts` exercises hosted browser fixtures at 1440 and 390 pixels, IME, untrusted output, 10,000-token-sized rendering, accessibility and storage absence, role alignment, the settings drawer, the compact list drawer, the Ready-first picker with a confirmed Load that sends one model action, the elapsed-seconds streaming label, and a 30-turn conversation at 1440x900 in which the composer stays in view and only the message list scrolls. Its reported render time is fixture-to-DOM time, not inference throughput. Existing visual baselines are not silently regenerated.

Root-owned real acceptance requires an isolated secured production server, an already loaded model and no competing request producers:

```sh
MLXCEL_CHAT_REAL_URL=http://127.0.0.1:8080/webui/ \
MLXCEL_CHAT_REAL_KEY_FILE=/private/path/session-key \
MLXCEL_CHAT_REAL_MODEL_ID=mdl_opaque_id \
MLXCEL_CHAT_REAL_ISOLATED=1 \
pnpm --dir webui exec playwright test --config playwright.chat-real.config.ts
```

The harness checks the actual served CSP, blocks unexpected external requests and requires zero CSP violations, then checks automated accessibility and layout on completed and cancelled chat states. It captures the real rendered reply for human semantic review and observes a positive request lease before Stop and zero afterward. The short request uses a 128-token override, and the Stop request uses a 1024-token override; these are bounds, not a guarantee that a model will avoid early EOS. Failure to observe an active request is a failed acceptance, not a skipped pass.

Repeat with a dense and hybrid/MoE checkpoint. For an actual provider-supported VLM, also set `MLXCEL_CHAT_REAL_IMAGE_FILE` to a known local PNG/JPEG/WebP fixture and inspect the captured response for sensible content. Missing configuration fails rather than skips. Manual Safari/VoiceOver and actual native 200% page zoom are deferred to the final integrated session at the maintainer's request, not recorded as passed.
