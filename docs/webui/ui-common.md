# Shared ui-common integration

All WebUI feature pages consume `webui/src/design-system/primitives.tsx`; they must not import package components directly, fork adapter CSS, or create a second auth/cache layer. Package imports stay in the `webui/src/design-system/common-*.tsx` adapter seam (`common-adapters`, `common-table`, `common-tabs`, `common-select`, `common-drawer`, `common-overlays`, `common-feedback`, `common-layout`, `common-data` and `common-theme`) plus the stylesheet entry `webui/src/ui-common-entry.css`. The first-paint modules (`app.tsx`, `design-system/shell.tsx`, `provider-surfaces.tsx`, `command-palette.tsx`) import those seam modules and `local-components.tsx` directly instead of the barrel: the bundler keeps whatever a barrel re-exports in the chunk that imports it, so importing `primitives.tsx` from the entry would pull every screen's controls into the first bundle.

The dependency is pinned exactly to `@lablup/ui-common@0.2.0-alpha.19`, which re-exports Astryx 0.7.0 one to one (`@lablup/ui-common/<Component>`, `@lablup/ui-common/lab`) and adds Lablup's own components. Its peers are pinned exactly too: `@astryxdesign/lab@0.7.0-canary.97a0d31` (the lab Drawer) and `@stylexjs/stylex@0.19.0` (the StyleX runtime; no compiler runs in this build, Astryx ships compiled CSS). `@lablup/ui-common-cli` is a dev dependency at the same version. `webui/pnpm-workspace.yaml` declines the Astryx postinstall scripts (pnpm 11 `allowBuilds`) and overrides `@astryxdesign/lab>@astryxdesign/core` to `0.7.0`, so lab components run on the one copy of core; `src/design-system/ui-common-dependencies.test.ts` fails when the lockfile resolves a second core. ESLint rejects any `@astryxdesign/*` import, `import()`, `require()` or `typeof import()` in the WebUI sources. The lockfile retains the published tarball integrity; source is not vendored.

## Export matrix

| Product export | ui-common / Astryx component and what the adapter keeps |
|---|---|
| Button / IconButton | Astryx `Button` (icon-only for IconButton). The product prop surface is explicit (tone, busy, disabled, type, the handlers and ARIA attributes the call sites use, `title`, test and other `data-*` attributes); arbitrary native props are not advertised. Tones map primary, secondary, danger to destructive, ghost. Astryx requires a string `label`: the adapter passes the caller's `aria-label`, or the visible text of the children with separate pieces joined by a space, which Astryx uses as the accessible name whenever the children are not that plain string. Busy is Astryx `isLoading` (spinner, `aria-busy`, native disabled and a visually hidden "Loading" announcement in the catalog language). IconButton keeps its native `title`. `tone="danger"` keeps the outlined control and draws the glyph in `--color-error`. |
| StatusBadge | Astryx `StatusDot` (decorative here, drawn in the label's color) beside the visible domain label, in the product pill; `appearance="inline"` drops the pill for running text (the toolbar's loaded-model chip). Lifecycle maps unloaded to neutral, loading to accent, ready to success, draining and unloading to warning, failed to error. |
| ProgressBar | Astryx `ProgressBar` with its label visually hidden; an undefined or nonfinite value is `isIndeterminate`, finite percentages clamp to 0-100, and the product label is the bar's name (through `aria-labelledby`). |
| EmptyState | Astryx `EmptyState` with `headingLevel={2}`, the product icon and the caller's action in `actions`. |
| Tabs | Astryx `TabList` with `role="tablist"` and one `Tab` per section; the adapter renders the active panel, linked both ways (`aria-controls` / `aria-labelledby`, ids prefixed with `useId`). Selection follows focus: an arrow, Home or End key moves focus and selects, as the product's tabs always have (Astryx alone activates manually). The IME capture guard stays. |
| Select | Astryx `Selector`, always as a popover (`presentation="popover"`, never the narrow-viewport bottom sheet), with the localized empty text. It supplies the combobox role, `aria-busy` and `aria-invalid` itself; the product hint and error stay below it and describe the trigger. An option's description is part of its name (label, then description). |
| DataTable<T> and column/state types | Astryx `Table`. The product column shape (`id`, `header`, `render`, `className`, `fixedWidth`, `sortable`, `sortComparator`, `sortValueAccessor`) and the controlled sort (`sortColumnId`, `sortDirection`, `onSortChange`, a third activation clears) are kept; sorting renders through Astryx's `useTableSortable` header buttons and `aria-sort`, and the adapter applies the active column's comparator to the caller's rows. Header and cell alignment are Astryx's defaults; the adapter takes no alignment prop. `fixedWidth` is Astryx's `pixel()` column width (the Models Actions column, so its buttons never truncate); a column without one gets no Astryx minimum, and the table plugin that carries column classes and `rowClassName` to the cells and rows drops its inline proportional header width so a product stylesheet can size it (the Activity slot shares). The loading and empty states render in Astryx's empty-state row. The scroll box is the adapter's own (`.ds-table-scroll`), so `overflowRegionLabel` / `useOverflowRegion` keep making it a named, focusable region only while it overflows. `activateRowPrimary` keeps whole-row activation through the row's `ROW_PRIMARY_CLASS` control; rows keep their native role and gain no tab stop, and the loading and empty rows stay inert. |
| StaticTable | Legacy semantic markup table retained only for the gallery fixture. New feature tables must use DataTable<T>. |
| Dialog / ConfirmDialog | Retained native `showModal()` dialog with the product focus restoration (including the fallback to a named page heading, and to an open Drawer's close button when the opener went away). It now joins Astryx's layer stack, so one Escape closes only the top-most layer: a confirmation opened from a Drawer closes and the Drawer stays. ui-common 0.2 ships a `Modal`; moving onto it is a follow-up. |
| Select and Tooltip inside Dialog | Still the native select and in-place tooltip markup under `NativeModalContext`. Astryx 0.7 layers stay inside the nearest native dialog, so these exceptions are no longer required; removing them is a follow-up. |
| Tooltip | Astryx `Tooltip`. Keyboard focus (`:focus-visible`) and hover show it, Escape dismisses it through the layer stack, and the wrapper adds no box or tab stop. The control is described by an always-present hidden node; the adapter removes the id Astryx adds for its own content, which exists only once shown, so the description is read once whether or not the tooltip is showing. |
| Drawer | ui-common's lab `Drawer`, a native modal `<dialog>` (`showModal()`): the browser keeps the page behind it inert, Astryx's layer stack closes it on Escape (ignoring an Escape that ends an IME composition) and it returns focus to its opener. The lab Drawer renders no header, so the adapter renders the localized title (`aria-labelledby`) and the close button, which carries `data-autofocus` and receives focus on open. `width` (`narrow` 320 px, `medium` 520 px) and `side` map onto the Drawer's own props; adapter CSS keeps the approved inset, rounded sheet. The adapter still wraps Tab at the panel's usable first and last stops in the capture phase, because Astryx's trap counts the contents of a closed `<details>` (the Models inspector's Details disclosure). The shell waits for the drawer's exit before moving focus to the desktop sidebar when the viewport widens past 960 px. |
| ErrorBanner | ui-common `ErrorState` keeping the `ErrorBanner` name and props. A ref bridge still removes the package's `role="alert" aria-live="polite"` from its inner block and sets `role="none"` on its h2 title, so the section stays the only live region (`role="status"` for info, `role="alert"` otherwise) and adds no heading. |
| Card | Astryx `Card` with `.surface-card` and the product role (`article`, or `region` for a named focusable container). |
| PageLayout | ui-common `PageLayout` (wide variant) as the shell's content column, keeping `.app-content`. |
| PageHeader | ui-common `PageHeader` on every route. Its h1, description and error block still take no attributes, so a ref bridge applies the title, description and error test ids and makes the h1 the route's dialog focus fallback (`tabIndex=-1`, `data-dialog-focus-fallback`) on every render. A Retry always carries a localized `retryLabel`. |
| StatCard | ui-common `StatCard`; its loading skeletons are Astryx skeletons, always decorative, so no bridge is needed and the caller keeps one localized status for the waiting tiles. |
| LoadingStatus | Decorative Astryx `Skeleton` rows under one visible, localized `role="status"`. |
| SmoothHeight | ui-common `SmoothHeight`, active only while an operation is in flight plus a 400 ms settle window. |
| Badge | Astryx `Badge`: neutral, `accent` (info) and `warning`, with adapter CSS for the readable warning pair and the outlined accent badge. |
| Field / Toggle / password login / auth / inspector / list / shell / icons | Product-specific semantic wrappers with no equivalent package control (`local-components.tsx`). |

### Bridges re-audited for 0.2

Dropped because 0.2 provides the outcome: the EmptyState heading-level bridge (`headingLevel`), the Select combobox-role and `aria-busy` bridge, the StatCard skeleton bridge (Astryx skeletons are decorative), the Drawer test-id bridge (`data-testid` prop), its first-open focus hand-off (`data-autofocus`), its outside-panel Escape and Tab handlers and IME Escape guard (native modal dialog plus the layer stack), its stale-edge Tab bookkeeping, the Tooltip wrapper's `tabIndex=-1`, and the DataTable scroll-box lookup (the adapter owns the scroll box). Kept: the ErrorBanner live-region and heading bridge, the PageHeader test-id and focus-fallback bridge, the Drawer Tab wrap at usable stops, the Tooltip always-present description, and the Tabs and Select IME guards.

## Theme and stylesheets

`webui/index.html` links `public/layer-order.css` first, which declares the cascade layers before any other stylesheet is parsed (`reset, theme, base, astryx-base, astryx-theme, ui-common, components, utilities`). `src/main.tsx` then imports `ui-common-entry.css` (the same statement, Astryx's `reset.css` and `astryx.css`, ui-common's global scrollbar rules and the lab stylesheet), the single theme entry `design-system/themes/index.css`, and `app.css`, which collects every other product stylesheet in a fixed order. The theme entry imports the two pre-built family themes (`themes/built/mlxcel.css`, `themes/built/mlxcel-glass.css`) in Astryx's own layers, then the product-only theme tokens in `@layer components`. All product stylesheets sit in `@layer components`, above every Astryx and ui-common layer, so the product look wins over the library's defaults; `design-system/ua-baseline.css` sits in `@layer base` and hands headings, paragraphs and lists back to the browser's defaults that the product stylesheets were written against, below every Astryx component layer. Feature stylesheets are no longer imported by their modules, so a lazily loaded route cannot reorder the cascade. The neutral theme's `theme.css` and `fonts.css` (a remote font) and ui-common's `legacy-tokens.css` are not loaded: the families carry every neutral token they inherit, and nothing reads a 0.1 `--token-*` name any more.

The app is wrapped in Astryx `<Theme>` with the active family's pre-built theme (`mlxcelTheme` or `mlxcelGlassTheme`, `__built: true`), its mode following the resolved color scheme, inside an `InternationalizationProvider` that loads the Astryx and ui-common Korean catalogs on demand. Each family is a `defineTheme`-style config over the built `neutralTheme` (`themes/mlxcel.theme.ts`, `themes/glass.theme.ts`) compiled by `astryx theme build`, so the Astryx and ui-common components render in the product palette and system font, and `pnpm --dir webui run check:themes` fails when the committed build drifts from its source. The root `<Theme>` writes `data-theme` (the scheme) and `data-astryx-theme` (the theme name) onto `<html>`; `applyAppearance` and the pre-paint bootstrap write the same values, so the product no longer rewrites `data-theme` after it, and the product family moves to `data-theme-family`. See [design-system.md](design-system.md#themes).

`<Theme>` still carries its runtime theme generator: it imports `generateThemeCSS` statically and only skips calling it for a built theme, so the generator cannot be tree-shaken while the app uses `<Theme>`. The built themes add two theme objects to the first bundle and keep the neutral theme object, which the generated modules read the inherited icon registry from.

## Code splitting

The first bundle holds the shell and what a fresh load shows (the session-key prompt and connection surfaces; the key lives in memory only, so every load starts signed out). The Models library, Chat, Activity, Settings and the gallery are separate chunks fetched the first time each renders, and render synchronously once loaded (`preloadRoutes()` in `app.tsx`; tests await it once). The Korean Astryx and ui-common catalogs are chunks of their own too. The initial JavaScript budget in `scripts/webui/build_bundle.py` is 256 KiB (262,144 bytes) gzip.

## Content Security Policy

The served CSP stays `style-src 'self'`. Astryx's popover layer inserts a `<style id="astryx-layer-slide-rules">` with its `@position-try` rules unless an element with that id exists; `index.html` links `public/astryx-layer-slide-rules.css` under that id, generated from the installed Astryx core by `webui/scripts/layer-slide-rules.mjs` (`ui-common-dependencies.test.ts` fails when it is stale). Only pre-built themes are used (the product families from `themes/built/`), so `<Theme>` injects nothing. Every other dynamic value Astryx writes (StyleX custom properties, anchor names and positions, the Drawer's scroll lock) goes through CSSOM, which the policy permits; `tests/browser-assertions.ts` allowlists each of them by component. Astryx features that inject styles at runtime (non-built themes, CodeBlock highlighting, Chat stream scrolling, the native DateInput) are not used.

## Recorded decisions

- `usePrefersReducedMotion` is not adopted. It reads only `matchMedia('(prefers-reduced-motion: reduce)')` and cannot see the in-app Settings toggle, which writes `data-reduce-motion`. CSS stays the only reduced-motion mechanism: `tokens.css` sets the motion tokens to 1 ms and `components.css` stops transitions and animations globally, which also covers the shared Drawer, Tooltip, SmoothHeight, Skeleton and Card. StatCard's `animate` count-up stays off for the same reason.
- `formatCompactNumber` is not adopted. `webui/src/design-system/format.ts` threads an explicit `ko-KR` or `en-US` locale through `Intl.NumberFormat`, stays the single formatter, and values reach StatCard as formatted strings.

## Verification boundary

Typecheck, lint and the Vitest suite cover props, refs and submit behavior, busy controls, lifecycle mappings, finite and unknown progress, heading levels, tab ids and selection, IME suppression, the modal select and tooltip exceptions, typed tables with row activation and overflow regions, the Drawer keyboard contract and Escape ownership, the layer order and stylesheet entries, the single Astryx core and the shipped slide rules. Unit tests use jsdom with a default `matchMedia` (`src/test-setup.ts`); they do not establish layout, native dialog inertness, CSP or VoiceOver correctness. The hosted browser suite (`pnpm --dir webui run browser`) continues axe, keyboard, reflow, 44 px-target and inline-style checks against the real DOM.

Run the served-CSP check against a server that sends the real headers:

```sh
MLXCEL_WEBUI_CSP_URL=http://127.0.0.1:8080/webui/ pnpm --dir webui exec playwright test --config playwright.csp.config.ts
```

The config starts no preview server and supplies no copied or injected headers. It requires the response's strict CSP, observes `securitypolicyviolation` events and external requests, opens the Selector list, the compact navigation Drawer and the gallery Tooltip, measures progress geometry, and asserts that no `<style>` element was inserted and the slide-rules link is present. Record which server was tested.
