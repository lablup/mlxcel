# Shared ui-common integration

All WebUI feature pages consume `webui/src/design-system/primitives.tsx`; they must not import package components directly, fork adapter CSS, or create a second auth/cache layer. Package imports stay in the `webui/src/design-system/common-*.tsx` adapter seam (`common-adapters`, `common-select`, `common-overlays`, `common-feedback`, `common-layout` and `common-data`) plus the `styles/base.css` import in `main.tsx`. The dependency is pinned exactly to `@lablup/ui-common@0.1.0-alpha.19` (React peer dependencies only). The npm `latest` tag points to an older release, so unversioned installs are not equivalent. The lockfile retains the published tarball integrity; source is not vendored and no sibling checkout is required.

The WebUI uses all 17 components that `dist/index.d.ts` exports. `grep -rn '@lablup/ui-common' webui/src/` lists one import of each component, all inside the adapter seam, plus the `base.css` import and a DataTable type re-export.

## Export and exception matrix

| Product export | Published component / ownership |
|---|---|
| Button / IconButton | Common Button, with supported props only, explicit busy/disabled/ARIA mapping, refs and submit semantics. Unsupported native props such as `onFocus`, `name`, `form` and arbitrary data attributes are deliberately not advertised. Extend the central adapter explicitly if a real consumer needs them; never cast a broad native prop bag. IconButton's `tone="danger"` keeps the outlined control and draws the glyph in `--color-error`, so a destructive action on every row of a dense list does not become a filled red button per line. |
| StatusBadge | Common StatusTag with domain lifecycle mapping and unchanged English/Korean domain labels. |
| ProgressBar | Common ProgressBar; undefined/nonfinite means indeterminate, finite percentages clamp to 0–100, and the product label remains the accessible name. |
| EmptyState | Common EmptyState with product illustration/actions; an explicit `role=heading` / `aria-level=2` ref bridge preserves the product hierarchy because alpha.19 fixes its DOM title at h3. |
| Tabs | Common controlled segmented Tabs, IDs prefixed with `useId`, callbacks translated to caller IDs, empty-array handling, IME capture guard and wrapping rather than a mobile dropdown. Callers provide unique IDs within each tabset. |
| Select | Common Select for normal pages, with localized labels and field help/error/busy state. An explicit ref bridge completes the combobox role because alpha.19 supplies active-descendant/listbox attributes on a plain button without exposing a role prop. |
| DataTable<T> and column/state types | Typed common table seam with required accessible label, stable caller-supplied opaque row keys and caller-owned column/sort state. Models and Activity must use this export. No automatic storage or API pagination/filtering is introduced. Opt-in `activateRowPrimary` makes the whole row a pointer target by delegating to the row's primary control, the element carrying `ROW_PRIMARY_CLASS` (the Models row's "Inspect {name}" icon button): a click anywhere in a body row focuses and clicks that control, so pointer and keyboard run the same handler. A click on another interactive element in the row (the Models row's Load, Use in Chat, Unload and Delete buttons), a click that ends a text-selection drag, and rows whose primary control is missing or disabled (including the loading and empty rows and the Models download rows) do nothing. Rows keep their native `row` role and gain no tab stop of their own; adapter CSS gives rows with an enabled primary control the package's pointer cursor and hover fill, and outlines the whole row while any control in it has `:focus-visible`. Opt-in `overflowRegionLabel` turns the table's own horizontal scroll box into a named, focusable `region` while its content is wider than it is, and removes both again when it fits, so a keyboard user can scroll a table whose loading or empty state holds nothing focusable (axe `scrollable-region-focusable`). Sorting stays with the caller: alpha.19 sorts the rows it is given even in controlled mode, so Models passes every sortable column a `sortComparator` that repeats its own ordering (the lifecycle pin, then the chosen column) rather than a bare `sortValueAccessor`, which would re-sort the page without the pin. In Models, the Inspect button's own `onClick` skips `actions.selectModel` when its entry is already selected, so activating the already-selected row, whether by clicking elsewhere in it or clicking the name button directly, is a no-op instead of re-aborting the live event stream and restarting the snapshot refetch that `selectModel` always triggers. The package's own `onRowClick` and `isRowClickable` are deliberately not exposed: in alpha.19 they render every body `<tr>` as `role="button"` with its own tab stop, which on the Models page fails axe `aria-required-children` (the table's rowgroup then holds buttons, not rows) and `nested-interactive` (the name button sits inside the row button), doubles the tab stops per row, and gives the row an accessible name that also matches the `Inspect .*{name}` locator the router-real harness relies on. |
| StaticTable | Legacy semantic markup table retained only for the existing gallery fixture. New feature tables must use DataTable<T>. |
| Dialog | Retained native `showModal` top-layer/focus implementation; the package has no Dialog or Modal. See the follow-up below. |
| Select and Tooltip inside Dialog | Native select and in-place tooltip markup, selected by NativeModalContext, because alpha.19 unconditionally portals popups and tooltip content into body without a portal-container option. A z-index override cannot repair top-layer ancestry. |
| Tooltip | Common Tooltip taking `content`. The package puts `aria-describedby` on its wrapper div and only while open, so the adapter clones the wrapped control with `aria-describedby` pointing at an always-present hidden description. The wrapper gets `tabIndex=-1` so an already-focusable control gains no extra tab stop. Escape dismisses the content (WCAG 1.4.13). |
| Drawer | Common Drawer as the compact off-canvas navigation below 960 px: a modal aside with the package's Escape close and opener restoration. The adapter passes one stable `onClose`, because the package re-runs its focus effect whenever `onClose` changes identity and every shell re-render would move focus. It also completes the first-open focus hand-off, which the package attempts one frame before the panel stops being `visibility: hidden`. A ref bridge puts the test id on the panel, and the localized title and close label are required. Adapter CSS keeps the approved left sheet at `min(320px, 100vw - 32px)` inset 12 px, overriding the package's right anchoring and its `width: 100vw !important` below 768 px. Chat's settings drawer and the Models inspector below 1100 px pass `width="medium"` and `side="end"`, Chat's compact conversation list the defaults; the options only add `ds-drawer--medium` and `ds-drawer--end`, whose CSS overrides the same constant inline width, so the navigation sheet is unchanged. The Models inspector drawer opens only on an explicit Inspect, row activation, or a toolbar chip or palette request, never merely because a selection is remembered. The package records its Tab cycle once, when the drawer opens, from a selector without `summary`, so a control disabled afterwards (Chat's drawer controls while a response streams) let Tab leave the panel and a Details disclosure (the Models inspector's) was never reachable. The adapter wraps Tab at the panel's first and last usable stops at the time of the key press instead, including a `summary` and skipping the contents of a closed `details`, and stops every Tab inside the panel in the capture phase so the package's stale handler never runs; for the navigation sheet's static links this is the same cycle. A capture-phase guard also keeps an Escape that only ends an IME composition from reaching the package's panel handler. The package handles Escape and Tab only from inside its panel, so the shell makes its `<main>` `inert` while the navigation drawer is open (as it was behind the native modal sheet), Chat makes its screen inert behind its drawers, and the adapter also closes on an Escape pressed outside the panel, for example after a pointer press on its heading, and moves a Tab pressed while focus is on no element into the panel at its first (Shift+Tab: last) stop, so the Models page behind its inspector is not reached either. That outside-panel handler backs off once the event is already `defaultPrevented`, so a popup that portals outside `.drawer` and handles its own Escape does not also close the drawer beneath it, and it leaves an Escape or Tab whose target is inside an open native `<dialog>` to that dialog: a confirmation opened from a drawer closes itself and returns focus to its opener in the drawer, which stays open. The shell suppresses global shortcuts inside `[role="dialog"][aria-modal="true"]` as well as `dialog[open]`, and when the viewport widens past 960 px it closes the drawer and moves focus to the desktop sidebar. |
| ErrorBanner | Adapter over common ErrorState that keeps the `ErrorBanner` name and props (`title`, `body`, `action`, `tone`, `testId`). A ref bridge removes the package's `role="alert" aria-live="polite"` from its inner block, so the section stays the only live region with `role="status"` for info and `role="alert"` otherwise. It also sets `role="none"` on the package's h2 title, so no heading lands inside sections that already own one. `action` stays a ReactNode rendered by the adapter because `primaryAction {label, onClick}` cannot express the chat anchor or icon buttons. Tones map error to danger, warning to warning and info to accent. Adapter CSS makes it the compact banner and keeps the `.ds-banner` root with its high-contrast border. |
| Card | Common BaseCard with `.surface-card` kept on the root. The adapter passes `role` (article, or region for a named focusable container) because BaseCard renders a role-less div, turns `hoverable` off for non-interactive cards, and restores the keyboard focus outline that BaseCard's `:focus-within` rule removes. Used by the gallery; StatCard builds on it. |
| PageLayout | Common PageLayout (wide variant, 1400 px cap) as the shell's content column, keeping `.app-content`. Adapter CSS drops the package's extra 0.5 rem inline padding below 768 px because `.app-content-grid` already pads the column. |
| PageHeader | Common PageHeader on every route (Models, Chat, Activity, Settings, the gallery and the ProductConnectionSurface states), always the first child of the shell's PageLayout. Route actions go in `actions`; the route's stale or action error goes in `error` and `errorDetail` with `onRetry`, typed so a Retry always carries a localized `retryLabel` (the package default is English, which is also why the dismiss control is not exposed). A ref bridge restores the title, description and error-block test ids (`errorTestId` lands on `.page-header__error`, re-applied on every render because the block mounts and unmounts with `error`) and always puts `tabIndex=-1` and `data-dialog-focus-fallback` on the h1, so each route has exactly one fallback and a dialog closing without a usable opener lands on a named heading. It has no eyebrow slot. Adapter CSS keeps the product's bold page-title typography, caps each action at the column width so labels wrap, and draws the error block like the product's error banner. |
| StatCard | Common StatCard for the Activity runtime tiles: a group named "label: value", with scope, observed time and reason in the hint slot. Values arrive as formatted strings. Adapter CSS undoes the package's label and value truncation, label uppercasing and hover lift. |
| LoadingStatus | Decorative common Skeleton rows under one visible, localized `role="status"` in the Models table loading slot. SkeletonRow and SkeletonText are not used because each mounts one status per row named "Loading"; SkeletonCard and SkeletonChart have no matching surface. |
| SmoothHeight | Common SmoothHeight around the Activity operations list. It is active only while an operation is in flight plus a 400 ms settle window, so a settled list is never height-pinned or clipped by its `overflow: hidden`. The settle window always runs the full 400 ms from the latest transition to false, so a false→true→false sequence within that window restarts it instead of releasing early. |
| Badge | Common Badge for the Models task list (one neutral badge per task, in the entry's declared output order) and its capability list, and, in the `warning` tone, for the one flag a row carries when its checkpoint is unsupported or incomplete and for a capability that is unavailable. Badges keep authored casing and do not wrap inside a row. Lifecycle state stays on StatusBadge. Adapter CSS draws the warning tone with the lifecycle badges' `--color-warning` pair instead of the package's fixed amber fill, and the accent tone as body text inside a `--color-focus` outline, because the package paints `--token-colorPrimary` text on a fixed translucent blue fill that measured 4.49:1 on a selected row in mlxcel-light and 3.7 to 4.5:1 in every theme under high contrast; `webui/tests/models.spec.ts` checks a selected and a hovered row for color contrast in all four themes with high contrast off and on. |
| Field / Toggle / password login / auth / inspector / list / shell / icons | Product-specific semantic wrappers with no equivalent package control. AuthGate and SchemaMismatchView compose ErrorBanner. |

The semantic ref bridges are narrowly scoped compatibility workarounds for the pinned API, not claims of independently verified assistive-technology behavior. Re-audit them when upgrading. Product icon SVGs remain project-authored. The bundled `third-party-licenses.txt` includes the package's published NOTICE and Apache-2.0 license verbatim.

## Recorded decisions

- `usePrefersReducedMotion` is not adopted. It reads only `matchMedia('(prefers-reduced-motion: reduce)')` and cannot see the in-app Settings toggle, which writes `data-reduce-motion`. CSS stays the only reduced-motion mechanism: `tokens.css` sets the motion tokens to 1 ms and `components.css` stops transitions and animations globally, which also covers the shared Drawer, Tooltip, SmoothHeight, Skeleton and BaseCard. StatCard's `animate` count-up stays off for the same reason.
- `formatCompactNumber` is not adopted. It abbreviates and otherwise falls back to a locale-less `toLocaleString()`, while `webui/src/design-system/format.ts` threads an explicit `ko-KR` or `en-US` locale through `Intl.NumberFormat`. `format.ts` stays the single formatter, and values reach StatCard as formatted strings.

## Follow-up: contribute Dialog upstream

The package has no Dialog or Modal, so `Dialog` stays local in `primitives.tsx` (`ModalDialog` and `restoreModalFocus`). It is the strongest candidate to contribute to `lablup/ui-common`: it carries the native `showModal()` top layer, the Tab focus trap, and Escape with focus restoration, including the fallback to a named page heading when the opener is gone, none of which the package has. A package dialog with a portal-container story would also let the NativeModalContext exceptions go away. This note is the record; no upstream issue or change has been opened.

## Theme authority

Only the library base stylesheet, one product theme stylesheet and component subpath styles are imported. `src/main.tsx` imports `@lablup/ui-common/styles/base.css` and then `design-system/themes/index.css`, the single theme entry, following the package rule of at most one theme file alongside `base.css`; no component imports a theme file. The product themes (`mlxcel-light`, `mlxcel-dark`, `glass-light`, `glass-dark`) are `[data-theme]` blocks over the published token contract, selected by the applied theme id; see [Themes](design-system.md#themes). `common-tokens.css` keeps the theme-independent half of the contract (typography, spacing, radii, control heights, motion, z-index) on `:root`. `common-components.css` scopes necessary DOM/geometry overrides to adapters, including primary/danger foregrounds, compact 44px targets and wrapped controls. No orange theme stylesheet or remote font/resource is loaded. Keep the approved macOS 27 shell topology, continuous toolbar and neutral content surfaces. PageLayout is adopted only as the content-column width container, and no package theme replaces the product tokens.

## Verification boundary

Typecheck, lint and the Vitest suite cover props/ref/submit behavior, busy controls, all lifecycle mappings, finite/unknown progress, heading roles, duplicate tabset IDs, IME suppression, modal select and tooltip exceptions and typed tables, including the row-activation guards. The `webui/src/design-system/ui-common-*.test.tsx` files and the `webui/tests/ui-common-components.spec.ts` and `webui/tests/ui-common-shell.spec.ts` browser specs pin the behavior each adoption above had to keep: live-region roles and outline, focus entry, wrap and restoration, shortcut suppression, the 390 px drawer and content column at the 200 percent text scale, test ids and focus fallbacks, untruncated tile and badge text, a single loading status, and unclipped focus rings. `webui/tests/models.spec.ts` drives DataTable row activation by pointer, by keyboard and by a text-selection drag, drives load, Use in Chat and unload through the row buttons alone, and runs axe with the inspector open as a pane and as a drawer. Unit tests use jsdom, including an explicit scrollIntoView mock; they do not establish layout, native select behavior, CSP or VoiceOver correctness.

The normal hosted browser suite continues axe, keyboard, reflow and 44px-target checks. Only narrowly identified package CSSOM geometry properties are allowed in the static DOM assertions: progress width, select popup position/top/left/width, common table header width, the Drawer panel's width with its `100vw` max-width, the Tooltip content's px top/left (or `visibility: hidden` before it is measured), SmoothHeight's measured px height and Skeleton width/height. React writes these through CSSOM, which a strict `style-src 'self'` permits, but the static assertions do not certify production CSP.

Run the separate actual-server check only after a healthy secured server containing the rebuilt bundle is available:

```sh
MLXCEL_WEBUI_CSP_URL=http://127.0.0.1:8080/webui/ pnpm --dir webui exec playwright test --config playwright.csp.config.ts
```

The config starts no preview server and supplies no copied/injected headers. It requires the real response's strict CSP, observes securitypolicyviolation events and external requests, measures popup/progress CSSOM geometry, opens the compact navigation drawer and shows the gallery tooltip, and checks keyboard close/reopen focus. A standalone server mounting the real security middleware proves that middleware boundary, not the full production CLI startup. Record which server was tested.
