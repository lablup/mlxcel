# Architecture Decision Records

This directory holds Architecture Decision Records (ADRs) for mlxcel. Each ADR captures one significant decision, the context that forced it, and the consequences that follow. ADRs are numbered sequentially and are immutable once their status is Accepted: a later decision that changes course gets a new ADR that supersedes the old one rather than editing it in place.

## Index

- [ADR 0001: Paged-attention gather strategy and KV pool tensor layout](0001-paged-attention-gather-vs-fused-kernel.md). Accepted. Adopts gather-then-SDPA for the unified paged KV cache (epic #116) and records the pool tensor layout decision, backed by `examples/page_gather_microbench.rs`.
- [ADR 0002: Turbo KV decode is split dequant plus native SDPA](0002-turbo-kv-split-dequant-vs-fused.md). Accepted. Records why mlxcel's split Turbo KV path does not reproduce the upstream turboquant_plus sparse-V `+22.8%` speedup (the V step is a negligible decode fraction in a split design), keeps dequant-SDPA (#369) as the default, and names fused V dequant (#370) as the one lever, backed by the A/B in `benchmarks/turbo_kv/`.
- [ADR 0003: Release builds unwind, and core generation threads re-impose fail-fast with a targeted abort](0003-release-panic-unwind-with-core-thread-abort.md). Accepted. Flips the release profile to `panic = "unwind"` (#375) so the deliberate `catch_unwind` request/stage backstops (audio worker `run_guarded`, pipeline stage isolation) work in production, and wraps the two core generation worker threads with `run_core_thread_or_abort` so a broken core invariant still aborts cleanly for a supervised restart. Records the no-global-abort-hook trap and the residual MLX-FFI `std::terminate` vector (#382).
- [ADR 0004: The compute-backend seam is an inference session engine, and non-MLX targets converge on a StableHLO/MLIR compiler family](0004-compute-backend-session-seam-and-stablehlo-family.md). Proposed. Reframes the load-boundary `ComputeBackend` seam from #338 / PR #446 (which returns the concrete MLX `LoadedModel`) toward a session-level, token-in/token-out engine contract that keeps the MLX hot path internal, and decides that FuriosaAI, Tenstorrent, and OpenXLA are served by one StableHLO/MLIR compiler-family backend rather than per-vendor engines. Keeps the #446 `select_backend` skeleton and `experimental-backend` gate; names the KV/scheduler coupling and the compiler-family model-definition strategy as the open follow-ups, to be Accepted once an OpenXLA reference backend validates the contract.
- [ADR 0005: Mixed prefill/decode step execution](0005-mixed-prefill-decode-step-execution.md). Accepted. Rejects ragged model-level mixing and kernel-level mixing (#908, epic #909) after finding that the tick alternation they were meant to replace does not exist: a chunked prefill parked next to a live decode batch yields every tick and starves until the batch drains, so decode streams are never blocked by prefill and the recoverable work is bounded to one decode step's linear layers per chunk. Extracts the policy into `src/server/batch/tick_policy.rs` so the tests stop asserting against a copy, ships the scheduling half behind `MLXCEL_MIXED_STEP` as a measurement instrument, and splits the starvation fix into a follow-up. That follow-up shipped as issue #1011: `--prefill-grant-interval N` (default 16) grants the parked prefill one tick after every N contended decode ticks, bounding a `C`-chunk prompt at `C * (N + 1)` ticks, and fills the ADR's open ITL cell.
