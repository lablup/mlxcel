# GELU call sites and the upstream activation each one ports

Inventory for #2423. `mlxcel_core::gelu_approx` computes the exact erf GELU despite its name, while MLX's `nn.gelu_approx` (and `nn.GELU(approx="precise")`) is the tanh approximation, so a call site's name says nothing about which formula its port needs. This file maps every non-test call site under `src/` to the formula it computes and the formula its mlx-lm / mlx-vlm / mlx-audio reference computes.

Scope: every non-test call site of `gelu_approx`, `compiled_gelu_approx`, `gelu` (erf), the sigmoid/fast variant (`gelu_sigmoid`, `gegelu`), the C++ `gelu_tanh_approx` helper and its fused users, and every private Rust tanh/erf copy. Test-only code (`*_tests.rs`, `#[cfg(test)]` modules, `xla-diagnostics` test modules) is excluded except where noted. Line numbers are at `main` 4658ae83, before #2423's changes; the rows #2423 changed are marked **changed in #2423**.

Upstream sources were read from installed copies, and every link pins the matching revision: mlx 0.32.4, mlx-lm `c39139d70` (0.32.3.dev2), mlx-vlm v0.7.8, mlx-audio v0.5.9. Hugging Face activations were read from transformers 5.20.1 (`ACT2FN`, the `*Config` class defaults, and the in-library `minicpmv4_6`, `gemma4`, `gemma3n`, `siglip` modeling code) and from the checkpoints' own `config.json` and remote code.

MLX semantics used for the "Upstream" column ([mlx/nn/layers/activations.py](https://github.com/ml-explore/mlx/blob/v0.32.4/python/mlx/nn/layers/activations.py)): `nn.gelu`, `nn.GELU()`, `nn.GELU(approx="none")` = **erf**; `nn.gelu_approx`, `nn.GELU(approx="precise")`, `nn.GELU(approx="tanh")` = **tanh**; `nn.gelu_fast_approx`, `nn.GELU(approx="fast")` = **fast** (`x * sigmoid(1.702 x)`). Hugging Face `ACT2FN`: `gelu` = erf, `gelu_pytorch_tanh` / `gelu_new` / `gelu_fast` = tanh, `quick_gelu` = fast.

Shared mlx-vlm MLP classes ([mlx_vlm/models/mlp.py](https://github.com/Blaizzy/mlx-vlm/blob/v0.7.8/mlx_vlm/models/mlp.py)): `GELUMLP` = tanh (`approx="precise"`, :36), `FastGELUMLP` = fast (:50), `TanhGELUMLP` = tanh (:65).

Verdict is mlxcel versus the mlx-lm / mlx-vlm / mlx-audio port it follows. Where upstream disagrees with the checkpoint's own Hugging Face activation, the Notes column says so, because a MISMATCH there means mlxcel follows the trained activation and the reference does not.

## 0. What #2423 changed, and what it decided not to change

New code chooses its formula through `mlxcel_core::utils::GeluActivation` (`Erf`, `Tanh`, `TanhF32`, `TanhF32Compiled`, `Fast`, plus `from_hf_name` for a config string), backed by the C++ `gelu_tanh_approx` helper the fused GeGLU kernels use. `TanhF32Compiled` is `TanhF32` as one compiled kernel (equal up to f32 rounding); the families switched in #2423 use it so the switch does not add prefill time, while the call sites folded onto `TanhF32` keep the eager, bit-exact helper. The measurements behind each decision are in [benchmark_results/gelu-erf-vs-tanh-2026-10-23.md](benchmark_results/gelu-erf-vs-tanh-2026-10-23.md).

## 0b. Final decisions for the families #2423 left open (#2548)

Decision rule, applied to every row below:

1. The checkpoint decides: its `config.json` (`hidden_act`, `hidden_activation`, `vision_config.hidden_act`, or the family's own key) and, where the key is missing, the default of the Hugging Face config class for that `model_type` (Hugging Face drops a key equal to the class default), evaluated as `transformers.activations.ACT2FN` does. Remote-code checkpoints are read from their own modeling files.
2. Cross-check against the mlx-lm / mlx-vlm port. Where the MLX port departs from Hugging Face, mlxcel follows Hugging Face and the row records the divergence.
3. Each row carries a one-line reason.

The logit-trace gate cannot tell erf from tanh (see section 0), so these are config decisions, smoke-tested with one `mlxcel generate` and one `mlxcel-server` request per family with a local checkpoint (results in the #2548 PR). Variants: "tanh (f32, compiled)" is `GeluActivation::TanhF32Compiled`, the #2423 choice for switched families; "tanh (input dtype)" is the C++ `gelu_tanh_approx` helper (`GeluActivation::Tanh`, or the fused Gemma GeGLU kernels), used where the sibling Gemma kernels and the XLA bf16 tape already compute it that way; "fast" is `GeluActivation::Fast` (`quick_gelu`).

### 2d. Shared SigLIP / CLIP encoder (`src/vision/encoders/siglip.rs`)

`VisionMLP::forward_impl` at `siglip.rs:126-130` dispatches on `VisionMlpActivation`, chosen by `select_mlp_activation` (`siglip.rs:63`) from `VisionConfig.hidden_act` (`src/vision/config.rs:34-40`): `"gelu_pytorch_tanh"` -> `PytorchTanh` (private f32 tanh at `siglip.rs:92`); **every other value, including a missing key, `"gelu"` and `"quick_gelu"`, -> `Exact` -> `mlxcel_core::gelu_approx` (erf)** unless the loader passes `use_fast_gelu = true` (-> `gelu_sigmoid`, fast).
