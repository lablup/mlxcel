# MLX pin review: 2026-11-16

## Decision

Move the reproducible CMake pin from `9f806b36` (2026-11-05, `v0.32.4-81-g9f806b360`) to `fc344c98` (2026-11-06), the head of upstream `main` on 2026-11-16. The latest stable release is still v0.32.4 (2026-10-14), which both pins postdate. The new pin is one commit ahead of the old one; nothing else has merged upstream since.

Sources: [stable release](https://github.com/ml-explore/mlx/releases/tag/v0.32.4), [exact comparison](https://github.com/ml-explore/mlx/compare/9f806b3606eaa9f7c807238f6bd465185cd94d6d...fc344c986c4169d99f76b5d95ae6b4a58a359a63).

## Upstream change

| Upstream change | Impact on mlxcel |
| --- | --- |
| [#4839](https://github.com/ml-explore/mlx/pull/4839) | `MLX_CUDA_ARCH_LIST` is passed to the compiler as one quoted macro, and `cu::get_arch_list()` splits it on commas at runtime. The old form put a quoted string per architecture into a `-D` definition, which MSVC with the Visual Studio generator rejects for a multi-architecture list. This affects Windows CUDA builds. mlxcel passes `MLX_CUDA_ARCHITECTURES` from `build.rs` and never reads the macro or `get_arch_list()`, so no mlxcel code changes. |

The commit touches only `mlx/backend/cuda/CMakeLists.txt` and `mlx/backend/cuda/device_info.cpp`. No Metal, CPU or core file changes, so the Apple build compiles the same MLX sources as before.

## Overlays

- **CPU, Metal, CUDA and core whole-file overlays.** None of the 175 overlay files (all five overlay trees) is one of the two changed upstream files, so every overlay applies unchanged. Overlay headers keep the base they were last merged from: a header names the commit the file was rebased onto, and no file needed a rebase.
- **ROCm.** `rocm_overlay.py retarget` moved `retargeted_to_mlx_pin` to `fc344c98` with no conflicts. `drift` reports the same 16 core files and the same residual as at `9f806b36`; only the `CORE_RESIDUAL.diff` header changed, rewritten by `drift --write`. The fork stays `75915908`, and `LOCAL_FIXES.md` needs no new entry.
