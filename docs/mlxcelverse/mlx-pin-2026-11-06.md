# MLX pin review — 2026-11-06

## Decision

Move the reproducible CMake pin from `7ca40033` (2026-10-26,
`v0.32.4-35-g7ca400331`) to `9f806b36` (2026-11-05,
`v0.32.4-81-g9f806b360`). The latest stable release is still v0.32.4
(2026-10-14), which the previous pin already postdated, so moving to it would
downgrade both pins. The selected main snapshot is 46 commits ahead of the
previous pin.

Sources: [stable release](https://github.com/ml-explore/mlx/releases/tag/v0.32.4),
[exact comparison](https://github.com/ml-explore/mlx/compare/7ca40033132dae444d45f7fc3daae57e24c13f6c...9f806b3606eaa9f7c807238f6bd465185cd94d6d).

These are upstream improvements, not measured mlxcel speedups. A custom mlxcel
kernel benefits only where execution actually reaches the changed MLX path.
`use_qmv_wide` is unchanged at this pin, so the QMV-wide off-switch keeps its
meaning.

## Integration

- 14 whole-file CPU, Metal and CUDA overlays were rebased from their declared
  upstream base with a three-way merge; the drift check now reports no file
  whose declared base is behind the pin. The five local-only CUDA helper
  headers (`load_staging.h`, `ptx_cache_*`, `runtime_dir.h`) have no upstream
  counterpart and are unchanged.
- **CPU overlay narrowed.** Upstream #4803 gave `_qmm` and `_qmm_t` float
  accumulation and a float scratch row, so those two bodies are now upstream
  verbatim. The overlay keeps only `fp_qmm` and `fp_qmm_t`, which upstream
  still reduces in the activation type.
- **Metal `qmv_mma` behind the QMV-wide switch.** #4787 lowered the affine
  `qmv_mma` entry to 3 rows below generation 15 and 4 rows above, so on
  generation 15 and later a verify block can reach a kernel that reduces along
  K differently from the single-token `qmv`. `use_qmv_mma` now returns false
  when `MLXCEL_QMV_WIDE=0`, which is the state the speculative exactness gate
  pins for its retry; without it, the retry could no longer restore
  byte-equality and the gate would decline MTP on those GPUs.
- Metal `quantized.cpp` also keeps the `#1599` broadcast gathered-row count
  (`B * M`) and the 5- to 8-row `mlxcel_affine_qmm_t_rows` dispatch on
  generations 13 and 14; `quantized.metal` keeps the kernel and its
  instantiations, re-appended after upstream's restructured macro block
  (#4741).
- Metal `device.cpp` keeps the runtime input-budget override across upstream's
  new `get_default_max_ops_mb_per_buffer` plus `env::max_ops_per_buffer` /
  `env::max_mb_per_buffer` path; the override is applied last, so it still
  wins when set.
- The `load_safe` tile-extent bounds (#2852) are unchanged upstream and were
  carried through the three kernel headers verbatim.
- CUDA keeps the captured child-graph barriers, the cuDNN no-plan fallback, the
  SDPA plan cache and deterministic switches, the restricted Windows DLL
  loading, the `gather_gemm` replacement, the BF16 promotion patches, and the
  `MLXCEL_CUDA_DISABLE_GEMV` diagnostic.
- **`env::get_var` moved to `config::get`.** Upstream #4647 replaced the
  `env::get_var` helpers with a `config` module, keeping only `env::max_ops_per_buffer`,
  `env::max_mb_per_buffer` and `env::enable_tf32` as thin wrappers. The cxx
  bridge's `MLXCEL_*` lookup and the six CUDA `MLXCEL_SDPA_*` switches now call
  `config::get`; the cached `static` results around them are unchanged, so each
  variable is still read once per process.
- **IOKit on the macOS link line.** #4781 added `gpu_core_count()` to
  `mlx/backend/metal/device.cpp`, which reads the `AGXAccelerator` IORegistry
  entry. Upstream links IOKit `PRIVATE`, so it never reaches a static
  `libmlx.a` consumer; `mlxcel-core`'s build script now emits
  `framework=IOKit` next to Metal and Accelerate.

## ROCm overlay

The fork stays `75915908`; only its MLX target changes. `rocm_overlay.py
retarget` three-way merged the 16 core files onto the new pin. Two conflicts
were resolved by hand: `mlx/fast.h` keeps both upstream's
`precompiled_cuda_kernel` and the fork's `hip_kernel`, and
`mlx/backend/gpu/primitives.cpp` drops the local `add_temporary` branch because
upstream #4711 donates the contiguous copy; only the ROCm device-header include
remains, and LOCAL_FIXES item 50 records the narrowing. `drift --write`
regenerated `CORE_RESIDUAL.diff` with notes for every residual, and `make
verify-rocm-overlay` passes.

## Validation

- `cargo test -p mlxcel-mlx-pin`: 52 unit tests and the cross-parser test
  passed; `scripts/ci/mlx_pinned_commit_test.sh`: 13 parser cases passed, and
  the real CMake file resolves to the new pin.
- `make verify-rocm-overlay`: records, 29 tooling checks, the allocator
  ownership mock, the runtime-directory contract and the HSACO cache checks
  passed.
- `cargo build --features metal,accelerate`: passed.
- Metal, serial (`--test-threads=1`): `layers::tests` 104 passed, `sdpa` and
  `attention` filters 77 passed, `qmm` and `qmv` filters 22 passed, and the
  three fused-launcher parity tests named in CONTRIBUTING passed. The same
  `qmm`/`qmv` filter under the default parallel harness fails two tests
  (`metal_few_row_qmm_matches_dequantized_reference`,
  `prefill_dense_gemm_matches_qmm_bytes_where_eligible`); both pass serially,
  because another test in the shard moves the process-wide `MLXCEL_QMV_WIDE`
  pin. This is the interference the Makefile's `--test-threads=1` already
  avoids.
- `cpu_qmm_accum_tests`: 4 passed, which covers the narrowed CPU overlay for
  both affine bodies and the mxfp4 body.
- Python tooling suites under Python 3.12 (`uv python find 3.12`): 214 passed,
  28 skipped. The Makefile target runs the system `python3`, which is 3.9 here
  and lacks `tomllib`, so `make verify-python-tooling` and `make verify-versions`
  fail in this environment before reaching the tests; both pass under 3.12.
- `cargo fmt --all -- --check`: clean.
- CUDA, Windows and AMD builds are not run on this host; the CUDA overlay
  changes were reviewed and merged, not compiled.
