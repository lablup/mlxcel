# MLX pin review — 2026-10-26

## Decision

Move the reproducible CMake pin from `bff10220` (2026-10-20,
`v0.32.4-13-gbff10220c`) to `7ca40033` (2026-10-26,
`v0.32.4-35-g7ca400331`). GitHub reports v0.32.4 (2026-10-14) as the
latest stable release; moving to that tag would downgrade the existing pin.
The selected main snapshot is 22 commits ahead, not a new stable release.

Sources: [stable release](https://github.com/ml-explore/mlx/releases/tag/v0.32.4),
[exact comparison](https://github.com/ml-explore/mlx/compare/bff10220c742907f0c68e55ff174aaea56f74e3d...7ca40033132dae444d45f7fc3daae57e24c13f6c).

These are upstream improvements, not measured mlxcel speedups. Custom mlxcel
kernels benefit only where execution actually reaches the changed MLX path.
Sliding-window SDPA (#4734) becomes available upstream, but this update keeps
existing Rust-facing attention behavior: C++ callers explicitly pass `-1`.

## Integration

- Rebased every changed CPU/Metal/CUDA whole-file overlay from its declared
  upstream base. All 30 upstream-derived overlay files have zero content drift
  between their declared base and the selected pin; three local-only helper
  headers have no upstream counterpart.
- Kept the QMV-wide override, gathered-row counts, CUDA capture barriers,
  normalization precision changes, and deterministic/bucketed SDPA behavior.
- Combined upstream Windows versioned DLL paths and exception handling with
  the existing restricted DLL search and dependency preloading.
- Adapted all five C++ SDPA call sites with explicit masks to the new
  `window_size` argument. The four-argument call retains the upstream default.

## ROCm overlay

The fork remains `75915908`; only its MLX target changes. Retargeted the core
files, regenerated and reviewed `CORE_RESIDUAL.diff`, and updated LOCAL_FIXES
item 5. The GQA fallback keeps four-dimensional repeated K/V heads and combines
window/causal masks with explicit masks without the upstream five-dimensional
reshape. Positive windows use the graph fallback; forced fused windows throw
instead of silently computing unwindowed attention.

## Validation

- Pin Rust unit/cross-parser tests: 49 passed; shell parser: 13 cases passed.
- `make verify-rocm-overlay`: passed, including 29 tooling checks and host-only
  allocation/runtime-directory contracts.
- ROCm reconstructed-core and backend drift check: passed.
- CPU-only `mlxcel-core` and C++ bridge build: passed. SDPA-filtered tests:
  20 passed; CPU QMM accumulation tests: 4 passed.
- CPU layer suite: 103 passed, 1 failed in
  `prefill_dense_gemm_matches_qmm_bytes_where_eligible` (f16 byte equality).
  A standalone C++ reproduction of the same f16 inputs and operations linked
  against the cached old-pin and freshly built new-pin CPU libraries reports
  exactly 598,053 unequal elements out of 1,048,576 on both. This numerical
  mismatch predates this upgrade; the layer suite is not fully green.
- CUDA `mlxcel-core`/C++/kernel build for `MLX_CUDA_ARCHITECTURES=121`:
  passed. On NVIDIA GB10 under `gpu-lock`, running single-threaded:
  `layers::tests::` 104 passed, `sdpa` 22 passed, and
  `grouped_gemm_numeric_tests::` 3 passed. These filters overlap, so the counts
  are per invocation, not a count of unique tests. In particular, the dense
  GEMM byte-equality test that fails on CPU passes on CUDA.
- ROCm `mlx/fast.cpp` syntax-only C++ compilation against the updated overlay
  headers: passed (host check, not HIP compilation).

Apple Silicon Metal runtime/JIT validation, native Windows DLL loading, and AMD
ROCm compilation/runtime validation require their respective hosts and were
not run here. No hardware performance claim is made by this update.
