# mlxcel WebUI — agent guidance

Scope: this file governs `webui/` only, the React and TypeScript source of the WebUI that
`scripts/webui/build_bundle.py` turns into `src/webui/assets/`. It does not govern the Rust
crate, the Python tooling, `webpage/` or anything else in the repository. The authorities are
the WebUI documents under `docs/webui/` — start at `docs/webui/contributing.md`; this file only
points at them.

The block between the UI-COMMON markers is generated by the `ui-common` CLI. The PROJECT LINES
after it are this repository's and win wherever the two disagree.

SETUP (once, first in your entry stylesheet) — without these, components render unstyled:

WORKFLOW — start every page from a template, never from scratch:
1. `ui-common build "<idea>"` — names the template to scaffold from and the parts it lacks.
2. `ui-common template <name> <path>` — scaffold it; keep its frame, gap and padding; replace the content.
3. `ui-common template <Block>` for parts it lacks; `ui-common component <Name>` to read props before using one.
Changing an existing page? Keep it: skip step 2 and add blocks/components inside its sections.

RULES:
- No <div> — components handle all layout and spacing.
- Read `ui-common docs layout` before changing a template's frame.
- Dense data = rows (Table, List/Item), not Card-wrapped lists. Badge = counts only.
- Style with component props first, then tokens (var(--color-*|--spacing-*|--radius-*)). No raw hex/px. No StyleX/Tailwind compiler here — don't use xstyle/utility classes directly. Some templates use StyleX and need a compiler plugin; see `ui-common docs styling-overview`.
- Palettes and custom colors go through the theme, never :root overrides. Run `ui-common theme add <slug>` to import; `theme eject <slug>` only forks source. See `ui-common docs theme`.
- SELF-CHECK: re-read the file; replace any raw <div>/<span>, imported .css/@apply, or hardcoded #hex/px with the component or a token.

`ui-common help` lists every command. Key ones beyond the workflow:
  search "<query>"   find any component / hook / doc / template
  discover <words>   integrations you could add
  docs <topic>       getting-started, principles, tokens, theme … (`ui-common docs` lists all)
  docs cli           commands, API reference, integration authoring
  upgrade --from <old version> --apply   run after a dependency bump

UI-COMMON (@lablup/ui-common v0.2.0-alpha.19 wraps Astryx v0.7.0):
- Import only from @lablup/ui-common: the root, or the same subpath Astryx uses (@lablup/ui-common/Button, /theme/tokens.stylex, /lab). Never import @astryxdesign/* directly.
- Layers: declare `@layer reset, theme, base, astryx-base, astryx-theme, ui-common, components, utilities;` once, first, in the entry stylesheet. ui-common's styles sit in `ui-common`; yours go in `components` / `utilities`.
- Use AlertModal (@lablup/ui-common/AlertModal), not AlertDialog: ui-common hides AlertDialog.
- Use Modal (@lablup/ui-common/Modal), not Dialog: ui-common hides Dialog.
- ComplexSelector (@lablup/ui-common/ComplexSelector) comes from ui-common: its own copy of Astryx's, same API and import path. Adds hasClear and onClear, a clear button as Selector has (facebook/astryx#6362).
- Drawer (@lablup/ui-common/lab) comes from ui-common: its own copy of Astryx's, same API and import path. An Escape from a layer opened inside the drawer, or one that ends an IME composition, no longer closes it; aria-modal passes through.
- Tour (@lablup/ui-common/lab) comes from ui-common: its own copy of Astryx's, same API and import path. A step's highlight is promoted into the top layer once, so under StrictMode the spotlight dim no longer covers the callout.
- Theme: <Theme theme={lablupTheme}> with lablupTheme from @lablup/ui-common/theme/lablup/built, plus @lablup/ui-common/theme/lablup/theme.css. A product palette is its own defineTheme over lablupTheme.
- Strings: every built-in string is a prop; defaults come from ui-common's catalog. Pass uiCommonMessages from @lablup/ui-common/i18n-catalog to Astryx's InternationalizationProvider. Never a product i18n runtime.
- ui-common's own components: AlertModal, Board, BoardItemTitle, BooleanToken, BulkEditFormItem, BulkErrorModal, ColorPicker, ConfirmPopover, CountBadge, CountdownBorder, DataGrid, DeleteConfirmModal, DigitPopIn, DividedRow, DoubleBadge, DoubleToken, ErrorState, Form, IconWithTooltip, ImageWithFallback, ListBanner, Modal, NotificationItem, NotificationStack, OverlayScrollbar, PageHeader, PageLayout, PagedSelector, ProgressWithLabel, SelectionLabel, Skeleton composites, SmoothHeight, StatCard, Statistic, StepNumberInput, TextHighlighter, TokenList, TokenRow, UncontrolledInput, UnitGrid. `pnpm exec ui-common docs ui-common` explains them.
- The `ui-common` bin is @lablup/ui-common-cli, a devDependency pinned to the same version as @lablup/ui-common; bump both together. Without it installed, `pnpm dlx @lablup/ui-common-cli@next <cmd>` (or `npx @lablup/ui-common-cli@next <cmd>`); drop `@next` once 0.2.0 is published.
- After bumping @lablup/ui-common and @lablup/ui-common-cli: `pnpm exec ui-common upgrade --from <old version>`, then read ui-common-upgrade-report.md.

PROJECT LINES (mlxcel WebUI; outside the generated markers so `ui-common agents --write` keeps them, and they win where they disagree with the block):
- CLI (this repo): the `ui-common` bin is `@lablup/ui-common-cli`, a `webui/` devDependency. Inside `webui/` run `pnpm exec ui-common <cmd>`; from the repository root run `pnpm --dir webui run ui-common <cmd>`. `ui-common astryx <cmd>` runs the Astryx CLI. The CLI is for reading (`component`, `search`, `docs`, `build`) and for `astryx theme build` (through `pnpm run build:themes`): `template`, `theme add`, `swizzle`, `init` and `upgrade --apply` write files and are not part of the normal workflow here.
- PAGES (this repo; overrides WORKFLOW and the "No <div>" rule): feature pages under `src/features/*` import controls only from `src/design-system/primitives.tsx`, never from `@lablup/ui-common` directly (`docs/webui/contributing.md`, `docs/webui/ui-common.md`). Package imports live only in the `src/design-system/common-*.tsx` adapter seam; first-paint modules (`app.tsx`, `design-system/shell.tsx`, `provider-surfaces.tsx`, `command-palette.tsx`) import seam modules directly, not the barrel. Do not scaffold ui-common templates or blocks into the tree: they assume a StyleX compiler. Use them, and `ui-common component <Name>`, as the reference for what an adapter should wrap. ESLint rejects any `@astryxdesign/*` import.
- STYLING (this repo): no StyleX compiler runs, so never use `xstyle` or StyleX `create`/`props`. Product styles are plain CSS files collected by `src/app.css` (feature stylesheets are not imported by their modules), in `@layer components`, reading the semantic tokens listed in `docs/webui/design-system.md#tokens`. No inline `style` attributes or `style={{…}}`: dynamic appearance is a data attribute with discrete CSS rules (glass intensity is the model).
- CSP (this repo): the served policy is `style-src 'self'` and `script-src 'self'`, so nothing may insert a `<style>` element or an inline script. Astryx's popover slide rules ship as `public/astryx-layer-slide-rules.css` (regenerate with `node scripts/layer-slide-rules.mjs` after an Astryx bump); only pre-built themes are allowed, and Astryx features that inject styles at runtime (non-built themes, CodeBlock highlighting, Chat stream scrolling, the native DateInput) are off limits. Nothing loads from another origin (no remote fonts: the neutral theme's `fonts.css` stays unimported). `tests/csp.spec.ts` checks a served build (`docs/webui/ui-common.md#content-security-policy`).
- THEME (this repo; overrides the Theme line in the block): the product families `mlxcel` and `glass` are Astryx themes over the built `neutralTheme` (`src/design-system/themes/mlxcel.theme.ts`, `glass.theme.ts`, palette in `palette.ts`), pre-built into `themes/built/` with `pnpm run build:themes`; never hand-edit `built/`, never pass `<Theme>` an unbuilt theme (it would inject `<style>`), and `lablupTheme` is not used. Astryx tokens carry the palette (`--color-background-body`, `--color-text-primary`, `--color-border`, ...); product-only tokens are `--mx-*` (`themes/mlxcel.css`, `glass.css`, `tokens.css`). `<html>` carries `data-theme` = `light`/`dark` and `data-astryx-theme` (both also written by `<Theme>`) plus `data-theme-family`; `public/theme-bootstrap.js` writes them before first paint and is parity-tested against `preferences.ts`. `pnpm run check:theme-selectors` gates every theme selector and `pnpm run check:themes` the built artifacts (`docs/webui/design-system.md#themes`).
- SETUP (this repo): `public/layer-order.css` (linked first in `index.html`) and `src/ui-common-entry.css` declare the layer order; the entry imports `reset.css`, `astryx.css`, `ui-common.css` and `lab/lab.css`, and `src/design-system/themes/index.css` imports the built family themes. Neither `theme/lablup/theme.css`, the neutral `theme.css`/`fonts.css` nor `legacy-tokens.css` is loaded.
- STRINGS (this repo): every user-facing string is a key with English and Korean values in the feature's `strings.ts` (combined by `src/i18n/catalog.ts`) and the same entry in `tests/fixtures/webui/strings.json`. Astryx and ui-common built-in strings come from their catalogs through `InternationalizationProvider`; pass product strings as props.
- BUDGET (this repo): `scripts/webui/build_bundle.py` limits the initial JavaScript to 256 KiB gzip (262,144 bytes) and all JavaScript to 700 KiB gzip. Screens behind sign-in are lazy route chunks (`preloadRoutes()` in `app.tsx`); keep new package imports out of the first-paint modules.
- TOOLCHAIN (this repo): Node 26.5.1 and pnpm 11.18.0, pinned in `package.json` `engines`/`packageManager` and checked by `build_bundle.py`. Dependencies are exact versions; `pnpm-workspace.yaml` declines the Astryx postinstalls (`allowBuilds`) and keeps a single `@astryxdesign/core` (`src/design-system/ui-common-dependencies.test.ts`).
- BUMPING (this repo): `@lablup/ui-common` and `@lablup/ui-common-cli` move together, to the same exact version. After a bump: `pnpm install`, `pnpm exec ui-common upgrade --from <old version>` (read the report; do not `--apply` blindly), `node scripts/layer-slide-rules.mjs`, `pnpm run build:themes` (Astryx changes reach the built themes only through a rebuild), then regenerate this block with `pnpm exec ui-common agents --write AGENTS.md` from `webui/`. `pnpm run check:agents` (CI `webui-bundle` job and `make verify-webui-frontend`) fails while the block is stale. Do not hand-edit between the markers.
- GATES (this repo): `pnpm run typecheck`, `lint`, `check:theme-selectors`, `check:themes`, `check:agents`, `unit` and `browser` from `webui/`; regenerate `src/webui/assets/` with `python3 scripts/webui/build_bundle.py` from the root (`docs/webui/contributing.md#gates`).
