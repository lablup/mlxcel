# PR #3306: Apply YaRN rope_scaling in DeepSeek-V3 and LongCat MLA

**Date**: 2026-11-23
**Status**: PR open as a draft (closes #3295). Narrow unit selectors, clippy, fmt and the CI scripts pass. Real-checkpoint traces against mlx-lm are recorded below.
**Risk Level**: Medium (shared rope code under five MLA families; three of them trace byte-identical before and after)

## Executive Summary

`DeepSeekV3Attention` and the LongCat ngram MLA rotated `q_pe` / `k_pe` with plain `base^(2i/d)` frequencies whatever `rope_scaling` declared, so every YaRN checkpoint of the DeepSeek-V3 family and LongCat-Flash-Lite rotated its low-frequency pairs `factor` times too fast. This PR adds one shared `MlaRope` (`src/models/mla_rope.rs`), wires both families to it, and moves the three private copies (V3.2 `DsaRope`, the LongCat sparse rope, Xing4.0's opt-in table) onto it. On GigaChat3-10B-A1.8B (`deepseek_v3`, YaRN 64 over 4096) the trace has 0 of 1264 decided disagreements past position 4096, against 971 before the fix.

## 1. Problem Statement

Upstream builds the MLA rotation with `initialize_rope(..., scaling_config=rope_scaling)`, which returns `YarnRoPE` for `yarn` and `deepseek_yarn`. mlxcel's DeepSeek-V3 attention read the block only for the softmax-scale correction (`get_attention_scale`), and the LongCat ngram MLA ignored it entirely. The plain and YaRN tables agree on the high-frequency pairs, so short prompts look fine. Past `original_max_position_embeddings` the output degrades: the pre-fix GigaChat3 trace has perplexity 3047 past 4096 against the reference's 16.65.

## 3. Technical Decisions

### 3.1 One type, each family keeps its original-context fallback

The three existing copies differed only in the `train_ctx` they passed when a block names no `original_max_position_embeddings`. Upstream `YarnRoPE` defaults to 4096 and never reads `max_position_embeddings`, so DeepSeek-V3 and the LongCat ngram model pass `None`. V3.2 keeps `None`, and sparse and Xing4.0 keep `max_position_embeddings`. Every local checkpoint names its original context, so the choice changes nothing measured here.

### 3.2 Youtu stays plain

Youtu builds the DeepSeek-V3 attention but only admits a block that reduces to the identity (`yarn`, factor 1). Resolving that block would build a factor-1 table that equals the plain frequencies only up to rounding. Passing `MlaRope::plain` keeps the exact `fast_rope` call it made before.

### 3.3 One plain-base behavior change

The old `SparseRope` used `rope_theta` for its plain rotation even under `--rope-freq-base`, while its table followed the override. `MlaRope` applies the override to both, as `DsaRope` and Xing4.0 already did. This only matters when an override is set and no table applies.

## 4. Verification

Teacher-forced `examples/logit_trace` against mlx-lm 1bf8da0. The negative arm is the pre-fix binary built from main.

| Checkpoint | Region | Decided disagreements | Pre-fix | Perplexity / reference |
| --- | --- | --- | --- | --- |
| GigaChat3-10B-A1.8B, 8-bit | 8192 positions | 0 / 2774 | 989 / 2774 | 14.582 / 14.572 |
| same | past 4096 | 0 / 1264 | 971 / 1264 | 16.688 / 16.652 |
| longcat-flash-lite-4bit | 36864 positions | 39 / 20486 | 1709 / 20486 | 25.45 / 25.82 |
| same | past 32768 | 6 / 2446 | 671 / 2446 | 17.92 / 17.49 |

- GigaChat3 was quantized locally to affine 8-bit because the `deepseek_v3` loader does not load an unquantized MoE checkpoint. mlx-lm needed a shim to drop the MTP layer at index 26, because upstream hardcodes index 61.
- A single 36864-token mlx-lm forward on LongCat returns uniform logits past position 16384, so that reference is prefilled through mlx-lm's KV cache. Prefill steps of 2048 and 4096 give identical rows.
- Byte-identical rows before and after: `moonlight-16b-a3b-instruct-4bit` (no block), `xing4.0-29b-a4b-mlx-8bit`, `longcat-flash-lite-sparse-4bit`.
- Unit tests: tables against a float64 port of `YarnRoPE` at three checkpoint geometries, the alias, byte-identity of the no-block path, the magnitude, a synthetic `deepseek_v3` YaRN config changing `q_pe` past the original context, the table reaching every layer and the batched decode, and the ngram model carrying it.

## 5. Unverified and Open Items

- On LongCat the residual decided disagreements (gap 4.5 or less) grow with position: 0 to 1 per 4096-position chunk below 12288, 4 to 10 from 12288 on, with no step at 32768. The reference has no noise of its own across prefill step sizes, so this residual sits above the reference's noise, which is the issue's criterion. Its source is not identified.
- No real DeepSeek V3.2 or Kimi-K2 checkpoint was traced. V3.2 rope tests pass unchanged.
- The `deepseek_v3` loader cannot load an unquantized MoE checkpoint (it looks for `switch_mlp.*.scales`). That is a separate gap.
- Three LongCat latent tests fail only in parallel, with or without this PR, because of the global MLA stats counters (#3298).

## 6. Learning Points

- A long-context trace needs a reference that is valid at that length: mlx-lm's single forward fails silently past 16384 on LongCat, and perplexity per chunk made that visible.
- A change that alters the rotation at every position cannot use the pre-fix arm as a noise floor. It shows that the trace detects the bug, nothing more.
