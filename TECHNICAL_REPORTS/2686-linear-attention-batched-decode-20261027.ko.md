# 기술 보고서: PR #2686 — Linear-attention 배치 디코드

**작성일**: 2026-10-27
**상태**: 구현·측정·최종 통합 검증 완료

## 요약

이슈 #2572는 Qwen3-Next, Qwen3.5, Bailing MoE Linear, Kimi Linear, Kimi K3에 ID 기반 다중 행 네이티브 디코드를 추가한다. 체크포인트 4개의 구성 6개를 측정했으며 두 Qwen3.5 체크포인트는 기본·명시적 dense 저장 모드를 각각 실행했다. 모든 greedy 결과와 B1 trace 데이터 256행이 기준과 정확히 일치하고 모든 후보 C4 총 처리량이 후보 C1보다 높다. 아래 수치 차이를 보존하며 보편적 동등성을 주장하지 않는다.

## 문제 정의

모델 소유 순환 상태 때문에 요청 간 디코드가 직렬 실행되었다. Qwen3.5는 배치를 지원했지만 디코드는 행별로 실행했다. 동시 실행에서도 요청별 순환 상태, attention 이력과 MRoPE 위치를 보존해야 한다.

## 기술적 검토 및 선택

공유 recurrent stack/split과 split-attention 도우미를 재사용하고 B1 스칼라 경로 및 변경 전 ID 검증을 유지한다. 혼합 초기화, 행별 attention/MLA, Qwen3.5 prefill·저장 정책과 MRoPE 의미를 보존한다. Qwen3.5 및 Kimi K3 비전 래퍼는 텍스트 타워에 위임한다.

HIGH 리뷰 지적은 Qwen3.5 GDN 순환 상태를 paged attention 이력으로 계산하는 문제였다. `413e4649`는 순환 슬롯을 0으로 유지하며 실제 attention 길이를 보존한다. 수정된 계산 사례를 포함한 GPU 회귀 7개, 커버리지 검사 14개, 범위 내 clippy와 포맷 검사가 통과했다. #2572 머지와 #2573 rebase 이후 최종 워크스페이스 통합 검증도 아래에 기록한 대로 통과했다.

## 변경 요약 및 측정

측정 release는 `413e4649ebe9451fc73a7f4d03c492807a4e9148`, 기준 모델 소스는 `a29a2692`다. 이후 `9b6265f4`는 도구만 변경한다. 호스트는 Apple M3 Ultra, 512 GB, macOS 26.6.2이며 release `metal,accelerate`를 사용했다. 원본 실행 manifest가 바이너리와 실제 로딩된 Metal 라이브러리 해시를 보존한다. 기존 기준 실행의 해시 누락은 명시했다.

| 구성 | 기준 C1/C2/C4 tok/s | 후보 C1/C2/C4 tok/s | B4 top-1 | Decided | PPL 변화 |
|---|---|---|---|---|---|
| qwen-next | 69.7/66.6/80.6 | 71.1/103.3/148.1 | 8/256 | 0/126 | +0.523% |
| ring-mini | 140.0/179.2/177.8 | 159.6/298.8/460.8 | 22/256 | 1/118 | -2.052% |
| qwen35-4b | 109.5/188.8/168.6 | 112.6/225.3/357.9 | 2/256 | 0/117 | +0.025% |
| qwen35-moe | 87.4/138.8/122.5 | 89.3/165.7/262.9 | 3/256 | 0/113 | +0.634% |
| qwen35-4b-dense | 110.9/191.8/170.3 | 112.7/225.3/361.8 | 2/256 | 0/117 | +0.025% |
| qwen35-moe-dense | 88.7/146.2/123.9 | 89.5/166.5/262.9 | 3/256 | 0/113 | +0.634% |

Ring은 top-1 22/256 불일치이며 **decided 위치 1/118**도 불일치한다. 불일치 최대 gap은 **2.312**다. 이는 **0이 아닌 decided 불일치**다. 이슈는 불일치 0을 수용 기준으로 요구하지 않고 측정 규모의 기록을 요구한다. PPL -2.052% 변화가 이 차이를 없애지는 않는다. 다른 측정 구성은 decided 불일치 0이다. 이슈는 이러한 규모를 기록하도록 요구하며 전체 수치 또는 일반 품질 동등성을 주장하지 않는다. 모든 후보 시작 로그는 clamp 없이 native batching을 보고한다. 단일 ladder 표본은 B1 성능의 통계적 동등성을 입증하지 않는다.

B1/B4 모두 `MLXCEL_FUSED_MOE=0`인 별도 진단은 top-1 22/256 차이를 유지하지만 decided 차이는 0/114(최대 불일치 gap 1.25)이며 PPL은 60.6904 → 57.1854(-5.775%)다. 리뷰는 B1 full-fused와 B4 short gate/up 및 gather-QMM 산술 경로 차이를 확인했다. Fusion을 끄면 decided 차이는 사라지지만 B1 PPL과 반올림도 달라지므로 품질 동등성의 증거가 아니다. 위 운영 설정 측정값과 처리량은 변경하지 않았다. 진단 드라이버와 release 출처는 별도로 보존했다.

Qwen3.5 원본 자유형 VLM은 기준과 후보 모두 `[true, false, true]`다. Counting 응답 reasoning은 변경 전후 모두 동시 실행에서 달라진다. HTTP 단계는 모두 성공하며 종료 코드 1은 응답 비동일성을 뜻한다. 기준 대비 후보 solo 전체 메시지는 3/3 일치하지만 concurrent 전체 메시지는 `[true, false, true]`다. 이를 VLM 3/3 exact 통과로 기록하지 않는다. 이미지 조건 teacher-forced B1은 64행 모두 정확히 일치하며 B4는 top-1 2/64, decided 0/15 불일치이고 PPL은 82.5008 → 81.7597(-0.898%)이다.

서빙 프롬프트 요청은 약 512토큰이며 실제 토큰 수는 달라진다. 생성 한도는 128이다. 텍스트 trace는 64위치 청크 4개와 최대 이력 512를 사용하며 고정 512토큰 문맥이 아니다. 이미지 trace는 별도의 64위치 실행이다. Affine 양자화 decided 위치 검사만으로 일반 품질 동등성을 입증할 수 없다. Kimi Linear와 Kimi K3는 합성 검증만 있고 실제 체크포인트 측정은 없다.

## 후속 조치 및 증거

최종 통합 검증을 완료했으며 Ring·VLM 차이는 이슈 기준에 따라 그대로 기록한다. [구조화 결과](../docs/benchmark_results/data/native-batched-decode-m3ultra-2026-10-27/linear-attention.json)는 각 원본 실행으로 연결된다. 원본 증거는 단계별 출력·stderr·상태, 원본 실행 manifest와 참조 로그, 소스·입력 해시, 정확한 VLM 요청, fixture 이미지 및 재생 드라이버를 보존한다. 원본 루트 manifest는 이전 epic 증거와의 합집합을 포함한다. 현재 빌드에서 과거 바이너리 해시를 추정하지 않는다.
