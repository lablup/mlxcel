# 기술 보고서: PR #1497 - 융합 경계까지의 멀티 어댑터 LoRA

**날짜**: 2026-08-28

**상태**: 완료

**언어**: Rust

**위험도**: 중간

## 요약

b10621 멀티 어댑터 LoRA 표면(#1439)을 mlxcel 설계가 정하는 경계까지 구현한다. 어댑터는 모델 로드 시 베이스 가중치에 융합되므로, `--lora a,b`와 `--lora-scaled a:0.5,b:2`로 임의 개수의 어댑터를 결정적 순서와 어댑터별 스케일로 적재하고, `GET /lora-adapters`는 업스트림의 인벤토리 형태를 보고하며, 런타임 스왑 표면(`POST /lora-adapters`, 요청별 `lora` 필드, `--lora-init-without-apply`의 사후 활성화)은 정확히 무해한 값만 수용하고 나머지는 진단과 함께 거부한다. 매니페스트 3개 항목이 `supported`로 전환되고 3개는 융합 가중치 divergence로 `deferred`에 남아 이슈 #1439는 열린 채 유지된다.

## 1. 문제 정의

b10621은 LoRA 어댑터를 런타임 교체 가능한 레이어로 유지한다. 시작 시 임의 개수를 적재하고, 요청별로 또는 `POST /lora-adapters`로 스케일을 바꾸며, 나열되지 않은 어댑터는 스케일 0.0으로 떨어진다. mlxcel은 가중치에 영구 융합되는 단일 `--lora` 어댑터만 있었고 인벤토리/갱신 표면이 없어서, 어댑터 여러 개나 런타임 스왑을 쓰는 llama-server 배포에는 정직한 이행 대상이 없었다.

## 2. 기술적 결정

### 2.1 융합은 유지하고, 경계는 숨기지 않고 명시한다

런타임 교체 가능한 어댑터에는 모든 패밀리의 forward에 적용되는 비융합 A/B 행렬이 필요하며, 이는 코드베이스 전반에 파급되는 코어 크레이트 변경이다. 융합은 이미 존재하고 정적 사례에 대해 올바르므로, 정적 표면(멀티 어댑터, 어댑터별 스케일, 순서 결정적 적재, 인벤토리)은 완전히 구현하고, 동적 표면은 업스트림 자체의 해석 규칙(`construct_lora_list`: 나열된 id는 스케일 설정, 미나열은 0.0, 범위 밖 id는 무시)으로 요청을 해석한 뒤 이미 적용 중인 구성이면 승인하고 아니면 `--lora-scaled`와 재시작을 지목하는 진단으로 거부한다. 요청이 요구하지 않은 가중치 위에서 조용히 서빙되는 일은 없으며, 이것이 에픽의 핵심 규칙이다.

### 2.2 스케일 도메인은 시작 시 강제

사용자 스케일은 융합 시 어댑터 자체의 `alpha / r`에 곱해지며, 업스트림의 산술과 동일하다. NaN, 무한대, 비숫자 스케일은 명령줄에서 실패한다. 비유한 델타는 어댑터가 건드리는 모든 가중치를 오염시키고 증상은 깨진 출력으로만 나타나기 때문이다. 없는 어댑터 디렉터리도 시작 시 실패하고, 멀티/스케일 어댑터를 텐서·파이프라인 병렬과 함께 쓰는 것은 부분 적용 대신 거부한다.

### 2.3 호환 이음새는 좁게

단일 어댑터의 자명한 경우는 기존 `adapter_path` 채널로 환원되어 그 경로는 바이트 동일하게 유지된다. 라우터 모드 풀의 자식은 어댑터를 의도적으로 상속하지 않는다. 어댑터는 베이스 모델 특정적이고, 관대한 레거시 로더는 불일치 텐서를 조용히 건너뛰는 #1328의 실패 모드를 갖고 있기 때문이다. #1328의 엄격 검증 자체는 건드리지 않았다.

## 3. 변경 요약

| 항목 | 값 |
|------|-----|
| 변경 파일 | 24 |
| 매니페스트 | supported: --lora, --lora-scaled, GET /lora-adapters / deferred: --lora-init-without-apply, POST /lora-adapters, field:lora |

검증: 유닛·라우트 테스트(NaN/inf 거부를 포함한 플래그 파싱, 레거시 환원, 인벤토리 형태, POST 무해 승인/거부/비배열, 요청별 필드 무해/거부)와 실제 체크포인트(`qwen2.5-0.5b-bf16`, greedy)에 합성한 실제 포맷 어댑터 2개: `--lora`는 베이스 대비 출력을 바꾸고, `:0`은 베이스와 동일하며, `:3`은 더 벌어지고, 두 어댑터가 함께 적재되며, 위의 모든 라우트 동작을 라이브로 확인했다. 체인이 드러낸 테스트 회귀 2건(그림자 처리된 중복 `--no-webui` 스텁, 모델 해석 전에 발화하도록 옮긴 #1438 마이그레이션 가드)도 함께 수정했다.

## 4. 후속 조치

- 비융합 런타임 LoRA forward 경로(또는 #1438 모델 풀 재적재 플로)가 deferred 3개 항목을 여는 열쇠이며 #1439에 남는다.
- #1328(엄격한 어댑터 텐서 검증)은 열린 채 영향 없이 유지된다.
