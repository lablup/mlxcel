# 기술 보고서: PR #3027 - Muse 수신자 스트림 헤더

**작성일**: 2026-11-12
**상태**: 로컬 구현 검증 완료, 보고서 작성 시점 CI 대기
**언어**: Rust
**위험도**: 중간

## 요약

[PR #3027](https://github.com/lablup/mlxcel/pull/3027)은 Muse Glimmer 스트리밍 답변에 수신자 헤더가 노출되는 문제를 수정한다. `to=user<|message|>Hello<|eot|>`로 시작하는 응답은 이제 `Hello`만 출력하며, `to=web_search<|message|>`는 도구 메시지 억제 상태로 전환한다.

## 문제 정의

채팅 템플릿이 assistant 역할을 미리 덧붙이므로 첫 생성 헤더에는 `<|start|>assistant`가 생략될 수 있다. 기존 스트림 필터는 축약형 중 `to=self`만 인식했다. 직접 답변과 도구 호출에서는 수신자 헤더가 노출되었고, 독립 토큰으로 전달된 선행 공백이 추론 이후 답변에 남을 수 있었다. 비스트리밍 파서는 이미 더 많은 수신자 형식을 인식했다.

## 기술적 선택과 그 이유

경계 상태를 두어 축약 헤더를 턴 시작과 Muse 메시지 종료 토큰 직후에서만 인식한다. 부분 헤더는 메시지 구분자가 완성될 때까지 기다리며, 수신자 길이와 경계 공백 길이 제한으로 보류량을 제한한다. 헤더가 아닌 `to=` 일반 문장은 도구 호출로 처리하지 않고 출력한다. 역할이 포함된 전체 헤더도 계속 지원하며 Harmony는 기존 채널 격리를 유지한다.

Muse 본문, 추론, 도구 전환은 기존 공백 및 구분자 처리 구조를 공유한다. 도구 메시지 억제는 내부 ATEM 종료 태그 이후에도 Muse 경계까지 유지하여 도구 메시지의 후속 텍스트가 답변에 섞이지 않게 한다. 비스트리밍 경계 파싱은 동일한 수신자 검증을 사용하고 정리된 출력에서 Muse 종료 토큰을 제거한다.

## 변경 요약

구현 커밋 `78da87c8`은 Rust 파일 8개를 변경한다. 공통 메시지 파싱 및 스트림 상태 처리, 필터와 동등성 테스트, Chat Completions·Responses·Messages 어댑터 테스트가 포함된다. 의존성과 공개 API 시그니처는 바뀌지 않는다. [이슈 #3025](https://github.com/lablup/mlxcel/issues/3025)에 완료 기준이 있으며, 클라이언트 방어는 backend.ai-go #7244에서 별도로 진행한다.

## 검증과 한계

로컬에서 도구 호출 테스트 502개, Muse 어댑터 테스트 14개, 라우트 테스트 589개가 통과했고 라우트 테스트 1개는 제외되었다. `cargo fmt --check`와 엄격한 clippy 검사(`--lib --tests -- -D warnings`)가 통과했다. 라우트 테스트는 `RUST_MIN_STACK=16777216`을 사용했다. 한국어, 분할 헤더, 다중 채널, 도구 추출, `to=` 일반 문장과 긴 접두사를 검증한다. 실제 모델 추론과 데스크톱 UI 세션은 다시 실행하지 않았으며, 테스트는 고정된 생성 출력 데이터를 사용한다.
