# 기술 보고서: PR #1975, Models와 Activity 페이지의 잔여 LOW 항목

**날짜**: 2026-09-25

**상태**: 구현, 리뷰, 로컬 검증과 실제 서빙 바이너리 대상 검증 완료. 이 보고서를 만든 chain 실행이 머지함.

**언어**: TypeScript/React

**위험도**: 낮음

## 요약

PR #1975는 이슈 #1974를 닫는다. #1974는 epic #1910 아래 PR #1930(Models 라이브러리 재설계, #1918)과 PR #1929(Activity 상태 페이지, #1916)의 하드닝에서 남은 LOW 항목을 묶은 이슈다. 두 페이지가 WebUI 테스트 표면 하나와 CI 한 사이클(GB10 installed-artifact 잡 포함)을 공유하기 때문에 한 PR로 묶었다. 변경은 WebUI와 생성 번들뿐이며 Rust, API, 스키마는 바뀌지 않았다.

## 문제 정의

각 항목은 두 재설계 PR이 의도적으로 미룬 잠재 결함이나 접근성 공백이었다.

- 1100px 미만에서 Models inspector 드로어 뒤 페이지가 접근성 트리에 남고 포커스도 받았다. Chat과 내비게이션 시트는 `inert`를 건다.
- 드로어 어댑터가 패널 안의 모든 Tab을 캡처 단계에서 막아서, 하위 핸들러(ui-common `Select`, Dialog 트랩)가 Tab을 받지 못했다.
- 행 레이블과 툴팁이 모델 이름을 유니코드 격리 없이 넣었다.
- 검색이 없을 때 행에서 Unload하면 lifecycle 고정 정렬로 행이 뒤 페이지로 이동했다. 그래서 포커스된 Load 버튼이 보이는 페이지를 떠나고 포커스 intent는 영구히 남았다. 또 라우트가 바뀔 때마다 화면이 다시 마운트되어 Chat을 다녀오면 검색, 필터, 정렬이 사라졌다.
- Activity에도 문제가 여럿 있었다.
  - 슬롯 박스가 스크롤되지 않아도 탭 정지점이었다.
  - 포매터와 operations 정렬을 호출이나 폴링마다 다시 만들었다.
  - 복수형 규칙이 반올림 전 값을 읽었다.
  - 컨텍스트 0이 "0 tokens"로 표시됐다.
  - 모델을 다시 선택하면 이전 타일이 "갱신 중지" 배너와 함께 보였다.
- StatCard 로딩 스켈레톤은 서빙 CSP 아래에서 한 번도 실행된 적이 없었다.

## 변경 요약

- **Models:**
  - 1100px 미만에서 드로어가 열리면 `display: contents` 래퍼가 드로어 앞의 모든 요소를 `inert`로 만든다.
  - 행 레이블은 `isolate()`를 거치고, 테스트 로케이터도 같은 헬퍼로 만든다.
  - 행 포커스 effect가 행의 인덱스를 찾아 페이저를 그 페이지로 넘긴다. 행이 마지막으로 보인 페이지를 기억하므로, 재정렬은 따라가되 사용자가 다른 페이지로 넘기면 멈춘다. 일회성 `once` intent는 페이지를 넘기지 않는다.
  - 검색, 필터, 정렬은 새 모듈 스토어 `library-view.ts`에 둔다. 이 스토어는 설정된 서버 인스턴스에 묶이고 로그아웃 시 초기화된다.
  - 콜백 ref는 컨트롤 키마다 캐시하고, `consumeInspectorRequest`는 구독자에게 알린다.
- **드로어 어댑터:** 열릴 때 alpha.19가 쓰는 셀렉터로 첫 번째와 마지막 포커스 요소를 기록한다. Tab 전파는 실제로 감쌀 때, 탭 정지점이 없을 때, 포커스가 그 오래된 패키지 가장자리에 있을 때만 막는다.
- **오버플로 영역:** `useOverflowRegion`을 일반화해 스크롤 요소를 받고, 두 축을 모두 검사하고, label과 `labelledBy`를 모두 받게 했다. DataTable과 Activity 슬롯 박스가 이 훅을 공유하므로, 박스는 실제로 넘칠 때만 이름 있는 포커스 가능 영역이 된다.
- **Activity와 포매팅:**
  - `design-system/format.ts`가 로케일과 소수 자릿수를 키로 하는 `cached()`를 내보낸다.
  - `Operations`는 정렬과 개수를 memoize한다.
  - `Intl.PluralRules`는 표시 반올림과 같은 옵션을 쓴다.
  - 0 이하 컨텍스트는 "unknown"으로 표시한다.
  - `RuntimeView`는 재선택 후 첫 샘플이 올 때까지 대기 상태를 보인다.
- **CSP:** 갤러리에 로딩 StatCard를 추가했다. `csp.spec.ts`는 위반 검사 전에 장식용 스켈레톤이 보이는지 확인한다.

## 기술적 선택과 그 이유

- **감쌀 때만 막지 않고 오래된 가장자리에서도 Tab을 막는다.** alpha.19는 열릴 때 가장자리를 한 번만 잡고, 포커스가 그 요소에 있으면 일찍 감싼다. 실제로 감쌀 때만 막으면 그 오래된 핸들러가 오작동한다. 그래서 어댑터가 패키지의 스냅샷을 그대로 재현해, 패키지가 개입할 바로 그 지점에서만 막는다.
- **컴포넌트 상태도 영속화도 아닌, 인스턴스에 묶인 세션 스토어.** 컴포넌트 상태는 라우트가 다시 마운트될 때마다 뷰를 잃고, 영속화는 로그아웃 뒤에도 남는다. `serverInstanceId`에 묶인 모듈 스토어는 Chat 왕복은 유지하면서, 이전 사용자의 검색어나 새 카탈로그가 만족할 수 없는 필터는 넘기지 않는다. 보안 리뷰가 이 문제를 MEDIUM으로 제기했고 머지 전에 고쳤다.
- **기억한 페이지를 쓰는 페이지 추적.** 첫 구현은 `<body>` 포커스를 "아직 대기 중"으로 봤다. 그런데 macOS의 Safari와 Firefox는 Next 클릭 시 버튼에 포커스를 주지 않아, effect가 사용자의 페이지를 되돌렸다. 행이 마지막으로 있던 페이지를 기록하면 재정렬(따라가야 함)과 사용자의 페이지 이동(intent 종료)을 구분할 수 있다.
- **재선택 시 reducer 삭제 대신 대기 상태.** 캐시된 runtime을 지우면 같은 맵을 읽는 Models inspector가 비어 버린다. 그래서 수정은 Activity 뷰 안에서만 한다.

## 검증

- **로컬 검사:** typecheck와 lint 통과, 유닛 스위트 통과(node 테스트 35개, Vitest 710개), 기본 Chromium Playwright 전체 124개 통과. `build_bundle.py --verify`, contract 검사, binary-asset 검사도 통과했다.
- **수정 없이는 실패하는 테스트:** 각 항목의 새 테스트는 수정을 되돌리면 실패함을 확인했다. 11번의 스켈레톤 단언만은 main 갤러리에 StatCard가 없다는 점을 코드로 확인했고 실행하지는 않았다.
- **실서버 CSP 실행:** `dc1845d3`로 빌드한 `mlxcel-server`(`--release --features cuda`, GB10, 번들 내장)에 대해 `tests/csp.spec.ts`가 light와 dark 테마에서 모두 통과했다. 서빙 정책은 `unsafe-inline` 없는 `style-src 'self'`였다.
- **CI:** 첫 push(`70c1029b`)의 CI는 `WebUI installed artifact`를 포함해 모두 통과했다.

## 남은 항목

- **Models 화면 응집도:** `screen.tsx`는 약 720줄로 `docs/code-guidelines.md`의 800줄 기준 안에 있지만, 컴포넌트 하나가 페이지 상태, 행 포커스 effect, 열 렌더러, 필터 툴바를 모두 담고 있다. 분할은 이번 범위 밖이며 #1976에서 다룬다.
- **오버플로 훅 시점:** 훅은 ref가 붙을 때 내부 테이블을 한 번만 찾는다. Activity 슬롯 박스는 제한 높이가 박스 자체 크기를 바꾸므로 여전히 갱신된다.
- **축소 후 포커스:** 포커스된 스크롤 박스가 더 이상 넘치지 않으면 포커스가 `<body>`로 떨어진다.
- **크기 제한 없는 캐시 헬퍼:** 내보낸 `cached()`에는 크기 제한이 없다. 현재 키 집합은 모두 작고 고정되어 있다.
