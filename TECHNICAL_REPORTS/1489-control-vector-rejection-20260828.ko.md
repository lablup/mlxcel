# 기술 보고서: PR #1489 - Control-vector 명시적 거부

**작성일**: 2026-08-28

**상태**: 완료

**언어**: Rust

**위험도**: Low

## 요약

b10621의 control-vector 옵션 세 개를 이슈 #1449 스스로 제시한 대안 분기인 명시적 미지원 동작으로 분류했다. `--control-vector`와 `--control-vector-scaled`는 두 서버 바이너리에서 숨김으로 파싱되고, 벡터가 설정되면 모델 로드 전에 logit 수준 스티어링을 대안으로 안내하며 시작을 중단한다. `--control-vector-layer-range START END`는 벡터 없이는 아무것도 설정하지 않으므로(업스트림과 동일) inert로 수용한다. #1449 소유 매니페스트 엔트리 3건 모두 `not_applicable`로 `deferred`를 벗어났고, 실제 차이(b10621은 벡터를 로드해 적용한다)를 divergence로 기록했다.

## 1. 문제 정의

control vector는 로딩이 아니라 모델 활성값을 바꾸므로, 호환성 no-op으로 수용하면 배포가 서빙한다고 믿는 것을 조용히 바꾼다. 구현하려면 모든 모델 패밀리에 걸친 층별 forward 훅과 GGUF 벡터 로더가 필요한데, 이는 프로젝트 지침이 금지하는 미완성 광역 변경이다. 이슈는 미지원 분류를 명시적으로 허용한다.

## 2. 기술적 선택과 그 이유

### 2.1 구현 대신 거부, 시작 시점에

플래그는 기존 숨김 `GgmlCompatArgs` 수용·분류 표면에 합류해(세 플래그짜리 새 모듈 대신 공유 기계) 벡터가 설정되면 가중치를 읽기 전에 수 밀리초 안에 실패하고, 대안(`--lang-bias`, 요청별 `logit_bias`)을 안내한다. scale 0도 설정된 벡터 집합이므로 부분 적용 없이 통째로 거부되어 이슈의 원자성 기준을 충족한다. 벡터 없는 설정만 서빙 가능하므로 설정 간 prompt/KV 캐시 재사용은 구조적으로 불가능하다.

### 2.2 정직한 기록

리뷰가 두 바이너리와 핀 고정된 b10621 소스에 대해 모든 동작 주장을 실증 검증했고 정확성 문제는 없었다. 기록 관련 지적을 반영했다: 거부되는 두 옵션의 divergence 기록, 업스트림 `stoi`와 동일한 층 범위 정수 파싱, `<START> <END>` 진단 표기, `,...` 반복 마커, 모듈 헤더의 #1449 섹션 명시, `docs/llama-server-compat.md`의 운영자용 섹션.

### 2.3 scale-zero 기준

이슈의 teacher-forced 기준선과 scale-zero 재현 기준은 문구 자체가 구현된 경로에 적용된다. 거부 분류에서는 샘플링·forward 산술이 전혀 바뀌지 않아 추적 비교가 구성상 0이고, scale-zero 케이스는 대신 시작 거부 테스트로 고정했다. 0 스케일 벡터도 설정된 집합이지 조용한 no-op이 아니기 때문이다.

## 3. 변경 요약

| 항목 | 값 |
|-----|---|
| 변경 파일 | 4개 (리뷰 후속 +4) |

검증: 새 단위 테스트 2개와 ggml compat 스위트 36개, 재빌드 바이너리 대상 compat 통합 4/4, 샤드 diff가 #1449 엔트리 3건에 국한됨을 확인한 매니페스트 체커 green, clippy `-D warnings`, fmt, 라이브 스모크(로드 전 거부와 대안 안내, 범위 단독 inert, `--help` 비노출, 비숫자 범위 거부).

## 4. 후속 조치

- 이 이슈 소유의 후속 없음. control vector를 실제로 구현하려면 forward 훅 설계를 갖춘 새 이슈에서 시작한다. 이 분류는 현재의 사실을 검증 가능하게 만든다.
