# 기술 보고서: PR #2039 - Nemotron VoiceChat 캐시 기반 온라인 세션

**날짜**: 2026-09-29

**상태**: 4비트 체크포인트에서 구현과 검증을 마쳤고, 머지 대기 중입니다.

**언어**: Rust

**위험도**: 낮음. 이 PR은 기존 코드를 바꾸지 않고 추가만 합니다. 오프라인 진입점 옆에 스트리밍 진입점을 두고, 새 세션 모듈을 추가하며, VoiceChat 경로에서만 읽는 CLI 플래그를 추가합니다.

## 요약

#2037은 Nemotron VoiceChat을 발화 전체 단위로 실행합니다. 대화에는 80ms마다 처리량이 제한된 작업이 필요합니다. 이 PR은 `VoiceChatStreamingSession`을 추가합니다. 이 세션은 크기에 상관없이 들어오는 PCM 청크를 1280 샘플 프레임으로 모으고, 모든 네트워크를 지속되는 상태에서 한 프레임씩 진행합니다. 각 프레임마다 텍스트, 함수, 받아쓰기, 1764 샘플 오디오 이벤트를 프레임 인덱스와 함께 내보냅니다. 이 세션은 `/v1/realtime` 엔드포인트(#1376)가 쓰는 라이브러리 인터페이스이고, CLI에서는 `mlxcel generate --audio ... --stream [--profile]`로 실행합니다.

테스트 발화에서 스트리밍한 61개 프레임은 모두 오프라인 경로와 같은 텍스트 id와 같은 31개 코드를 냅니다.

## 1. 문제 정의

오프라인 루프는 파형 전체에 대해 log-mel과 FastConformer를 매번 다시 계산하고, 코덱도 전체 이력에서 디코드합니다. 그래서 비용이 대화 길이에 따라 늘어납니다. 전이중 세션은 80ms 프레임 하나를 제한된 시간 안에 처리해야 합니다. 그러려면 다음 여섯 단계 모두에서 상태를 프레임 사이에 이어 가야 합니다.
- log-mel
- 인코더의 어텐션, 합성곱, 서브샘플링
- RNNT 예측망
- Nemotron-H
- EAR-TTS
- 코덱의 overlap

## 2. 변경 요약

- **스트리밍 perception**
  - `StreamingLogMel`은 입력 끝보다 1280 샘플 뒤처진 hop 정렬 프레임을 내보냅니다. 중앙 정렬 STFT에 필요한 만큼의 과거 샘플만 남깁니다.
  - `ConformerStreamingState`는 층마다 최근 어텐션 입력 70개와 합성곱 입력 8개를 보관합니다. 인과적 서브샘플링 스택용 16프레임 mel 캐시도 따로 둡니다.
  - `RnntStreamState`는 마지막 토큰과 LSTM 상태를 보관하고, 받아쓰기 델타를 만듭니다.
  - 어텐션, 블록, 합성곱 타입에 `stream` 진입점을 추가했습니다. 오프라인 수치는 바뀌지 않습니다.
- **세션**(`models::nemotron_voicechat::streaming`)
  - 세션을 만들 때 MLX 전역 RNG 시드를 설정하고, Aria 프롬프트로 EAR-TTS를 워밍업한 뒤, 시스템 프롬프트를 미리 채웁니다. 이 프리필은 타임라인을 진행시키지만 이벤트는 내보내지 않습니다.
  - `push_audio`는 `FrameBuffer`로 완성된 프레임만 꺼내 처리합니다.
  - `flush(pad_partial)`는 필요하면 0으로 채운 부분 프레임을 실행하고 `Done`으로 세션을 닫습니다. `cancel()`은 `Cancelled`로 닫습니다.
  - `max_streaming_seconds`로 세션 길이를 제한합니다.
  - 진단용으로 언어 캐시와 perception 캐시를 끌 수 있습니다.
- **프로파일러**: 단계마다 평가를 강제한 뒤 벽시계 시간을 기록합니다. 평균, p50, p95, 최대값과 초당 프레임 수, 실시간 계수를 요약합니다.
- **CLI**: `--stream`, `--max-streaming-seconds`, `--profile`을 추가했습니다. `--profile`은 콜드 프레임 5개를 제외한 요약을 JSON으로 출력합니다.

## 3. 기술적 선택과 그 이유

### 모델 소유 시퀀스 슬롯 대신 세션이 캐시를 직접 소유

이슈는 Nemotron-H의 `ModelOwnedSequenceState`에서 새 `SequenceId`를 쓰도록 계획했습니다. 이 PR에서는 세션마다 `make_caches()`로 캐시를 직접 만들어 보관합니다. 연달아 만든 두 세션이 상태를 공유하지 않는다는 점은 계획과 같습니다. 여기에 두 가지 이점이 있습니다. 스케줄러를 쓰지 않는 경로가 스케줄러의 시퀀스 상태 장치에 얽히지 않고, 세션이 해제될 때 캐시도 자동으로 풀립니다.

### 스트리밍 인코더 프레임은 오프라인 합성곱이 아니라 기준 구현을 따름

기준 구현의 점진적 서브샘플링은 16프레임 mel 캐시 위에서 동작합니다. 이 캐시는 8프레임 서브샘플링 격자에서 한 프레임 어긋난 위치에서 시작합니다. 그래서 처음 몇 프레임이 지나면 전체 발화에 대한 오프라인 합성곱과 조금씩 달라집니다(최대 절대 오차 0.33). Python 기준 구현에서도 같은 차이가 나타납니다. 이 포팅은 기준 구현의 규칙을 그대로 따랐습니다. 그 결과 스트리밍 프레임은 기준 구현의 스트리밍 경로와 1e-6 이내로 일치하고, 이후 단계의 토큰과 코드는 테스트 입력에서 오프라인과 같습니다. 단위 테스트는 정확히 같아야 하는 부분만 확인합니다. 층 스택은 오프라인과 비교하고, 처음 몇 프레임은 입력부터 출력까지 비교합니다.

### 프레임 버퍼링을 별도 타입으로 분리

청크 경계 동작을 체크포인트 없이 단위 테스트할 수 있도록 `FrameBuffer`를 세션에서 분리했습니다. 테스트하는 동작은 다음과 같습니다.
- 300, 1000, 1280, 2000 샘플씩 넣으면 프레임이 각각 0, 1, 1, 1개 나옵니다.
- 패딩을 켜고 flush하면 프레임이 하나 더 나옵니다.
- 패딩 없이 flush하면 부분 프레임은 버려집니다.

실체크포인트 테스트는 여기에 청크 크기 독립성을 더해 확인합니다. 777 샘플씩 넣어도 1280 샘플씩 넣을 때와 같은 이벤트가 나옵니다.

## 4. 검증

모든 검증은 `mlx-community/NemotronLabs-VoiceChat-11B-4bit`에서 실행했습니다.

| 항목 | 결과 |
|---|---|
| 첫 오디오 프레임의 텍스트 id, 함수 id, 코드 31개 (오프라인과 비교) | 동일 |
| 스트리밍 프레임 61개 전체 (오프라인과 비교) | 텍스트 id와 코드 모두 동일 |
| 스트리밍 결과 답변 텍스트 | "The capital of France is Paris." (오프라인과 동일) |
| 스트리밍 인코더 (Python 스트리밍 경로와 비교) | 최대 절대 오차 1.1e-6, 프레임별 받아쓰기 델타 동일 |
| 777 샘플 청크와 1280 샘플 청크 비교 | 이벤트 동일 |
| `--stream`을 같은 시드로 반복 실행 | WAV 바이트 단위 동일, 61 x 1764 샘플 |
| `--max-streaming-seconds 1` | 컨텍스트 한도 오류로 중단 |
| 프로파일러 출력 | 모든 필드가 유한값 |

로컬 게이트로는 fmt, lib과 tests에 대한 clippy, 변경된 모듈의 단위 테스트, 그리고 `cli_help_consistency`, `dead_doc_pointers`, `llama_compat_manifest`를 실행했습니다. 이번 실행 동안 GPU를 다른 작업과 공유했기 때문에 지연 시간과 실시간 계수 수치는 기록하지 않았습니다.

## 5. 학습 포인트

- 스트리밍 경로와 오프라인 경로는 연속적인 중간값이 조금씩 달라져도 이산 출력은 같을 수 있습니다. 이번에는 인코더의 서브샘플링 윈도부터 차이가 생겼습니다. 그래서 동등성 테스트는 이산 출력(id와 코드)이 같은지를 판정 기준으로 삼고, 연속값의 차이는 따로 보고합니다.
- MLX는 평가가 스레드에 묶여 있으므로 세션은 한 스레드에서만 구동합니다. 이 때문에 realtime 엔드포인트(#1376)는 모델에 전용 워커 스레드를 둡니다.

## 6. 알려진 한계

- 4비트와 8비트 체크포인트의 실시간 계수는 `docs/nemotron-voicechat.md`에 표시해 둔 자리 표시 표에 들어갑니다. 수치는 오케스트레이터가 유휴 장비에서 측정합니다.
- 샘플링 노이즈가 MLX 전역 RNG에서 나오므로, 모델마다 한 번에 세션 하나만 실행할 수 있습니다.
