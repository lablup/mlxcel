# PR #2768: 일반 전체 모델을 엔진의 드래프터로 실행

**작성일**: 2026-11-01 (머지 전 작성, 당시 PR은 열려 있었음)
**상태**: 리뷰 중
**언어**: Rust
**위험도**: 중간 (`--draft-model`을 지정할 때만 동작하며 기본 경로는 바뀌지 않음)

## 요약

#2756에서 제거한 classic draft-model 루프를 `Engine::verify_round`로 검증하는 토큰 전용 드래프터 `FullModelDrafter`로 대체하며, `generate`, `run`, `serve`, `mlxcel-server`에서 동작한다. 서버에는 이전에 없던 조합이다. 유휴 상태의 M1 Ultra에서 측정한 결과 처리량은 오르지 않았으므로, 속도 개선이 아니라 기능 복원이다.

## 1. 문제 정의

classic 루프는 배치 기반 엔진 밖에 남은 마지막 디코드 경로이자, 작은 일반 체크포인트로 초안을 만드는 유일한 방법이었다. 대체 없이 제거하면 이 기능이 사라지므로 두 PR을 함께 낸다.

## 2. 기술적 검토 사항

- **상태.** 드래프트 캐시는 현재 토큰 직전까지의 컨텍스트 접두사를 유지한다. `DraftModelState::realign`이 확정된 제안만 남기고 나머지를 잘라 내므로, 조기 종료와 철회된 요청도 같은 경로를 탄다.
- **거부 조건.** trim으로 되돌릴 수 없는 타깃이나 드래프터(#2495), 더 큰 드래프트 어휘, 선언되지 않은 `vocab_size`, 전체 모델로 지정한 DFlash 디렉터리는 시작 시 실패한다.
- **실패 범위.** 드래프트 쪽 MLX 예외나 빈 컨텍스트는 해당 행의 초안 생성만 끝낸다. 예외는 `KVCache::try_eval_state`가 전달한다(#822).
- **저장소 ID.** `--draft-model`은 `owner/name`을 `-m`처럼 해석하되 타깃의 `--revision`은 쓰지 않는다.

## 3. 기술적 선택과 그 이유

### 3.1 행별 캐시, 배치 드래프터 없음

체크포인트 하나를 모든 행이 공유하고 행마다 `DraftModelState`를 가지므로 각 행이 독립적으로 되돌린다. 대가는 직렬 검증이며, 넓은 배치에서 처리량이 줄어드는 이유다.

### 3.2 틱당 한 청크씩 catch-up

한 틱에 한 행, 한 청크만 넣으므로 catch-up이 프롬프트 전체 동안 다른 행을 멈추지 않는다. 남은 `max_tokens`가 `ticks * (block + 2)`를 넘을 때만 catch-up한다.

### 3.3 `--prompt-lookup-max-batch`를 2로 유지

늘리면 두 조합을 통틀어 B = 4와 B = 8에서 35~68% 손실이 났다.

## 5. 후속 조치

- temperature 0 출력은 일반 디코드와 바이트 단위로 같지 않다. Qwen3 B = 2에서 한 행이 안정적으로 다르며, 처음 달라지는 위치는 기록하지 못했다(#2778).
- 일반 Llama 3.1 8B bf16이 B = 2에서 B = 1보다 느린 이유를 밝혀야 한다. 그전까지 이 B = 2 결과는 드래프터의 이득으로 보지 않는다.
- 미검증: 실제 드래프터 다운로드, 진행 중 요청의 클라이언트 취소.
