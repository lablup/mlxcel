# PR #2549: 공용 DINOv2 feature encoder 추가

**작성일**: 2026-10-23

**상태**: 로컬 검증 완료 (PR 열림; 최종 CI gate 대기 중)

**언어**: Rust, Python, Markdown

**위험도**: 중간

## 요약

PR #2549는 표준 및 register-token Hugging Face checkpoint를 위한 공용 DINOv2 vision backbone을 추가하고 `mlxcel predict`를 통해 독립 image feature 추출 기능을 제공한다. Checkpoint 변환, position interpolation, mask 처리, 정규화된 intermediate feature, giant preset의 SwiGLU 경로, checkpoint 기반 preprocessing과 `last_hidden_state`, `pooler_output`, `hidden_patch_tokens` 세 output tensor를 구현한다.

최종 source는 formatting-aware clippy, 저장소 contract target 8개, 실제 CPU f32 checkpoint reference를 쓰는 집중 테스트 13개, gfx1151에서 두 checkpoint layout을 실행한 guarded ROCm CLI 검증을 통과했다. 독립 implementation 및 security/performance review에는 남은 finding이 없다. 이 보고서 작성 시점의 GitHub CI에는 실패가 없었지만 중앙 compile/lint job 3개가 아직 queued 상태였으므로 merge 준비 여부는 해당 gate 완료 후 확정한다.

## 1. 문제 정의

Video Depth Anything, MoGe-3, SAM 3D Objects는 DINOv2 transformer에 의존하지만 mlxcel에는 재사용 가능한 구현이 없었다. 각 dense model 내부에 별도 transformer를 port하면 checkpoint 변환, position interpolation, token 처리와 수치 검증이 중복된다. 공개 DINOv2 checkpoint에서 feature를 추출할 때 text generation이나 object detection 경로를 거치지 않는 독립 실행 경로도 필요했다.

구현은 두 공개 checkpoint layout을 지원하고, register token을 spatial output에서 제외하며, 업스트림의 두 position interpolation mode와 Hugging Face image processor 계약을 재현해야 했다. Resize rounding, convolution layout 변환, mask dtype 또는 token slicing이 다르면 모든 downstream feature가 바뀌고 후속 dense-model port의 결과가 조용히 잘못될 수 있다.

## 2. 변경 요약

| 영역 | 변경 |
|---|---|
| 공용 encoder | DINOv2 patch embedding, class/register/mask token, attention, LayerScale block, dense MLP와 giant SwiGLU FFN, final normalization, 정규화된 intermediate-layer 추출을 추가했다. |
| Checkpoint loading | 표준/register Hugging Face key remap, fused QKV와 SwiGLU projection, 보호된 OIHW-to-OHWI patch-convolution 변환, parent checkpoint scope loading, shape validation을 추가했다. |
| Position 처리 | 설정 가능한 antialias를 포함하는 Hugging Face size mode와 `0.1` offset을 쓰는 legacy scale-factor mode의 rectangular bicubic position interpolation을 추가했다. |
| 독립 prediction | `dinov2`와 `dinov2_with_registers`를 `features` task로 등록하고 정규화된 전체 sequence, class pooling, spatial-only patch tensor를 출력한다. |
| Preprocessing | `preprocessor_config.json`을 읽고 slow Hugging Face processor의 RGB 변환, shortest-edge resize, Pillow 호환 bicubic uint8 rounding, center crop, rescaling, channel normalization을 재현한다. |
| 안전성 | 비싼 graph operation 전에 architecture dimension, processor size, source/resized pixel, batch token 수, register token, intermediate-layer request를 제한한다. Public attention input과 public attention/MLP construction도 검증한다. |
| Fixture와 문서 | 두 small checkpoint variant의 pinned 전체 output fixture, 재현 가능한 reference generator, 환경 변수 문서, architecture capability metadata, dense-prediction 운영 가이드를 추가했다. |

이 보고서 이전 구현 diff는 19개 파일, 2,829개 추가와 14개 삭제이다. 구현 commit은 `e3ab2c2e`, `29b30a27`, `0b0ea0c3`, `bb89237b`이다.

## 3. 기술적 선택과 그 이유

### 3.1 Dense consumer가 공유하는 하나의 backbone

`Dinov2`는 checkpoint 호환 transformer를 소유하고, `Dinov2Encoder`는 dense model에 필요한 resize, ImageNet normalization, 선택된 intermediate layer와 spatial grid reshape를 추가한다. Public `Attention`과 `Mlp` type을 통해 SAM 3D Objects가 검증된 같은 primitive를 재사용할 수 있다. Scoped construction은 지정된 DINOv2 subtree만 복사해 parent weight map을 sibling head가 계속 사용할 수 있게 한다.

### 3.2 업스트림 token 및 interpolation 계약 보존

Sequence 순서는 class token, 선택적 register token, patch token이다. Position embedding은 Hugging Face와 같이 register를 삽입하기 전에 class와 patch에 적용한다. `forward_features`는 모든 token을 유지하고, `pooler_output`은 정규화된 class token을 사용하며, spatial output은 class와 register를 모두 제외한다. Position interpolation은 Hugging Face checkpoint가 사용하는 explicit-size antialias mode와 dense consumer가 사용하는 legacy scale-factor offset mode를 지원한다.

### 3.3 Byte 경계에서 slow Hugging Face processor 일치

독립 predictor는 patch-aligned input을 가정하지 않고 checkpoint processor 설정을 사용한다. Bicubic 경로는 rescaling과 normalization 전에 Pillow의 fixed-point coefficient 및 uint8 rounding 동작을 재현한다. 이 선택은 실제 slow processor output과 비교해 검증했다.

### 3.4 Allocation 전에 checkpoint dimension 검증

Config와 public layer API는 잘못되거나 과도한 hidden size, layer 수, patch grid, register 수, image size, intermediate request를 거부한다. Attention은 공용 safe dispatch를 사용하고 `Attention::forward`는 잘못된 input shape을 거부하며 public attention과 MLP constructor는 dimension과 checkpoint weight를 검증한다. 이 검증은 손상된 checkpoint metadata가 과도한 host buffer나 MLX graph를 만드는 것을 막는다.

### 3.5 전체 reference tensor commit

두 safetensors fixture는 sparse probe 대신 정규화된 NHWC input과 세 expected output tensor 전체를 담는다. 각 fixture는 공개 model ID, 변경 불가능한 checkpoint revision, library version, dtype, device와 input convention을 기록한다. 따라서 후속 consumer는 issue의 상대 RMS 허용치 `1e-3`에 대해 안정적인 end-to-end CPU oracle을 사용할 수 있다.

## 4. 구조와 데이터 흐름

```text
source image
    -> checkpoint BitImageProcessor policy
    -> f32 NHWC pixels
    -> patch convolution + class/register/mask token handling
    -> DINOv2 blocks with LayerScale
    -> final LayerNorm
    -> last_hidden_state
       + normalized class pooler_output
       + register-free hidden_patch_tokens
```

Dense consumer는 대신 `[0,1]` NHWC image와 요청할 token grid를 `Dinov2Encoder`에 전달할 수 있다. 이 경로는 antialiased bilinear resize, ImageNet normalization, 선택된 정규화 intermediate layer와 patch token의 NHWC feature grid reshape를 수행한다.

## 5. 검증

최종 source head `bb89237b`는 `cargo clippy --profile test-fast --lib --tests -- -D warnings`를 2분 29초에 status 0으로 통과했다. Fast contract target 8개와 각 self-test도 모두 status 0으로 통과했다. 독립 implementation 및 security/performance review는 정확한 processor 동작, mask dtype, scoped prefix API, allocation bound, public attention validation, 공용 fast dispatch, 제한된 intermediate request, fixture integrity 수정 후 남은 문제를 발견하지 않았다.

최종 집중 DINOv2 suite는 8분 39초 동안 rebuild한 뒤 49.71초에 실행을 마쳤다. 결과는 13개 통과, 0개 실패, 0개 ignored, 9,888개 filtered였고 두 full checkpoint 비교는 skip되지 않고 CPU f32에서 실제 실행되었다.

| CPU f32 reference | `last_hidden_state` RMS | `pooler_output` RMS | `hidden_patch_tokens` RMS |
|---|---:|---:|---:|
| `facebook/dinov2-small` | `2.432286715e-6` | `1.959671192e-6` | `2.433967071e-6` |
| `facebook/dinov2-with-registers-small` | `4.238213112e-6` | `2.756216562e-6` | `4.275870861e-6` |

Slow-processor input 비교의 상대 RMS는 `1.197926287e-7`이었다. 독립 predictor의 표준 checkpoint output은 전체 sequence, pooled class token, spatial patch token에 대해 각각 `2.705206368e-6`, `2.218856821e-6`, `2.706949506e-6`이었다. 이 측정도 CPU f32에서 실행되었으며 suite의 serialized ROCm guard는 공용 hardware 접근만 조정한다.

CLI는 8분 10초에 status 0으로 build되었다. `MLXCEL_DEVICE=gpu`를 지정한 하나의 guarded 실행은 gfx1151 AMD Radeon 8060S를 bind하고 두 공개 small checkpoint variant를 모두 status 0으로 실행했다.

| ROCm CLI checkpoint | Output과 shape | 상대 RMS |
|---|---|---:|
| Standard | `last_hidden_state` f32 `[1,257,384]` | `2.844445329e-6` |
| Standard | `pooler_output` f32 `[1,384]` | `2.473357604e-6` |
| Standard | `hidden_patch_tokens` f32 `[1,256,384]` | `2.845811506e-6` |
| Register | `last_hidden_state` f32 `[1,261,384]` | `4.548628530e-6` |
| Register | `pooler_output` f32 `[1,384]` | `2.131596900e-6` |
| Register | `hidden_patch_tokens` f32 `[1,256,384]` | `4.596212478e-6` |

모든 ROCm 결과는 `1e-3` 미만이다. 각 variant는 `meta.json`과 `result.safetensors`를 생성했고 safetensors에는 위 표의 f32 dtype과 shape을 가진 문서화된 key 세 개만 정확히 존재한다. 두 model type의 `arch --json`과 `predict`, image, embeddings 경로도 통과했다.

이 보고서 작성 시점에 GitHub CI 실패는 없었다. 중앙 `cargo-clippy`, CPU-only link, OpenXLA feature compile job은 아직 queued 상태였으므로 CI 완료로 기록하지 않으며 merge gate로 남겨 둔다.

## 6. 제한 사항

공개 giant checkpoint 전체는 실행하지 않았다. Giant preset 값과 SwiGLU remapping/sanitizer 동작에는 unit coverage가 있지만 이 보고서는 실제 giant forward, 실제 weight parity 또는 memory 특성을 주장하지 않는다. Metal runtime parity, DINO training/classification head, `/v1/embeddings`, RF-DETR windowed variant는 이 PR 범위 밖이다. Throughput benchmark도 수행하지 않았다.

## 7. 학습 포인트

- 공용 backbone은 full-sequence view와 spatial-only view를 모두 제공해야 한다. Register token은 transformer context로 유효하지만 image-grid 위치는 아니기 때문이다.
- Image processor parity에는 normalization 전의 integer resize 동작이 포함된다. Floating-point network만 일치해서는 end-to-end parity를 입증할 수 없다.
- Scoped checkpoint loading은 unrelated head weight를 소비하지 않고 composite dense model이 backbone을 재사용하게 한다.
- Full-tensor fixture는 sparse probe가 놓칠 수 있는 체계적 drift를 드러내며, 충분한 metadata를 남겨 이후에도 oracle을 재현할 수 있게 한다.

## 8. 후속 조치

- Merge 전에 중앙 CI gate 완료를 확인한다.
- 적절한 hardware와 memory를 사용할 수 있을 때 실제 giant checkpoint를 실행한다.
- 적절한 Apple hardware에서 Metal runtime parity를 검증한다.
- 이 encoder를 후속 Video Depth Anything, MoGe-3, SAM 3D Objects port에서 재사용한다.
