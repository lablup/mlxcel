## Executive Summary

Two intermittent test failures from issue #2467 are fixed in test code only. The mllama parity test's exact-zero assert now uses the documented 1e-6 reassociation tolerance (the same constant the sibling comparison already used), and the WebUI router harness now waits on the 401 catalog response itself instead of assuming the session-key prompt mounts within 5 s of a refresh click. The item-2 root cause is a test-side timing assumption: the click's forced snapshot is deferred to the next 2 s poll tick, so the 401 could land outside the 5 s window under CPU load. The DOM signal was never late; no product code changed. The harness now passes 20 consecutive runs including 7 under CPU load.

## 3. Technical Decisions

### 3.1 Item 2 root cause: deferred snapshot, not late DOM

**Context:** the 5 s DOM wait intermittently expired.

**Chosen:** root-caused via an instrumented run (page-level request/response trace). `WebUiSynchronizer.refresh()` (webui/src/state/sync.ts:162) returns early when an observation tick is already in flight, so the "Refresh server state" click only sets `needsFullSnapshot` and defers the forced full snapshot to the next 2 s poll tick (`visiblePollMs`, line 39). The one-shot route then stays armed until that later tick's catalog GET, so the 401 lands at (in-flight tick remainder + up to 2 s + bootstrap latency) after the click, which can exceed the 5 s window under CPU load. The trace shows the click landing 2 ms after the bootstrap GET (tick in flight) and the 401-to-prompt latency at ~22 ms.

**Fix:** wait on the signal that means "401 handled": `page.waitForResponse` with predicate (status 401, same origin, catalog pathname) registered BEFORE arming the one-shot route, then click, then `await`, then assert session-key visibility. Not a timeout raise.

### 3.2 Item 1: reuse, not a new constant

`TILE_SELECTION_REASSOCIATION_TOL` (1e-6, #1067) is reused; its doc comment now names both comparisons in the file. The lineage matches #953's `RAGGED_REASSOCIATION_TOL` in `src/models/mllama/text.rs`.
