**Date**: 2026-10-24
**Status**: Partial

## Executive Summary

PR #2580 adds `sam3d_body` to `mlxcel predict`. The body-only path combines a DINOv3-H+ image backbone, camera-ray conditioning, a six-layer decoder with iterative keypoint feedback, and the MHR parametric body model. It returns a colorless 18,439-vertex mesh, 70 3D keypoints, 127 joint coordinates, and the raw three-value weak-perspective camera prediction.

The implementation and its static correctness and security reviews are complete. Revision `23d372286d5abdfe5944471858a48e8f1fa31182` adds only the reviewed empty-Objects-mesh test expectations and a function-local Clippy allowance that preserves authenticated BF16 oracle literals. Authenticated upstream reference generation succeeded for an explicit person box and the default whole-image case. The corrected Rust pipeline then reproduced every reference tensor exactly in both cases, and the literal no-options CLI reproduced the default case exactly. A standard OBJ parser accepted the emitted mesh. The required Clippy gate, all local acceptance gates, and the independent evidence audits passed, and CI is green for the tested Rust source. The report status remains **Partial** only because the final Python, fixture, documentation, and report commit has not yet completed CI.

## 1. Problem Statement

### 1.1 Background

SAM 3D Body reconstructs a human body from one RGB image and an optional person box. Its forward path differs from existing dense predictors in several ways:

- the released checkpoint mixes 615 BF16 backbone tensors, 574 F32 decoder and MHR tensors, 11 I32 topology tensors, and 3 U8 masks;
- the published configuration is 512×512 even though the upstream dataclass default is 512×384;
- the decoder predicts an MHR parameter vector at every layer and feeds projected 2D and pelvis-relative 3D keypoint information into later layers;
- MHR reconstruction requires rotation conversions, a 889×249 parameter transform, 127-joint forward kinematics, pose correctives, ordered sparse accumulation, and linear blend skinning;
- the output mesh is colorless, while the existing SAM 3D Objects writer must retain its colored OBJ format.

Before this PR, mlxcel did not recognize `sam3d_body`, could not run its body reconstruction graph, and could not write a colorless mesh through the shared dense-prediction output contract.

### 1.2 Correctness Risks

| Risk | Impact | Treatment |
|---|---|---|
| Using the stale 512×384 default | Changes patch count, position encoding, and every downstream prediction | Require an explicit released `[512,512]` configuration |
| Converting the mixed checkpoint to one dtype | Changes DINO and MHR numerical behavior and corrupts integer topology | Validate all 1,203 stored tensors and preserve their dtypes |
| Reordering sparse additions | Produces different F32 pose-corrective and skinning results | Accumulate in source order, matching `numpy.add.at` |
| Clipping partly outside boxes | Changes the affine crop and camera conditioning | Preserve the box and fill outside pixels with black |
| Reusing host bytes after their buffer is dropped | Can leave MLX arrays referring to invalid storage | Materialize every tensor before releasing its source buffer |
| Changing the shared OBJ path | Could regress SAM 3D Objects exports | Add optional colors and retain the existing colored formatting branch |

## 2. Technical Decisions

### 2.1 Preserve the released graph and precision

The loader validates the complete released schema before selecting the 869 arrays used by the body-only path. The retained model keeps the BF16 DINOv3 weights, F32 decoder and MHR weights, and I32 topology. It retains the coarse hand tokens and hand PCA data used by the main body head while excluding the separate hand-refinement decoder and other unused buffers.

The configuration now requires an explicit 512×512 image size. This prevents a missing field from silently selecting the upstream dataclass's stale 512×384 default. At 512×512 with patch size 16, the backbone processes 1,024 patch tokens plus one class token and four storage tokens.

### 2.2 Port MHR without changing accumulation order

The MHR path stays in F32 and preserves the pinned operation order:

```text
decoder pose token
  -> 519 predicted values
  -> global/body/shape/scale/hand/face partitions
  -> compact body and hand rotations
  -> 204 model parameters
  -> 889 joint DOFs
  -> blend shapes + pose correctives
  -> 127-joint forward kinematics
  -> sparse linear blend skinning
  -> 18,439 vertices, 127 joints, 70 keypoints
```

Sparse pose-corrective and skinning contributions use ordered host F32 accumulation. This is intentionally more constrained than a parallel reduction because floating-point addition order is part of the upstream result.

### 2.3 Keep the public output contract shared

`Mesh.vertex_colors` becomes optional. A Body mesh writes `v x y z` with six digits after the decimal point and one-based triangular faces. SAM 3D Objects continues to use the existing colored `v x y z r g b` path and its eight-significant-digit formatting.

The predictor exposes one task, `body_mesh`, through the existing dense registry and architecture registry. It accepts:

- `bbox`: source-pixel `[x1,y1,x2,y2]`, defaulting to the whole image;
- `cam_int`: a flat row-major 3×3 matrix or three rows of three values, defaulting to focal length `sqrt(width² + height²)` and the image center.

Partly outside boxes remain unchanged and receive black crop padding. Nonfinite, degenerate, and wholly nonintersecting boxes fail.

## 3. Implementation Details

### 3.1 Model graph

The new `src/vision/dense/sam3d_body/` module contains the released DINOv3-H+ backbone, learned axial RoPE, camera rays and Fourier features, prompt embeddings, six decoder layers, the MHR head and body, preprocessing, strict checkpoint loading, and the public predictor.

The backbone uses 32 blocks at width 1,280, 20 heads of dimension 64, patch size 16, four storage tokens, SwiGLU, and LayerScale. Decoder layers use the upstream fast scaled-dot-product attention route and fused biased linear behavior. Every non-final decoder layer updates 2D keypoint tokens from sampled image features and updates 2D and 3D positional embeddings from the current body estimate.

### 3.2 Outputs

The predictor writes these F32 tensors to `result.safetensors`:

| Key | Shape |
|---|---:|
| `vertices` | `[18439,3]` |
| `keypoints_3d` | `[70,3]` |
| `joint_coords` | `[127,3]` |
| `camera` | `[3]` |

`mesh.obj` contains 18,439 colorless vertices and 36,874 faces from `head_pose.faces`. `meta.json` records the unchanged box, camera intrinsics, mesh span, coordinate convention, configured image size, and precision policy. The shared dense writer also emits an empty `instances.json`.

### 3.3 Loader hardening

Three concrete findings were corrected before the final static review:

1. Checkpoint arrays created from temporary byte buffers are now materialized before those buffers leave scope, including integer topology arrays.
2. Body configuration loading now rejects a missing or non-released crop size and accepts only explicit `[512,512]`.
3. Dense `config.json` loading uses one stable regular-file handle and rejects files above 8 MiB, including files that grow during the read.

The corrected-source security review closed all three findings. The independent implementation review found no remaining correctness or integration issue in the released graph, preprocessing, decoder feedback, MHR reconstruction, writer, registry, or CLI surface.
