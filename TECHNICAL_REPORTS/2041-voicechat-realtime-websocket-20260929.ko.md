# 기술 보고서: PR #2041 - Nemotron VoiceChat용 /v1/realtime WebSocket

**날짜**: 2026-09-29

**상태**: 4비트 체크포인트에서 파일 클라이언트로 구현과 검증을 마쳤습니다. 실시간 마이크 대화는 검증하지 못했습니다. 머지 대기 중입니다.

**언어**: Rust

**위험도**: 중간. 공유 HTTP 서빙 경로를 건드립니다. hyper 연결이 이제 upgrade를 처리하고, 서버 기동 과정에 모델 타입 분기가 새로 생겼습니다. 서버에 처음으로 오래 유지되는 상태 보유 연결이 추가됩니다.

## 요약

이 PR은 Nemotron VoiceChat 온라인 세션(#1378)을 `/v1/realtime` WebSocket으로 제공합니다. 프로토콜은 JSON 제어 메시지와 양방향 base64 PCM16 오디오를 사용하며, 동시에 활성 세션은 하나만 허용합니다. 모든 MLX 작업은 전용 엔진 스레드 하나에서 실행됩니다. WAV 파일 클라이언트와 실시간 마이크/스피커 클라이언트도 함께 넣었습니다.

4비트 체크포인트에서 WAV를 소켓으로 보낸 결과는 `mlxcel generate --stream`과 받아쓰기, 답변, 오디오가 모두 같습니다. 유일한 차이는 PCM16 스케일링에서 생기는 마지막 비트입니다. 이로써 에픽 #1372의 서빙 인터페이스가 완성됩니다.

## 1. 문제 정의

mlxcel의 오디오 엔드포인트는 지금까지 요청/응답 방식이었고, 각 엔드포인트의 워커는 한 번에 명령 하나만 처리했습니다. 전이중 음성 모델에는 오디오가 양방향으로 흐르는 동안 계속 열려 있는 연결이 필요합니다. 세션 상태(캐시 계열 여섯 가지와 RNG)는 대화가 끝날 때까지 MLX 스레드에 머물러야 하고, 비동기 런타임은 MLX 코드를 절대 실행하면 안 됩니다.

## 2. 변경 요약

- **엔진**(`server::realtime_engine`, `server::realtime_session`):
  - 스레드 하나가 체크포인트를 로드하고 활성 세션을 소유합니다.
  - 명령(`open`, `push`, `flush`, `cancel`, `close`)은 FIFO 채널로 들어오고, one-shot 채널로 응답합니다.
  - `try_reserve`는 연결을 하나만 받아들입니다.
  - 명령 처리 중 panic이 나도 격리되어 엔진은 계속 동작합니다.
  - `close`는 MLX 버퍼 캐시를 세션마다 한 번 비웁니다. 프레임마다 비우지 않습니다.
- **프로토콜**(`server::realtime_protocol`): 기준 서버의 메시지와 이벤트 집합, PCM16 base64 인코딩과 디코딩, 이벤트 id를 구현했습니다.
- **라우트**(`server::routes::realtime`):
  - 소켓 루프는 append를 1280 샘플 단위로 잘라 보내고, 한 조각의 이벤트를 모두 전달한 뒤에 다음 조각을 보냅니다.
  - 세션이 활성인 동안 들어온 두 번째 연결은 `server_busy`와 종료 코드 1013을 받습니다.
  - 연결이 드롭되는 경우를 포함해 모든 종료 경로에서 예약을 해제합니다.
  - 라우트는 `--api-key`와 `--api-prefix` 뒤에 등록됩니다.
- **기동**: VoiceChat 체크포인트이면 엔진을 띄웁니다. 채팅 워커, 스케줄러, 텍스트 워밍업은 건너뜁니다. 채팅 엔드포인트는 소켓 경로를 안내하는 메시지와 함께 501로 응답합니다.
- **클라이언트**:
  - `examples/voicechat_file_client.rs`
  - `examples/voicechat_microphone.rs`: 선택적 `voicechat-mic` 기능 뒤에서 cpal을 사용합니다.

## 3. 기술적 선택과 그 이유

### 전용 엔진 스레드와 FIFO 명령 채널

MLX 평가는 스레드에 묶여 있고, 세션은 모델을 빌려 씁니다. 그래서 엔진이 둘을 같은 스레드에 둡니다. 비동기 소켓 태스크는 명령을 보내고 응답을 기다리기만 합니다.

채널이 FIFO이므로, 연결이 끊겼을 때 처리기는 `close`를 기다리지 않고 큐에 넣기만 해도 됩니다. 다음 연결의 `open`은 항상 그 close 뒤에 실행되기 때문입니다. 따라서 예약 해제는 드롭된 태스크가 await 지점에 도달하는지와 상관없이 이루어집니다.

### 단일 슬롯에 대한 제한

프로세스당 세션이 하나뿐이라, 잘못 동작하거나 악의적인 클라이언트가 붙잡을 수 있는 자원이 바로 그 슬롯입니다. 리뷰 단계에서 다음 네 가지 제한을 추가했습니다.

| 제한 | 값 | 막는 상황 |
|---|---|---|
| 세션 길이 | 오디오 600초 (클라이언트가 요청한 값은 이 안으로 제한) | 캐시가 한없이 커짐 |
| WebSocket 메시지와 프레임 크기 | 1 MiB | 거대한 append 하나가 메모리를 차지하고 엔진을 붙잡음 |
| 설정 대기 시간 | 30초 | 설정하지 않는 연결이 슬롯을 점유 |
| 설정 후 유휴 시간 | 120초, ping은 활동으로 치지 않음, 종료 코드 1008 | 유휴 상태이거나 ping만 보내는 클라이언트가 슬롯을 점유 |

`/health`는 엔진 스레드가 살아 있는지도 확인합니다.

### 이슈 본문보다 기준 구현을 따름

이슈의 표와 mlx-vlm의 `realtime.py`가 다른 곳은 기준 구현을 따랐습니다.
- 잘못된 base64나 잘못된 샘플레이트에는 `inference_error`를 돌려줍니다.
- commit과 cancel 뒤에는 종료 코드 1000으로 닫습니다.
- 서버가 모델 하나만 실행하므로 `session.model`은 선택 사항입니다.

Python의 `int()`와 마찬가지로 `sample_rate`와 `seed`에는 정수로 떨어지는 실수 값도 받습니다.

### 마이크 클라이언트는 기본 빌드에서 제외

cpal은 플랫폼 오디오 바인딩을 끌어옵니다. macOS에서는 CoreAudio를, Linux에서는 ALSA 헤더를 요구합니다. 그래서 cpal은 `voicechat-mic` 기능을 켤 때만 들어오는 선택적 의존성으로 두었고, 예제는 `required-features`에 이를 선언합니다. 라이브러리, 서버, CI, 테스트 대상은 cpal을 컴파일하지 않습니다.

## 4. 검증

조건: 4비트 체크포인트, `mlxcel-server`, 파일 클라이언트, "What is the capital of France?" 뒤에 무음 3초, 시드 0.
- **이벤트**: 받아쓰기 델타가 "What is the capital of France"를, 텍스트 델타가 "The capital of France is Paris."를 만듭니다. 오디오 델타는 61개이고 각각 1764 샘플이며, 프레임 인덱스는 끊김 없이 이어집니다. 마지막에 `response.done`이 옵니다.
- **`--stream`과 오디오 비교**: 소켓으로 받은 오디오는 `--stream`과 같은 107604 샘플이고, 모든 샘플이 하나의 실수 파형과 일치합니다. 정수 WAV끼리 차이가 나는 이유는 CLI WAV 작성기가 32768로, 전송 형식이 32767로 스케일링하기 때문입니다.
- **busy/free**: 세션 중에 들어온 두 번째 연결은 `server_busy`와 종료 코드 1013을 받습니다. 첫 세션이 끝나면 다음 연결은 정상적으로 설정됩니다.
- **기타 엔드포인트**: 채팅은 501로 응답하고 `/health`는 정상입니다.

로컬 게이트:
- fmt, clippy (lib와 tests, 예제, 마이크 기능)
- `cargo test --lib server::` (3268개 통과)
- `tests/realtime_ws.rs` (가짜 엔진으로 9개 통과)
- 계약 테스트

**검증하지 못한 항목**: 실시간 마이크 대화. 이 비대화형 에이전트 세션에서는 입력 스트림을 여는 단계가 멈추거나 실패했습니다. 프로세스에 마이크 권한이 없을 때 나타나는 증상과 일치합니다. 마이크 접근 권한이 있는 터미널에서 직접 실행해 확인해야 합니다.

## 5. 알려진 한계

- **CORS**: `--cors-origins`는 WebSocket upgrade를 제한하지 않습니다.
- **프로세스당 세션 하나**: 명세대로입니다.
- **에코 제거 없음**: 마이크 클라이언트는 헤드폰으로 사용해야 합니다.
- **실시간 계수**: 이번에는 측정하지 않았습니다. `docs/nemotron-voicechat.md`의 자리 표시 표에 들어갈 값입니다.
