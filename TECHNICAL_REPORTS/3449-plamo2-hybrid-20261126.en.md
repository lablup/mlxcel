# PR #3449: PLaMo 2 hybrid on OpenXLA/IREE

**Date**: 2026-11-26

**Status**: CPU/CUDA acceptance passed; ROCm replay pending externally

## Executive Summary

PLaMo 2 now runs original `pfnet/plamo-2-1b` weights through OpenXLA/IREE. Eight Mamba2-variant blocks alternate with eight sliding-window attention blocks, each followed by an MLP, on the existing hybrid KV and recurrent-state contract. Acceptance found an inherited RoPE scaling error that short-sequence oracles could not see, and pinned the window boundary that HF defines inclusively.

## Problem Statement

`from_json_str` rejected `plamo2`. The issue described PLaMo 2 as Mamba2 with dt/B/C RMSNorms, but the checkpoint and HF code need more: four offset norms per block with different offsets, a per-head interleaved z/x input projection, B/C/dt projected after the convolution, no gated output norm, per-head learned Q/K scales after weightless per-head RMSNorm, and a 2048-token window that keeps keys with `age <= W`, one wider than the existing XLA local masks. The HF remote code needs CUDA-only `mamba_ssm`, so no HF CPU oracle exists.

## Change Summary and Technical Decisions

`SsmKind::Plamo2` (`ssm_plamo2.rs`) builds the mixer from the shared conv and selective-scan helpers, leaving the SSD internals and Mamba1 untouched. The four norm offsets are added to the weights in the graph and the shared `GemmaFf` four-norm placement runs unchanged, so other families' graphs do not change. Q/K scale shape support was extended to `[heads, head_dim]`. Plamo2 stores `sliding_window = W + 1` so the existing `age < sliding_window` masks reproduce HF's inclusive window without touching shared mask code.

The dt time step follows the MLX eager oracle, which clamps `softplus(dt + dt_bias)` to (0.001, 100); the HF CPU path does not clamp. Padded prefill rows still get `dt = 0`. The config originally inherited `RopeScaling::Llama3` (factor 32) from the Llama-3.2 base; it now uses plain RoPE, asserted by a unit test.

## Validation and Evidence Boundaries

The 40-token oracle is the MLX eager CPU run (F32, revision `92c75fd6`). Structural independence comes from `plamo2_oracle.py`, a float64 reimplementation of the HF formulas with a naive sequential scan. On local-task and CUDA, the real checkpoint matched 40/40, hybrid synthetic parity passed (worst 6.9e-6 and 1.0e-5), and the window probe passed prefill, decode and ragged decode (worst 4.2e-6 and 5.4e-6). The probe loads the same weights with W = 2047, 2048 and 2049, requires each to follow its own reference mask, and requires the three trajectories to differ, so an off-by-one cannot pass. Half the synthetic heads sit on the dt clamp floor, so removing the clamp fails the 3e-4 tolerance.

On CUDA, `validate_arch.sh --batch 4 --requests 8 --maxcap 24 --oracle` exited 0, and four HTTP and four SSE server completions matched the CLI's displayed text and token counts. The lib tests kept every previous golden byte-identical; fmt, clippy, the prompt-cache/APC guard, the env-var documentation check and the Used by check passed. Evidence is in `spike/openxla/plamo2_reference/`.

Not verified: ROCm `hip`, Python re-decoding of token ids in the CLI/server check (the checkpoint ships only `tokenizer.jsonl`), single-sequence window-probe logits (tokens are checked there; logits on the ragged path), and HF numerical equivalence of the clamped dt.

## Learning Points and Follow-up

A family config built on another model's defaults inherits every field it does not override, including position encoding; short oracles cannot detect a low-frequency RoPE error, so a long-position probe belongs in each new family's acceptance. Falcon-H1 shares the same base without overriding `rope` and needs a correction. Request an external ROCm replay on the final head and rebase after Jamba (#3448) before merge.
