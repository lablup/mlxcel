# 기술 보고서: PR #1857 — 재현 가능한 WebUI 번들

**날짜**: 2026-09-12
**상태**: 머지 전; 로컬 번들·정적 라우터 검증 완료, CI 및 후속 운영 경로 통합 대기
**언어**: Rust, TypeScript/React, Python, 영어/한국어 문서
**위험도**: 중간

## 요약

[PR #1857](https://github.com/lablup/mlxcel/pull/1857)은 에픽 #1834에서 #1835의 계약을 따르는 오프라인 번들 기반 #1836을 구현합니다. 커밋된 React 자산을 개발용·릴리스 Rust 산출물에 임베드하여 런타임 Node나 소스 체크아웃 의존성을 없앱니다. 운영용 `--webui` 시작 경로 구현은 아니며, 해당 통합은 #1838이 담당합니다.

## 1. 문제 정의

개발용 바이너리가 체크아웃에서 파일을 읽거나 Cargo가 네트워크에 의존하는 프런트엔드 빌드를 암묵적으로 수행하거나 생성 자산이 소스와 어긋난다면 브라우저 셸을 독립적인 배포물로 볼 수 없습니다. 병렬 페이지 개발에도 제각각인 빌드 방법 대신 단일 재생성 파이프라인과 명시적인 크기 예산이 필요합니다.

## 2. 변경 요약과 기술적 선택

- strict TypeScript/React와 Vite는 잠긴 pnpm 의존성 그래프 및 정확한 Node 26.5.1/pnpm 11.18.0 도구 체인을 사용합니다. Python 빌드 진입점이 Vite 이후 소스·파일 매니페스트를 작성합니다. 따라서 `pnpm build`만 실행해서는 배포 파이프라인을 완료할 수 없습니다.
- 검증은 독립적인 임시 디렉터리에서 두 번 빌드하고 상호 바이트 및 커밋된 자산과 비교합니다. 오래된 입력, 누락 자산, 잘못된 셸 구조, 예산 초과를 거부합니다. 매니페스트에는 타임스탬프나 절대 빌드 경로를 넣지 않습니다.
- 기본 `webui` feature는 선택적 임베딩·MIME 의존성을 활성화합니다. `rust-embed`에 `debug-embed`를 적용하여 개발용 파일 시스템 의존성을 없앱니다. 기본 feature를 끄면 정적 모듈과 자산을 제외하며 백엔드 feature는 별도로 선택할 수 있습니다.
- 재사용 라우터는 `/webui`와 자산만 소유하고 검증된 API 접두사 아래 중첩할 수 있습니다. 상태 확인·API 경로를 유지하고 광범위한 SPA 대체 응답 대신 해시 탐색을 사용합니다. 정적 자산은 공개이며 관리 API 인증과 브라우저 출처 검사는 #1837의 책임입니다.
- 영어·한국어 기여자 문서는 feature 조합, 표준 재생성, 라우터 연결, 테스트 범위, 이동 산출물 검증 요구 사항을 설명합니다.

## 3. 리뷰와 보안 보완

리뷰에서 weak/list ETag 처리를 보강하고 지원하지 않는 메서드에도 일반·리디렉션·없는 경로·조건부 응답과 같은 보안 헤더 정책을 적용했습니다. 인코딩된 경로 탐색, NUL, 역슬래시 입력을 거부하며 부팅 불가능한 인덱스를 성공한 빈 페이지로 반환하지 않습니다. HTML·매니페스트는 재검증하고 콘텐츠 해시 자산에는 immutable 캐시를 허용합니다.

보안 수정은 React·React DOM·scheduler의 MIT 고지를 `NOTICE`와 임베드 라이선스 자산에 보존했습니다. 검증기는 정확한 도구 버전, 생성 해시·크기와 소스 다이제스트를 검사하고 초기·전체 JavaScript 예산을 구분하며 디버그 산출물과 활성 외부 출처 참조를 검사합니다. 정적 검사는 브라우저 테스트와 후속 API 보안을 보완할 뿐 대체하지 않습니다.

## 4. 검증 근거

로컬 구현·리뷰 실행에서 다음 항목의 통과가 보고되었으며, 유닛 조정자가 번들 및 공통 계약 검증을 독립적으로 반복했습니다.

- 프런트엔드 frozen-lockfile 설치, 타입 검사, 린트, 단위 테스트, Playwright Chromium 셸 테스트.
- `make verify-webui-bundle`: 두 번의 새 빌드와 커밋된 바이트 일치. 번들 다이제스트는 `1b50b860b289ce10a4fac31da4f9ecddafc7b5480ab25e942c54d40d13064cd3`입니다. 오래된 소스·빈 번들/인덱스·JavaScript 누락 음성 사례는 의도대로 실패했습니다.
- 정적 Rust 라우터 테스트 12개(`cargo test --profile test-fast assets_tests --features webui`), `cargo check --profile test-fast --no-default-features --lib`를 포함한 feature 활성/비활성 확인, 공통 계약 fixture 30개.
- 포맷, 적용 범위 내 라이선스 헤더, 문서 링크, 공백 검사. 로컬 교차 저장소 참조 검사는 수동 검토 대체 경로를 사용했으며 무관해 보이는 숫자 참조는 CSS 색상이었습니다.

루트 검증 실행은 런타임·자산 리비전 `dd918147`에서 **개발용 및 배포 프로파일 릴리스** 정적 하네스를 각각 빌드하고 이동했습니다. 이후 `3d2259cc`는 문서만 변경했습니다. 두 결과 모두 `result: pass`, JS/CSS 자산 2개 요청, HTML 453바이트를 기록했습니다. 샌드박스 음성 대조군은 소스 자산 읽기와 외부 네트워크가 차단됨을 확인했으며 PATH에는 Node 없이 시스템 도구만 있었습니다. 상태 확인·API 대조 경로, 셸·매니페스트·자산, HEAD, 304, 404, 405를 확인했습니다. 릴리스 컴파일에는 7분 22초가 걸렸습니다.

하네스는 운영 정적 라우터를 사용하지만 상태 확인·모델 경로는 스텁입니다. 따라서 자산 이동 독립성을 입증할 뿐 운영 CLI 시작이나 추론의 정확성을 입증하지 않습니다. MLX 동적 라이브러리와 Metal 리소스 요구 사항은 브라우저 자산과 별개입니다.

| 측정 항목 | 바이트 | 상한 |
|---|---:|---:|
| 초기 JavaScript gzip | 68,364 | 204,800 |
| 전체 JavaScript gzip | 68,364 | 716,800 |
| 전체 임베드 자산 | 227,718 | 5,242,880 |

보고서 작성 시 PR CI는 실행 중이고 CUDA 컴파일은 대기 중이었습니다. 로컬에서 CUDA 의존성 그래프 분리는 살펴보았으나 CUDA 컴파일이나 추론 통과를 주장하지 않습니다. Chromium·정적 테스트에서 Safari·실모델·운영 서버 이동·관리 인증의 인수 검증을 추론하지 않습니다.

## 5. 학습 포인트와 남은 통합

프런트엔드 빌드 재현성, 개발용 산출물의 임베딩, 이동한 프로세스의 오프라인 실행은 서로 다른 속성입니다. 바이트 비교가 실행 시 소스 파일 접근 차단을 대신할 수 없습니다. 정적 라우터 하네스도 번들을 격리해 검증하기에는 적절하지만 완성된 WebUI 서버로 설명해서는 안 됩니다.

시작 경로 담당자는 검증된 접두사 아래 라우터를 한 번 연결하고 운영 서버 이동 검증을 다시 수행해야 합니다. 보안·클라이언트·페이지 담당자는 동일 출처 정책과 표준 자산 재생성 파이프라인을 유지해야 합니다. 후속 채팅·시각화 코드는 필요하면 지연 로딩으로 예산을 지켜야 하며, 최종 macOS/Safari 및 실체크포인트 인수 검증은 #1848에 남아 있습니다.
