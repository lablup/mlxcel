# 기술 보고서: PR #2593 — Qwen VL 텍스트 배치 디코드

**날짜:** 2026-10-25
**관련 이슈:** #2562, #2566, #2567, #2587

## 요약

Qwen2-VL, Qwen3-VL, Qwen3-VL-MoE 텍스트 모델이 위치 인코딩 방식별로 디코드를 배치 처리합니다. Qwen VL/Omni wrapper 5개는 실제 요청 ID 진입점을 통해 새 경로를 사용합니다. Metal 성능 및 체크포인트 검증은 #2587에 남아 있습니다.

## 문제

기존 wrapper는 요청별 MRoPE 상태를 유지하기 위해 각 행을 따로 실행하여 가중치 projection과 FFN 계산을 반복했습니다. 모든 행에 동일한 위치 인코딩을 적용하면 텍스트 요청의 계산이 달라질 수 있어, 기존 요청별 경로 선택을 보존해야 합니다.

## 변경 사항

디코드 행을 일반 RoPE와 MRoPE 그룹으로 나누고 그룹별 임베딩, projection, FFN 또는 expert 연산, 최종 정규화와 logits를 배치 처리합니다. 결과는 원래 요청 순서로 복원하며 attention과 캐시 갱신은 요청별로 유지합니다. MRoPE 테이블은 그룹당 한 번 계산하여 모든 층에서 재사용하고, 단일 행 그룹은 기존 단독 실행 경로를 사용합니다.

공통 MRoPE 도우미는 요청별 캐시 offset과 delta로 위치를 구성합니다. Prefill, 요청 ID 누락, 저장된 위치 텐서의 적용 범위, 모델 전역 DeepStack 상태에서는 기존 행별 처리를 유지합니다. 이는 기존 동작 보존이며 #2567의 전역 DeepStack 상태 격리 문제를 해결한 것은 아닙니다.

로그 비교 도구는 새 요청 ID를 준비합니다. 이미지 배치 경로는 첫 행에 실제 이미지 prefill을 수행하고 나머지 행은 독립적인 텍스트 prefill을 한 뒤 첫 행의 teacher-forced 디코드 logits를 출력합니다. 기존 TP 옵션은 텍스트 경로로 제한됩니다.

## 검증

CPU에서 세 텍스트 모델의 parity fixture, 실제 객체로 구성한 wrapper 5개의 실행, MRoPE 위치 테스트 2개, 정확한 DeepStack fallback 테스트 2개, 경로 분류 테스트 8개, trace 예제 테스트 7개가 통과했습니다. 서로 다른 프롬프트 길이와 delta, 혼합 그룹, 저장 위치 fallback 및 B0/B1 계약을 확인했습니다. 컴파일, 포맷, 소스 계약, 전체 workspace/all-target Clippy도 통과했으며 최종 Clippy 실행은 2분 38초였습니다.

최종 리뷰 결과는 PR에 기록합니다. 실제 이미지 체크포인트, Metal trace, 서버 동시성 및 처리량은 #2587에서 검증해야 합니다. 사용자 지시에 따라 로컬 CI와 리뷰가 머지 기준이며 원격 CI를 기다리지 않습니다.

## 기술적 결정과 학습

수학적으로 동등한 위치 인코딩이어도 단독 실행과 동일한 조건으로 그룹을 나눕니다. 저장 위치와 전역 상태의 fallback을 명시적으로 유지합니다. Wrapper의 서버 연결 여부는 분류 선언만으로 판단하지 않고 실제 공개 진입점을 호출하는 테스트로 확인합니다.
