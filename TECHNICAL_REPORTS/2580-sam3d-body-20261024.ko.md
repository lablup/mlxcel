# 기술 보고서: PR #2580 - SAM 3D Body 메시 예측 추가

**작성일**: 2026-10-24
**상태**: 부분 완료
**언어**: Rust, Python, Markdown
**위험도**: 높음

## 요약

PR #2580은 `sam3d_body`를 `mlxcel predict`에 추가합니다. Body 전용 경로는 DINOv3-H+ 이미지 backbone, camera-ray conditioning, keypoint feedback이 있는 6-layer decoder, MHR parametric body model을 결합합니다. 결과로 색상이 없는 18,439-vertex mesh, 70개 3D keypoint, 127개 joint coordinate, 3개 값으로 된 raw weak-perspective camera 예측을 반환합니다.

구현과 정적 정확성 및 보안 검토는 완료되었습니다. Revision `23d372286d5abdfe5944471858a48e8f1fa31182`는 검토된 Objects empty-mesh 테스트 기대값과 인증된 BF16 oracle literal을 유지하는 function-local Clippy allow만 추가합니다. 명시적 person box와 기본 전체 이미지 case의 인증된 upstream reference 생성이 성공했습니다. 수정된 Rust pipeline은 두 case의 모든 reference tensor를 정확히 재현했고, literal no-options CLI도 default case를 정확히 재현했습니다. 표준 OBJ parser는 생성된 mesh를 정상적으로 읽었습니다. 필수 Clippy gate, 모든 local acceptance gate, 독립 증거 감사가 통과했고 검증된 Rust source의 CI도 green입니다. Final Python, fixture, documentation, report commit의 CI가 아직 완료되지 않았으므로 보고서 상태는 **부분 완료**입니다.

## 1. 문제 정의

### 1.1 배경

SAM 3D Body는 하나의 RGB 이미지와 선택적인 person box에서 사람의 body를 복원합니다. Forward 경로는 기존 dense predictor와 다음 면에서 다릅니다.

- 공개 checkpoint는 BF16 backbone tensor 615개, F32 decoder 및 MHR tensor 574개, I32 topology tensor 11개, U8 mask 3개를 함께 저장합니다.
- upstream dataclass 기본값은 512×384이지만 공개 configuration은 512×512입니다.
- decoder는 각 layer에서 MHR parameter vector를 예측하고, 투영된 2D keypoint와 pelvis 기준 3D keypoint 정보를 다음 layer에 반영합니다.
- MHR 복원에는 rotation 변환, 889×249 parameter transform, 127-joint forward kinematics, pose corrective, 순서가 고정된 sparse accumulation, linear blend skinning이 필요합니다.
- 출력 mesh는 colorless 형식이지만 기존 SAM 3D Objects writer의 colored OBJ 형식은 그대로 유지해야 합니다.

이 PR 이전에는 mlxcel이 `sam3d_body`를 인식하거나 body reconstruction graph를 실행할 수 없었고, 공유 dense-prediction 출력 계약으로 colorless mesh를 쓸 수도 없었습니다.

### 1.2 정확성 위험

| 위험 | 영향 | 대응 |
|---|---|---|
| 오래된 512×384 기본값 사용 | Patch 수, position encoding, 이후 모든 예측이 달라짐 | 명시적인 공개 `[512,512]` configuration만 허용 |
| 혼합 checkpoint를 하나의 dtype으로 변환 | DINO와 MHR 수치 동작이 달라지고 integer topology가 손상됨 | 저장 tensor 1,203개를 모두 검증하고 dtype 유지 |
| Sparse addition 순서 변경 | F32 pose-corrective와 skinning 결과가 달라짐 | `numpy.add.at`과 같은 source 순서로 누적 |
| 이미지 밖으로 나간 box clipping | Affine crop과 camera conditioning이 달라짐 | Box를 그대로 유지하고 외부 pixel을 black으로 채움 |
| 원본 host buffer 해제 후 byte 재사용 | MLX array가 유효하지 않은 storage를 참조할 수 있음 | Source buffer를 해제하기 전에 모든 tensor materialize |
| 공유 OBJ 경로 변경 | SAM 3D Objects export가 회귀할 수 있음 | Color를 optional로 만들고 기존 colored formatting branch 유지 |

## 2. 기술적 선택과 그 이유

### 2.1 공개 graph와 precision 유지

Loader는 body-only 경로가 사용하는 869개 array를 선택하기 전에 공개 schema 전체를 검증합니다. 유지된 model은 BF16 DINOv3 weight, F32 decoder 및 MHR weight, I32 topology를 그대로 사용합니다. Main body head에 필요한 coarse hand token과 hand PCA data는 유지하고, 별도 hand-refinement decoder와 사용하지 않는 buffer는 제외합니다.

Configuration은 이제 명시적인 512×512 image size를 요구합니다. 이 검사는 field가 없을 때 upstream dataclass의 오래된 512×384 기본값을 조용히 선택하는 문제를 막습니다. 512×512, patch size 16에서 backbone은 patch token 1,024개와 class token 1개, storage token 4개를 처리합니다.

### 2.2 누적 순서를 변경하지 않는 MHR 이식

MHR 경로는 F32를 유지하고 다음의 고정된 operation 순서를 따릅니다.

```text
decoder pose token
  -> 예측값 519개
  -> global/body/shape/scale/hand/face partition
  -> compact body 및 hand rotation
  -> model parameter 204개
  -> joint DOF 889개
  -> blend shape + pose corrective
  -> 127-joint forward kinematics
  -> sparse linear blend skinning
  -> vertex 18,439개, joint 127개, keypoint 70개
```

Sparse pose-corrective와 skinning contribution은 host에서 입력 순서대로 F32 누적합니다. Floating-point addition 순서가 upstream 결과의 일부이므로 parallel reduction으로 바꾸지 않았습니다.

### 2.3 공유 public output 계약 유지

`Mesh.vertex_colors`는 optional이 됩니다. Body mesh는 소수점 아래 6자리의 `v x y z`와 1-based triangle face를 기록합니다. SAM 3D Objects는 기존 colored `v x y z r g b` 경로와 유효 숫자 8자리 formatting을 계속 사용합니다.

Predictor는 기존 dense registry와 architecture registry를 통해 `body_mesh` task 하나를 제공합니다. 입력 option은 다음과 같습니다.

- `bbox`: source-pixel `[x1,y1,x2,y2]`, 생략 시 전체 이미지
- `cam_int`: row-major 3×3 flat array 또는 3개 값으로 된 row 3개, 생략 시 focal length `sqrt(width² + height²)`와 이미지 중심

일부가 이미지 밖에 있는 box는 변경하지 않고 black crop padding을 적용합니다. Nonfinite, degenerate, 완전히 교차하지 않는 box는 실패합니다.

## 3. 구현 상세

### 3.1 Model graph

새 `src/vision/dense/sam3d_body/` module은 공개 DINOv3-H+ backbone, learned axial RoPE, camera ray 및 Fourier feature, prompt embedding, decoder 6개 layer, MHR head와 body, preprocessing, 엄격한 checkpoint loading, public predictor를 포함합니다.

Backbone은 width 1,280인 block 32개, dimension 64인 head 20개, patch size 16, storage token 4개, SwiGLU, LayerScale를 사용합니다. Decoder layer는 upstream fast scaled-dot-product attention 경로와 fused biased linear 동작을 사용합니다. Final 이전의 각 decoder layer는 sampled image feature로 2D keypoint token을 갱신하고, 현재 body estimate에서 계산한 2D 및 3D positional embedding을 갱신합니다.

### 3.2 출력

Predictor는 다음 F32 tensor를 `result.safetensors`에 기록합니다.

| Key | Shape |
|---|---:|
| `vertices` | `[18439,3]` |
| `keypoints_3d` | `[70,3]` |
| `joint_coords` | `[127,3]` |
| `camera` | `[3]` |

`mesh.obj`는 colorless vertex 18,439개와 `head_pose.faces`에서 얻은 face 36,874개를 포함합니다. `meta.json`은 변경하지 않은 box, camera intrinsics, mesh span, coordinate convention, 설정된 image size, precision policy를 기록합니다. 공유 dense writer는 빈 `instances.json`도 생성합니다.

### 3.3 Loader hardening

최종 정적 검토 전에 구체적 지적 사항 3개를 수정했습니다.

1. 임시 byte buffer에서 만든 checkpoint array를 buffer 수명이 끝나기 전에 materialize합니다. Integer topology array도 같은 규칙을 적용합니다.
2. Body configuration은 crop size 누락 또는 공개 값과 다른 값을 거부하고 명시적 `[512,512]`만 허용합니다.
3. Dense `config.json`은 하나의 안정적인 regular-file handle로 읽고, 읽는 중 file이 커지는 경우까지 포함해 8 MiB 초과를 거부합니다.

수정 source의 보안 검토에서 세 지적 사항을 모두 닫았습니다. 독립 구현 검토에서도 공개 graph, preprocessing, decoder feedback, MHR reconstruction, writer, registry, CLI surface에 남은 정확성 또는 통합 문제가 발견되지 않았습니다.

## 4. Reference 및 검증 증거

### 4.1 인증된 upstream reference

완전한 upstream reference 2개가 child, wrapper, GPU guard exit code 0으로 성공했습니다.

| Case | 입력 정책 | Reference SHA-256 | 출력 |
|---|---|---|---|
| Boxed v4 | Box `[732,114,1523,1451]` | `677a8bd6b2bf7bbbe623cb38da9c2039df07355bfadd60e65cca4d3970903232` | Vertex 18,439개, keypoint 70개, joint 127개, camera, bbox, face 36,874개 |
| Default v1 | 전체 2250×1500 이미지 | `21fad47631033006dfd8e0ceaf0198fb4942b0390ac08dc0b721edbf6f17a0d9` | 같은 전체 schema |

모든 floating output은 finite입니다. Reference 실행은 native library SHA-256 `c1d8203b257364271e1ea6298705dd3bb0c82a7f06634f5578a209883601a9fc`, Python binding SHA-256 `f8ec0f363bc6eab1cda644a2579ae43aa663939f30ace531d5fb8cc33c7090cc`인 MLX 0.32.5를 사용했습니다. TF32는 비활성화했습니다. Generator는 body-only graph가 load한 checkpoint-backed array 958개의 shape, dtype, 전체 byte가 정확함을 증명했습니다.

수정하지 않은 public upstream loader는 공개 checkpoint에 포함된 미사용 buffer `parameter_limits`, `pmi`, `texcoord_faces`, `texcoords` 4개를 거부합니다. Reference 생성은 load 중 이 4개 항목만 제외하고 inference 전에 상속된 method를 복구하는 좁은 adapter를 사용했습니다. Preprocessing, forward operation, public `predict`, evaluation은 바꾸지 않았습니다. 이전의 pre-inference 실패 3개인 strict-loader 비호환, 불완전한 expected-key 목록, BF16 NumPy buffer 변환 문제는 성공 실행으로 바꾸지 않고 실패 증거로 보존했습니다.

### 4.3 인증된 Rust 및 CLI 인수

Boxed와 default Rust capture는 source revision `23d372286d5abdfe5944471858a48e8f1fa31182`와 integration binary SHA-256 `41c78473c3b25004aa1fe2c36b2581faa3c3b8c4699b02056303f4cba7bf623a`를 사용했습니다. 각 case에서 vertex 값 55,317개, keypoint 값 210개, joint 값 381개, camera 값 3개의 최대 절대 오차와 상대 L2 오차가 모두 `0`이었습니다. 두 mesh는 모두 vertex 18,439개와 face 36,874개를 가졌으며 face topology가 정확히 일치했습니다. 소수점 아래 6자리 OBJ serialization의 source tensor 대비 최대 차이는 boxed case에서 `4.99999523159711e-7`, default case에서 `4.999599456656512e-7`이었습니다.

Child, wrapper, GPU guard가 모두 exit 0이었고, default tensor 4개를 모두 정확히 재현했으며 face 36,874개도 정확히 일치했습니다.
