# PR #2818: 벤치마크 데이터에서 원시 로그 정리

**작성일**: 2026-11-01 (머지 전 작성)
**상태**: 리뷰 중
**언어**: Python, Bash, Markdown
**위험도**: 낮음 (런타임 코드 변경 없음, 삭제한 파일은 git 히스토리에 남음)

## 요약

`docs/benchmark_results`가 2,661개 파일, 18.5 MB에서 1,974개 파일, 14.0 MB로 줄었습니다. 인용되지 않은 원시 로그를 지우고, 실패한 break-even 시도 3개를 각각 `.7z` 하나로 묶었으며, 원시 로그가 다시 쌓이지 않도록 CI 검사를 추가했습니다.

## 1. 문제 정의

이 디렉터리는 저장소 추적 파일의 약 30%를 차지했습니다. `check_binary_assets.py`는 의도적으로 텍스트를 검사하지 않아서, 실행별 서버 로그, 빌드 로그, 빈 stderr 캡처를 제한하는 장치가 없었습니다. 비용은 clone 크기가 아니라 체크아웃과 검색의 노이즈입니다. 이 경로가 97 MiB pack에서 차지하는 양은 약 3 MiB입니다.

## 3. 기술적 선택과 그 이유

- **히스토리를 다시 쓰지 않음.** 약 3 MiB를 줄이려고 공유 저장소를 force-push할 이유가 없습니다.
- **압축본에서 서버 로그 제외.** 서버 로그를 넣으면 `attempt-3.7z`가 40 KB로 파일당 32 KB 제한을 넘고, 세 파일이 남은 바이너리 예산 94 KB를 거의 다 씁니다. 빼면 합계가 47 KB입니다.
- **실패한 시도의 메모는 평문으로 유지.** `attempt-2/`와 `attempt-3/summary-corrected.txt`를 가리키는 기존 인용이 그대로 동작합니다.
- **크기 제한 대신 허용 목록.** 텍스트 크기 제한은 무관한 파일에도 걸립니다. 허용 목록을 쓰면 새 로그마다 리뷰에서 판단할 수 있고, 낡은 항목은 실패로 처리됩니다.

## 5. 학습 포인트

근거 자료를 정리할 때 파일명 검색만으로는 부족합니다. `model-owned-storage/analyze.py`는 `server-*.log`를 glob으로 읽기 때문에 로그 60개가 인용되지 않은 것처럼 보였습니다. 스크립트의 쓰기뿐 아니라 읽기까지 확인한 뒤 복원했습니다.
