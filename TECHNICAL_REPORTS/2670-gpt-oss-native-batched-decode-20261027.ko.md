# 기술 보고서: PR #2670 — GPT-OSS 네이티브 배치 디코드

**작성일**: 2026-10-27
**상태**: 측정한 20B 체크포인트에 대해 완료
**위험도**: 중간

## 요약

GPT-OSS의 전체·슬라이딩 KV 캐시를 시퀀스별로 분리하고 디코드의 투영과 expert 계산을 배치화했다. 512 GB Apple M3 Ultra에서 `mlx-community/gpt-oss-20b-MXFP4-Q4`의 동시성 4 총 처리량은 110.1에서 209.0 tokens/s로 증가했다.

## 문제 정의

기존 래퍼는 새 요청을 받을 때 공유 캐시 벡터 하나를 초기화했다. 요청 간 덮어쓰기를 막기 위해 배치를 비활성화한 상태였다. 동시 실행에는 상태 분리, 순환된 슬라이딩 캐시 위치, 학습된 attention sink, 서버 메모리 계정 처리가 필요했다.

## 기술적 선택과 그 이유

`ModelOwnedSequenceState`가 요청별 캐시를 소유한다. B=1은 기존 계산 그래프와 지연 상태 생성을 유지하고, B>=2는 상태를 변경하기 전에 입력 모양과 시퀀스 ID를 검증한다. 여러 토큰이나 마스크가 있는 호출은 행별로 처리한다. 네이티브 디코드에서는 임베딩·정규화·투영·expert·출력 헤드를 배치화한다. 일반 attention 인터페이스에는 학습된 sink 인자가 없으므로 길이가 다른 KV에 대한 sink attention만 행별로 실행한다.

리뷰에서 중복·누락 ID의 원자적 거부와 페이지 저장소 동기화를 추가했다. 전체 캐시의 `live_len`, 슬라이딩 캐시의 `visible_len`을 페이지 계정에 반영하지 않으면 기본 paged 설정에서 동시 KV 사용량을 과소 계산할 수 있다. 패딩 prefill은 비활성 상태를 유지하며 분산 파이프라인·텐서 병렬 런타임은 변경하지 않았다.

## 검증 및 측정

서로 다른 프롬프트 길이, 순환 슬라이딩 창, YaRN, sink, 새 요청·초기화 격리, 정확한 B=1, 잘못된 입력의 원자적 거부, 페이지 저장소 길이를 포함한 모델·공유 상태·coverage·harness 테스트가 통과했다. 포맷, 범위를 제한한 clippy, 최종 배치 경로 검사 12개도 통과했다.

릴리스 빌드에는 `metal,accelerate`를 사용했다. 기준 커밋은 `a29a2692`, 측정 구현은 `dfd22beb`이며 이후 GPT-OSS 구현 변경 없이 rebase했다. `Hello`, 온도 0, 최대 128토큰 생성 결과는 바이트 단위로 동일했다. B=1 로짓 추적 256개 위치는 기록된 로짓 차이도 0으로 기준과 일치했다. B=4의 top-1 불일치는 8/256이었고 모두 기준 상위 두 토큰 차이가 0.25 이하였다. 확신도 높은 위치(gap >= 2)의 불일치는 0/96이었다. perplexity는 17.5500에서 17.5108로 변했다.

| 동시성 | 기준 총 tok/s | 네이티브 총 tok/s |
|---|---:|---:|
| 1 | 109.8 | 108.3 |
| 2 | 110.1 | 155.5 |
| 4 | 110.1 | 209.0 |

워밍업 후 B=1을 5회 반복한 디코드 중앙값은 136.1과 135.4 tok/s(-0.5%)였으며 관측 범위가 겹쳤다. 이번 측정에서 유의미한 단일 요청 성능 저하가 보이지 않았다는 근거이며, 처리량의 정확한 동일성을 보장하지는 않는다. 서버는 배치 제한 없이 `native batched forward`를 기록했다. 120B 체크포인트는 측정하지 않았다.

`--parallel 4` 서버에서 `scripts/bench_serving_concurrency.py --concurrency 1,2,4 --prompt-tokens 512 --max-tokens 128`로 재현할 수 있다. 로짓은 `MLXCEL_TRACE_BATCH_ROWS=1`과 `=4`에서 `examples/logit_trace MODEL docs/architecture.md 64 4 8 512`로 비교한다. 요약 측정값은 `docs/benchmark_results/data/native-batched-decode-m3ultra-2026-10-27/gpt-oss-20b.json`에 있다.

## 변경 요약

래퍼, sink attention 배치 경로, 모델 소유 ID 검증, 캐시 계정 훅, 테스트, 배치 경로 목록과 문서를 수정했다. 공통 harness는 스케줄러 소유 KV와 모델 소유 더미 캐시를 구분한다. 관련 이슈: #2568, #2574, #2555.
