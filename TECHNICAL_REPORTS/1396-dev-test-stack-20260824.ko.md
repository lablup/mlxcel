# 기술 보고서: PR #1396 - 개발 테스트 스레드 스택 확장

**작성일**: 2026-08-24

**작성자**: 신정규

**상태**: 완료

**언어**: Make, Python, Markdown

**위험도**: Low

## 요약

PR #1396은 mlxcel의 문서화된 Make 기반 개발 테스트 명령이 libtest의 기본 2 MiB 스레드 스택에서 큰 Qwen3.8 reasoning-effort fixture를 Minijinja로 렌더링할 때 중단되는 문제를 방지한다. 기본 프로필을 사용하는 세 대상은 이제 16 MiB `RUST_MIN_STACK`을 설정하며, CI-faithful `verify-test` 대상과 모든 Cargo 프로필 정의는 그대로 유지된다.

## 1. 문제 정의

`server::reasoning_effort_tests`는 8,952바이트 Qwen3.8 chat template을 반복 렌더링한다. 최적화하지 않은 Cargo 개발 프로필에서는 Minijinja의 native call frame이 libtest의 기본 테스트별 스레드 스택을 초과해 전체 테스트 바이너리를 SIGABRT로 종료할 수 있다. 최적화된 `test-fast`와 release 프로필에서는 같은 실패가 나타나지 않으므로 배포 바이너리나 문서화된 검증 프로필이 아니라 로컬 `make test`, `make test-verbose`, `make test-lib` 진입점이 영향을 받았다.

## 2. 변경 요약

| 영역 | 변경 |
|---|---|
| `Makefile` | 재정의 가능한 16 MiB 개발 테스트 스택을 선언하고 `test`, `test-verbose`, `test-lib`에만 설정 |
| `CONTRIBUTING.md` | 개발 프로필 한계, Make가 관리하는 동작, 직접 실행할 Cargo 명령을 설명 |
| 계약 테스트 | 기본 스택 값, 세 대상 recipe와 dry-run 확장, 변경되지 않은 정확한 `verify-test` 명령을 고정 |

## 3. 기술적 선택과 그 이유

### 3.1 지원되는 진입점에서 우회 적용

이슈는 개별 Rust 테스트를 별도 스레드로 감싸는 방법과 개발 프로필 제약을 문서화하면서 기존 Make 대상을 안전하게 만드는 방법을 모두 허용했다. 후자는 테스트 코드와 고정된 fixture를 건드리지 않고 해당 대상이 실행하는 모든 테스트를 보호하며, Cargo를 직접 사용하는 기여자에게는 명시적인 prefix를 제공한다.

### 3.2 검증 및 배포 프로필 보존

변경은 `[profile.dev]`, `[profile.test-fast]`, `[profile.release]`를 수정하지 않는다. `verify-test`도 정확히 `cargo test --workspace --profile test-fast --features metal,accelerate --no-fail-fast -- --test-threads=1`을 유지하므로 CI-faithful gate의 기존 성능과 수치 동작이 보존된다.

### 3.3 평가된 Make 동작 검증

회귀 테스트는 source recipe뿐 아니라 `make -n`이 출력한 명령도 확인한다. 따라서 source 문자열 검사만으로는 놓칠 수 있는 기본 스택 변수나 Make 확장 변경도 감지한다. subprocess는 shell 없이 인자 배열과 고정된 target 이름만 사용한다.

## 4. 검증

- `python3 -m unittest tests.test_makefile_dev_test_stack -v`: 4개 통과.
- `make -n test`, `make -n test-verbose`, `make -n test-lib`: 각 원래 Cargo 명령 앞에 `RUST_MIN_STACK=16777216`이 출력됨.
- `make -n verify-test`: stack override 없이 기존의 정확한 `test-fast` workspace 명령을 출력함.
- `RUST_MIN_STACK=16777216 cargo test --lib server::reasoning_effort_tests -- --test-threads=1`: 개발 프로필에서 세 차례 완료했으며 매번 19개 통과, SIGABRT 없음.
- `cargo fmt --all -- --check`: 통과.
- 최종 리뷰 code head의 Hosted CI: change detection, crate versions, kernel dtype keys, cross-repository references, CLA 통과. Rust source와 dependency metadata를 변경하지 않아 Rust 경로 job은 저장소 path filter 규칙에 따라 skip됨.
- 구현, 정확성, 보안/성능, finalization 리뷰는 dry-run 계약 커버리지를 추가한 뒤 미해결 문제를 발견하지 못함.

## 5. 남은 검증 경계

집중 개발 프로필 실행은 Metal 기능 없이 Linux에서 수행했다. 이 호스트에는 Apple Metal backend가 없으므로 요청된 Apple Silicon runtime 반복을 로컬에서 수행하지 못했으며 이를 통과로 주장하지 않는다. Issue #1384가 허용한 문서화와 Makefile 조합의 해결 경로는 Metal 의존 Rust 실행 경로를 변경하지 않는다.
