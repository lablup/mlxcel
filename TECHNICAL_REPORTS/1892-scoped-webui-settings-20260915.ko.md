# 기술 보고서: PR #1892 — 범위가 명확한 WebUI 설정

**날짜:** 2026-09-15

**상태:** 구현 리뷰와 CPU·모델 없는 실행·자동 브라우저 검증을 통과했습니다. 중앙 담당자의 격리된 실제 Settings 인수 검증도 통과했습니다. 유지보수자가 GPU 복구 근본 원인 조사를 명시적으로 연기했으므로 미확인 원인 자체를 WebUI 머지 차단 사유로 삼지 않으며, 실행하지 않은 기능 단언을 통과로 기록하지 않습니다.

**소스 체크포인트:** `8308a79fcc18e273cd2153f7fc6d01dc581e13f7` (`153d3c73` 검증 후 cfg만 수정한 체크포인트).

## 설계와 범위

이슈 #1846은 브라우저/개인정보, 요청 생성, 로드된 모델, 다음 로드, 재시작 전용 설정을 분리합니다. npm 배포 패키지 `@lablup/ui-common@0.1.0-alpha.19`의 기존 공통 컨트롤을 사용하며 패키지 소스를 복사하거나 별도 시각 체계를 만들지 않습니다. 네이티브 Field/textarea/modal은 기존에 문서화한 예외입니다. 요청 기본값은 메모리에만 유지하고 시스템 프롬프트는 대화가 소유하며, 명시적으로 저장한 안전한 로드 프로필만 브라우저 환경설정에 저장합니다.

실시간 설정은 인증된 공통 클라이언트를 통해 실제 선택 모델의 추론 식별자와 `autoload=false`로 기존 선택 활성화 `/settings` 스키마/현재 값/지문을 읽습니다. 서버 스키마에 숫자 min/max가 없으므로 범위 검증의 최종 권한은 서버에 있습니다. 사전 지문 비교는 관측된 외부 변경을 감지할 뿐 원자적 CAS가 아닙니다. 부분 PATCH 결과에서는 적용된 초안을 지우고 거부된 입력/오류를 유지한 뒤 실제 값을 다시 읽습니다. 결과가 불명확한 요청은 자동 재시도하지 않습니다.

## 로드 작업 구조

기존 정식 LoadProfile DTO를 좁은 어댑터로 이동했습니다. 제한된 컨텍스트, 병렬 수, 기존 KV 열거값만 허용하고 경로·자격 증명·argv·분산/워커 설정은 제외합니다. 명시적 CLI/환경변수 고정값, 작업 프로필, 프리셋/기본값 순으로 적용합니다. 시작 설정 복사본에 기존 시작 검증기와 모델 계열 KV 검증기를 적용하며 지원되지 않는 치환은 퇴거 전에 거부합니다. 이후 실제 설정은 재사용 템플릿이 아닌 로드된 AppState에서 읽습니다. 프로필은 멱등성 식별에 포함되며 해당 작업에만 적용되고 실행 중 워커나 이후 프로필 없는 로드를 변경하지 않습니다.

파일시스템 기반 프로필 해석은 코디네이터 수락 후 blocking pool에서 실행하고 기존 활성 작업 64개 제한을 따릅니다. Tokio 요청 실행기를 막지 않으면서 즉시 반환되는 정식 422 오류, 오래된 엔트리 검사, 명시적 퇴거 규칙을 유지합니다. 이 제한이 Tokio 자체 작업 큐까지 제한한다고 주장하지 않습니다.

## 소비자 경계와 리뷰 수정

Settings는 후속 Chat/Models가 사용할 `generation-defaults.ts`, 메모리 전용 `useGenerationDefaults()`, 버전이 있는 `useLoadProfile()`을 소유합니다. 모델별 프로필은 해당 모델의 재사용 프로필 전체를 대체합니다. 범위 편집/초기화는 선택 모델을 묵시적으로 변경하지 않고 표시된 범위에만 적용하도록 수정했습니다. `/props`에는 실제 슬롯별 컨텍스트, 설정 슬롯 수, 현재 KV 모드를 표시하고 0/누락된 컨텍스트는 알 수 없음으로 표시합니다. 선택적 원시 토큰 검사는 채팅 템플릿/기록/미디어를 제외하므로 전체 요청 수용을 보장하지 않습니다. 통합 KV는 별도 #1815 작업입니다.

독립 정확성 리뷰에서 범위별 초기화/표시, 실제 KV 표시 누락, 오래된 비동기 응답 문제를 수정했습니다. 독립 보안/성능 리뷰가 발견한 동기 메타데이터 I/O는 blocking pool로 옮긴 후 재검토를 통과했습니다. 공통 모달 언마운트 포커스 회귀 8건과 로그아웃/재로그인 후 늦게 도착한 수락/거부 결과 회귀 2건도 포함합니다. DOM 단위 테스트를 실제 브라우저 포커스 검증으로 간주하지 않습니다.

## 후속 인수 검증 수정

Settings 자체 모델 선택기는 공통 선택 액션을 사용하므로 후속 Models 페이지가 머지되기 전에도 준비된 모델의 props/실시간 설정에 접근할 수 있습니다. 모델 로드·언로드는 수행하지 않습니다.

`035cfe5b`의 최초 중앙 전체 실행에서는 실제 immutable 캐시 회귀가 발견됐습니다. Vite가 생성한 `index--ARMeYuQ.js`에서 마지막 하이픈으로 나누는 기존 방식이 유효한 base64url 해시의 첫 하이픈을 잃었습니다. 이제 모든 JS/청크/CSS 출력 해시를 8바이트로 고정하고, 서버는 `assets/` 내부에서 비어 있지 않은 기본 이름과 마지막 ASCII base64url 8바이트 바로 앞 구분자를 확인합니다. 앞·중간 하이픈과 밑줄, 잘못된 형식·비 ASCII·해시 없는 메타데이터를 포함한 제한된 CPU 에셋 테스트 13개가 통과했습니다. 해시 없는 에셋은 계속 `no-cache`이며 모든 에셋을 immutable로 바꾸지 않았습니다.

`64d4ba42`의 호스팅 브라우저 검증은 20개가 통과하고 강화된 준비 모델 Settings 2개가 실패했습니다. 이후 변경하지 않은 로컬 테스트도 실패했습니다. 실제 Chromium 추적에서 props 입력은 값 2048로 존재하고 실시간 설정도 존재했지만, 감싸는 label의 도움말이 접근 가능한 이름에 포함됐음이 확인됐습니다. props 누락·선택 유실·백엔드 전송 문제가 아니라 공통 Field 이름 결함입니다. 보이는 레이블 span의 명시적 ID와 입력의 `aria-labelledby`를 연결하고 네이티브 레이블 연결, 레이아웃, 도움말·오류의 `aria-describedby`는 유지했습니다. 기존 설치된 테스트 axe 엔진으로 계산한 이름 회귀 테스트가 수정 전 실패하고 수정 후 통과합니다. 의존성이나 브라우저 이름 단언은 변경하지 않았으며 독립 리뷰도 통과했습니다.

| CLI 우선순위, Llama | CLI 2048/1/fp16, 충돌 프로필 1024/2/int8 | 2048/1/fp16 유지, 세 필드 모두 `overridden_by_cli`에 표시 | `Hello.` |

혼합 실시간 PATCH는 `default_temperature=0.25`를 적용하고 `ctx_size=4096`은 거부했으며, 실행 중 컨텍스트 구성 변경 없이 반환값과 재조회한 현재 값이 일치했습니다. 명시적 언로드는 재로드 전에 워커 종료를 확인했습니다. 두 임시 서버 모두 종료 코드 0으로 정상 종료했고 강제 종료는 필요하지 않았습니다.

준비된 실제 Llama 모델의 1440/밝은 테마와 390/어두운 테마 브라우저 검증도 프로덕션 CSP 아래에서 통과했습니다. axe 위반 0개, 실제 props·실시간 컨트롤, 서버 상태를 변경하지 않는 브라우저 프로필 저장, 실제 PATCH, Escape·포커스, 화면 가로 넘침 없음, 비밀정보 영속 저장 없음이 확인됐습니다. 이는 앞선 픽스처 기반 21/22개 테스트와 구분되는 추가 프로덕션 검증입니다.

앞선 인수 검증 세 번은 제품 결함이 아닌 하네스 가정 때문에 실패했습니다. 외부 모델 디렉터리 심볼릭 링크는 기존 경로 제한 정책이 올바르게 거부했고, 비어 있지 않지만 언로드된 카탈로그는 `model_free`가 아닌 `router_pool`이며, `n_ctx`는 컨텍스트를 병렬 수로 나눈 값이 아니라 기존 state/props 권한을 따릅니다. 제품 정책을 완화하거나 런타임 코드를 변경하지 않고 기존 계약에 맞게 하네스를 교정했습니다. 실패 요약과 최종 기계 판독 결과는 실행 증거에 남기고 전체 요청 기록은 이 보고서에 공개하지 않습니다.

## 연기된 검사와 통합 상태

네이티브 Safari/VoiceOver와 실제 페이지 확대 200%는 최종 통합 수동 세션으로 연기했으며 통과나 면제로 기록하지 않습니다. 유지보수자가 연기한 GPU 복구 조사의 근본 원인은 미확인이며, 실제 Settings 검증 통과가 그 원인을 진단하거나 해결했다는 뜻은 아닙니다. CUDA 런타임 통과나 사용 불가 러너 면제도 주장하지 않습니다. 마지막 변경은 보고서만 추가하므로 검증된 소스와 번들은 그대로입니다. 중앙 오케스트레이터가 머지할 때까지 이슈/PR은 `status:review`를 유지합니다.
