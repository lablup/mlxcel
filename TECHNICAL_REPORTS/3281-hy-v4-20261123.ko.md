# 기술 보고서: PR #3281 - Hy4 (`hy_v4`) 지원 추가

**작성일**: 2026-11-23
**리뷰어**: -
**상태**: PR 오픈 (#2354 종료 예정). 실제 체크포인트로 검증 완료, 후속 작업은 7절 참고
**언어**: Rust, Python (트레이스 스크립트), Bash (검증 스크립트)
**위험도**: 낮음 (신규 모델 패밀리이며 DeepSeek-V3.2 forward 경로는 변경 없음)

---

## 요약

Tencent Hy4 (`model_type: hy_v4`, `mlx-community/Hy4-preview-4bit`)는 `Unsupported model type: hy_v4` 오류로 로드되지 않았습니다. 이 PR은 `deepseek_v32`의 자식 모듈로 Hy4를 추가합니다. V3.2의 MLA, DSA indexer, MoE 로더와 공용 `DsaRope`를 재사용하고, Hy4 고유 요소인 identity hyper-connection 잔차, 학습 가능한 attention sink를 가진 gated MLA, 레이어 간 공유 indexer를 새로 구현했습니다.

M3 Ultra (512 GB)에서 4비트 체크포인트는 59~61초에 로드되고, 상주 메모리 403.6 GB (최대 footprint 약 435.6 GB)를 차지하며, 14.3~14.5 tok/s로 디코딩합니다. mlx-vlm 대비 결정된 위치의 불일치는 125개 중 0개이고, indexer가 실제로 선택하는 4096 토큰 컨텍스트(`LONG=1`)에서는 55개 중 0개입니다. 서버는 `<think:opensource>...</think:opensource>`를 `reasoning_content`로 분리합니다. 도구 호출, `hy_v4_mtp` drafter, indexer가 선택하는 구간에서의 양자화 latent 트레이스는 후속 작업으로 남겼습니다.

---

## 1. 문제 정의

### 1.1 배경

이슈 #2354는 Hy4 지원을 요청합니다. 모델은 DeepSeek-V3.2 파생이며(absorbed `embed_q` / `unembed_out` MLA, DSA lightning indexer, noaux_tc MoE), 기존 패밀리 어디에도 함께 있지 않은 세 가지 변경이 있습니다.

### 1.2 기존 문제점

- **로더 없음**: `hy_v4`가 레지스트리와 감지 표에 없었습니다.
- **sink를 받는 MLA 없음**: V3.2 attention 커널은 attention sink를 받지 않으며, 출력에 헤드별 sigmoid 게이트가 필요합니다.
- **공유 indexer**: `indexer_types[i]`는 `full`(레이어가 indexer를 소유하고 indexer key를 latent 옆에 캐시) 또는 `shared`(indexer도, 캐시의 indexer key도 없고 가장 가까운 이전 `full` 레이어의 선택을 재사용)입니다. 캐시 레이아웃과 메모리 추정(`kv_arch`)이 레이어마다 다릅니다.
- **추론 태그**: 첫 서버 스모크 테스트에서 `<think:opensource>` 태그가 `content`에 그대로 반환됐습니다.

### 1.3 위험성

| 위험 | 영향 | 가능성 |
|------|------|--------|
| 합성 체크포인트 단위 테스트로는 보이지 않는 조용한 수치 드리프트 (RoPE 짝 구성, sink, gate, `swiglu_limit`) | 높음 | 중간 |
| 공용 V3.2 forward 변경으로 `deepseek_v32`가 깨짐 | 높음 | 낮음 (forward는 그대로이고 모듈 선언만 추가) |
| 433 GB 체크포인트가 메모리를 소진하거나 스왑 발생 | 중간 | 낮음 (스왑 관찰되지 않음) |
| 양자화 latent가 DSA indexer의 top-k 선택을 악화 | 중간 | Hy4에서는 미측정 |

## 2. 아키텍처

```
tokens -> embed -> h [B, L, hc_mult, hidden]
  블록마다:
    x   = hyper.collapse(h)            (pre 게이트)
    a   = gated sink MLA(norm(x))      (full 또는 shared indexer)
    h   = hyper.expand(h, a)           (post 게이트)
    x   = hyper.collapse(h)
    m   = MoE(norm(x))
    h   = hyper.expand(h, m)
  head: hyper head collapse -> norm -> lm_head
```

### 2.1 Identity hyper connection (`hy_v4_hyper.rs`)

블록 사이로 전달되는 잔차의 shape은 `[B, L, hc_mult, hidden]`입니다 (체크포인트의 `hc_mult`는 4). 각 서브레이어는 학습된 `pre` 게이트로 이를 접어 입력을 만들고, 출력은 학습된 `post` 게이트로 다시 펼쳐 더합니다.

```
x    = rms_norm(flatten(h), no weight) @ hc_fn.T      [B, L, 2 * hc]
pre  = sigmoid(x[..., :hc] * hc_scale[0] + hc_base[:hc]) + hc_eps
post = hc_magnitude * sigmoid(x[..., hc:] * hc_scale[1] + hc_base[hc:])
in   = sum(pre[..., None] * h, axis = hc)
h'   = h + post[..., None] * out[:, :, None, :]
```

DeepSeek-V4 hyper connection에서 `comb` 출력을 뺀 형태입니다. 스트림끼리 섞지 않으므로 Sinkhorn 단계가 없고, `hc_fn`은 `(2 + hc) * hc`행이 아니라 `2 * hc`행입니다. `deepseek_v4_hyper.rs`는 shape 검사가 이 텐서를 거부하므로 재사용할 수 없습니다. 연산은 잔차의 f32 복사본 위에서 float32로 수행하고, 접은 입력과 펼친 잔차만 원래 dtype으로 되돌립니다. `hc_*` 텐서는 float32로 제공되며 float32로 유지합니다. transformers 참조 구현은 `post`에도 `hc_eps`를 더하지만 mlx-vlm은 더하지 않으며, 이 구현은 mlx-vlm을 따릅니다 (크기 1 안팎의 게이트에 대해 1e-6 항).

### 2.2 Sink를 가진 gated MLA (`hy_v4_attention.rs`)

attention forward는 Hy4 전용입니다. 모든 단계에서 MLX SDPA를 sink와 함께 실행한 뒤, 헤드별 출력에 `sigmoid(linear_gate(x))`를 곱합니다. MLA 투영(`embed_q`, `unembed_out`, latent norm)은 `deepseek_v32`의 것을 씁니다.

### 2.3 공유 indexer 레이어

- `full` 레이어는 lightning indexer를 실행하고, `[kv_latent | indexer key]`를 캐시하며, top-k를 공개합니다.
- `shared` 레이어는 latent만 캐시하고 공개된 선택에 attention합니다. 디코드에서는 gather, 프리필에서는 sparse mask를 쓰고, `kv_len <= index_topk`인 동안은 dense로 대체합니다.

`kv_arch`는 `full` 레이어에서만 indexer key 크기를 계산하므로 메모리 추정이 캐시와 일치합니다.

### 2.4 MoE (`hy_v4_moe.rs`)

float32로 점수를 계산하는 noaux_tc 라우팅 후, 적층된 `switch_mlp.{gate,up,down}_proj` 전문가에 `swiglu_limit` clamp를 라우팅 전문가에 적용합니다. 라우팅과 `SwitchGLU` forward는 V3.2 것을 매개변수화하지 않고 여기서 다시 작성했습니다 (3.8 참고).

### 2.5 `deepseek_v32` 및 `DsaRope`와의 조합

`hy_v4`는 `deepseek_v32`의 자식 모듈로 선언되어, 가시성을 넓히지 않고도 비공개 MLA, indexer, MoE 구성요소와 로더에 접근합니다. `deepseek_v32.rs`의 변경은 모듈 선언뿐이므로 V3.2 전후 트레이스 비교는 필요하지 않았습니다. RoPE는 공용 `DsaRope`를 씁니다. 범위는 mlx-community affine 변환본이며, 원본 mxfp8 `tencent/Hy4-preview` 레이아웃(`kv_b_proj`, 융합된 `gate_up_proj`)은 거부합니다.

로더는 `hc_*` shape이 `hc_mult * hidden_size`와 맞지 않는 경우, `indexer_types`의 길이나 값이 잘못된 경우, indexer 가중치가 `indexer_types`와 맞지 않는 경우 메시지와 함께 실패합니다.

## 3. 기술적 선택과 그 이유

### 3.1 Interleaved RoPE

**컨텍스트:** mlx-vlm은 interleaved 짝을 회전하고(V3.2 attention에서 물려받은 `traditional=True`), transformers 참조 구현은 half-split 짝을 회전합니다. 첫 커밋은 mlx-vlm을 따랐고, 실제 체크포인트 실행 전까지 열린 문제로 남겼습니다.

**고려한 대안:**

| 옵션 | 실제 체크포인트 결과 |
|------|----------------------|
| Half-split (transformers) | 256개 위치 평균 NLL 3.9121 |
| **선택: interleaved (mlx-vlm)** | 256개 위치 평균 NLL 2.1995 |

**선택 이유:** 같은 토큰이 interleaved 짝에서 훨씬 높은 확률을 받으므로 체크포인트는 그 방식으로 학습된 것입니다. 비교를 다시 돌릴 수 있도록 `MLXCEL_HY4_ARM`의 `rope_half_split` arm을 남겼습니다.

### 3.2 라우팅 전문가에 `swiglu_limit` 적용

체크포인트 설정의 `swiglu_limit`은 10.0입니다. transformers는 라우팅 전문가를 이 값으로 clamp하고 mlx-vlm은 아무것도 적용하지 않습니다. 학습된 모델의 일부이므로 라우팅 전문가에만 적용했습니다. `no_swiglu_limit` arm이 mlx-vlm 동작을 재현합니다. 두 arm은 결정된 모든 위치에서 일치하며(각 0/125), mlx-vlm 대비 perplexity는 limit 없는 arm이 +0.47%, 출시 모델이 +0.53%입니다.

### 3.3 `lm_head`는 fp32로 실행하지 않음

transformers는 `enable_lm_head_fp32`를 설정합니다. MLX 체크포인트의 `lm_head`는 bf16 scale을 가진 4비트이고 mlx-vlm은 활성화 dtype으로 실행하며, 이 구현도 같습니다. 양자화된 head를 f32로 캐스팅해도 양자화 때 잃은 정밀도는 돌아오지 않습니다.

### 3.4 양자화 latent

| 옵션 | 장점 | 단점 |
|------|------|------|
| `hy_v4`를 `QUANTIZED_LATENT_FAMILIES`에 추가 (`auto`가 int8 선택) | 기본 캐시가 작아짐 | indexer가 선택하는 구간에서 입증되지 않음 |
| **선택: 제외하고 명시적 `--mla-latent-quant int8\|int4`만 허용** | `deepseek_v32`와 같은 입장, 사용자가 선택 가능 | 옵트인 전용, 실험적 표기 |

**선택 이유:** 결정된 위치 게이트는 통과하지만(아래), 두 latent 트레이스 모두 512 토큰까지만 돌았고 이 구간에서는 `kv_len <= index_topk`라 양자화 슬롯 위에서 indexer top-k 중첩이 검증되지 않았습니다. 이것이 DeepSeek-V3.2가 놓친 게이트입니다 (#3163). `auto`는 fp16을 유지합니다. 명시적 옵션이 동작하도록 `hy_v4`는 latent-pair 및 DSA key 패밀리에 포함되며, CLI는 측정값이 담긴 실험적 안내를 출력합니다.

### 3.5 행별 배치 디코드 fallback

Hy4의 sink, hyper 잔차, 공유 선택 전달을 받는 배치 커널이 없습니다. 배치 디코드는 행별 fallback을 쓰며, 올바르지만 네이티브 배치보다 느립니다. `HyV4Model`은 `batched_decode_coverage_tests.rs`의 `EXPECTED_PER_ROW_FALLBACK`에 올라 있습니다.

### 3.6 추론 태그

서버는 K2-Horizon과 같은 다섯 위치에 `<think:opensource>` / `</think:opensource>`를 등록해 `reasoning_content`를 `content`에서 분리합니다. 구분자는 ASCII 표 항목이고, `<think:opensource>`는 `<think>`와 접두사 충돌이 없으며, Hy4 토크나이저에는 thinking-budget 조회에서 이 쌍을 가릴 `<think>` 토큰이 없습니다.

### 3.7 Parity arm

`MLXCEL_HY4_ARM`은 `no_sinks`, `no_gate`, `no_swiglu_limit`, `rope_half_split`을 선택합니다. 실패해야 하는 arm은 트레이스가 해당 기능을 볼 수 있음을 증명하고, 통과해야 하는 arm은 어떤 결정이 결정된 위치에서는 보이지 않음을 보여줍니다. UTF-8이 아닌 값은 이제 미설정으로 읽지 않고 오류를 냅니다.

### 3.8 다시 작성한 MoE

`hy_v4_moe.rs`는 V3.2 `MoEGate` 라우팅과 `SwitchGLU` forward를 f32 라우팅과 clamp를 넣어 다시 작성했습니다. V3.2 forward를 바이트 단위로 동일하게 유지하는 대신 코드가 중복되며, 이후 리팩터링 대상으로 기록한 의도적 절충입니다.

## 4. 검증

M3 Ultra, 512 GB, `iogpu.wired_limit_mb` 491520, `mlx-community/Hy4-preview-4bit`.

### 4.1 메모리와 속도

| 실행 | 최대 footprint | 비고 |
|------|----------------|------|
| `generate -p "Hello" -n 50` | 434.1 GB | 상주 403.6 GB, 세 번 실행에서 14.26~14.48 tok/s |
| `mlxcel-server` | 434.2 GB | `/v1/chat/completions`가 200 반환, 40 토큰 |
| Logit 트레이스 | 최대 435.6 GB | 어떤 실행에서도 스왑 없음 |

로드는 59~61초 걸립니다. generate 스모크는 일관된 텍스트를 반환합니다. 서버의 첫 응답은 `content`에 추론 태그 원문을 담고 있었고, 이것이 3.6의 태그 분리로 이어졌습니다.

### 4.2 mlx-vlm 대비 logit 일치도

결정된 위치는 참조의 상위 두 logit 격차가 2 이상인 위치입니다. 게이트는 결정된 위치의 불일치 수입니다.

| Arm | 결정된 위치 불일치 | 참조 대비 perplexity |
|-----|--------------------|----------------------|
| 출시 모델 | 0 / 125 | +0.53% (전체 top-1은 256개 중 1개, 격차 0.06) |
| `no_swiglu_limit` | 0 / 125 | +0.47% |
| 출시 모델, `LONG=1` (4096 토큰, indexer 선택) | 0 / 55 | -0.99% |
| `no_swiglu_limit`, `LONG=1` | 0 / 55 | -1.01% |
| `no_sinks` (실패해야 함) | 78 / 125 | perplexity 7528 |
| `no_gate` (실패해야 함) | 124 / 125 | perplexity 1.6e6 |

실패해야 하는 두 arm이 실제로 실패하므로, 트레이스는 sink와 gate에 민감합니다.

### 4.3 양자화 latent 대 fp16 latent

| Latent | 결정된 위치 불일치 | Top-1 일치율 | Perplexity |
|--------|--------------------|--------------|------------|
| int8 | 0 / 124 | 98.0% | +1.00% |
| int4 | 0 / 124 | 95.7% | +0.68% |

둘 다 일관된 텍스트를 생성하며 `effective int8; applied to 78 of 78 layers`를 보고합니다. 둘 다 indexer가 아무것도 선택하지 않는 512 토큰에서 실행했습니다.

### 4.4 테스트

합성 체크포인트 단위 테스트는 shared 레이어 선택과 캐시 레이아웃, hyper connection 수식, sink 의미, parity arm, 프리필과 디코드 일치, int8/int4 latent, bf16 안정성, 기본 RoPE, 추론 분리를 다룹니다. 리뷰에서는 `hy_v4` 셀렉터(39개 테스트), `coverage_tests`, latent-option, `kv_arch`, DSA resolver 테스트, `-D warnings` clippy, `cargo fmt --check`, `scripts/ci` 계약 검사를 실행했습니다. 이 보고서를 위해 모델이나 테스트를 실행하지는 않았습니다.

## 5. 리뷰 반영 사항

| 발견 | 심각도 | 상태 |
|------|--------|------|
| `scripts/validate_hy_v4.sh` 서버 단계: `set -e` 아래에서 `curl -sf` 실패 시 RETURN trap 없이 종료되어 433 GB 체크포인트를 올린 `mlxcel-server`가 남았고, 이 단계는 `GPU_LOCK`도 잡지 않음 | 높음 | be0cfb31에서 수정: 락 아래에서 실행하고 EXIT trap이 서버를 중지. stub 서버로 재현 확인 |
| `hc_mult >= 1`을 상한 없이 허용, `as i32`와 `2 * hc_mult * hidden_size`가 오버플로 가능 | 중간 | 13088414에서 수정: `MAX_HC_MULT`는 64이고 곱이 i32에 들어가는지 검사 |
| `eos_token_id`를 i64에서 `as i32`로 잘라냄 | 낮음 | 13088414에서 수정: 범위 밖 및 음수 id 거부 |
| UTF-8이 아닌 `MLXCEL_HY4_ARM`을 미설정으로 읽음 | 낮음 | 13088414에서 수정: 오류 처리 |
| int8 latent 안내가 Hy4를 언급하지 않는 DeepSeek-V3.2 벤치마크 파일을 인용 | 낮음 | 수정: 이 PR(#3281)을 인용 |
| 서버 스모크가 모델 디렉터리 이름을 이스케이프 없이 JSON에 삽입 | 낮음 | 미해결 (운영자가 제어) |
| 디코드가 레이어 호출마다 sink를 다시 캐스팅하고 eps 스칼라를 다시 만듦 | 낮음 | 미해결 (attention에 비해 작음) |
