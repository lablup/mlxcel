# PR #2549: Add Shared DINOv2 Feature Encoder

**Date**: 2026-10-23

**Status**: Local validation complete (PR open; final CI gate pending)

**Languages**: Rust, Python, Markdown

**Risk**: Medium

## Executive Summary

PR #2549 adds a reusable DINOv2 vision backbone for standard and register-token Hugging Face checkpoints and exposes standalone image feature extraction through `mlxcel predict`. It implements checkpoint conversion, positional interpolation, mask handling, normalized intermediate features, the giant preset's SwiGLU path, checkpoint-driven preprocessing, and three output tensors: `last_hidden_state`, `pooler_output`, and `hidden_patch_tokens`.

The final source passed formatting-aware clippy, eight repository contract targets, 13 focused tests with genuine CPU f32 checkpoint references, and guarded ROCm CLI runs for both supported checkpoint layouts on gfx1151. Independent implementation and security/performance reviews have no remaining findings. GitHub CI had no reported failures at this report cut, but three central compile/lint jobs were still queued, so merge readiness remains subject to that gate.

## 1. Problem Statement

Video Depth Anything, MoGe-3, and SAM 3D Objects depend on a DINOv2 transformer, but mlxcel had no reusable implementation. Porting a private transformer into each dense model would duplicate checkpoint conversion, positional interpolation, token handling, and numerical validation. Public DINOv2 checkpoints also needed a standalone feature path that does not pass through text generation or object detection.

The implementation had to support both public checkpoint layouts, exclude register tokens from spatial output, reproduce both upstream positional interpolation modes, and preserve the Hugging Face image processor contract. Incorrect resize rounding, convolution layout conversion, mask dtype, or token slicing changes every downstream feature and can silently invalidate dependent model ports.

## 3. Technical Decisions

### 3.1 One reusable backbone for dense consumers

`Dinov2` owns the checkpoint-compatible transformer, while `Dinov2Encoder` adds resize, ImageNet normalization, selected intermediate layers, and spatial grid reshaping for dense models. Public `Attention` and `Mlp` types let SAM 3D Objects reuse the same verified primitives. Scoped construction copies only a named DINOv2 subtree, leaving the parent weight map available for sibling heads.

### 3.2 Preserve upstream token and interpolation contracts

The sequence order is class token, optional register tokens, then patch tokens. Position embeddings apply to class and patches before registers are inserted, matching Hugging Face. `forward_features` retains all tokens, `pooler_output` uses the normalized class token, and spatial outputs exclude both class and registers. Position interpolation supports the explicit-size antialias mode used by Hugging Face checkpoints and the legacy scale-factor offset mode used by dense consumers.

### 3.3 Match the slow Hugging Face processor at the byte boundary

The standalone predictor uses checkpoint processor settings instead of assuming patch-aligned input. Its bicubic path reproduces Pillow's fixed-point coefficient and uint8 rounding behavior before rescaling and normalization. This choice was verified against output from the actual slow processor.

### 3.4 Validate checkpoint dimensions before allocation

Configuration and public layer APIs reject invalid or excessive hidden sizes, layer counts, patch grids, register counts, image sizes, and intermediate requests. Attention uses the shared safe dispatch; `Attention::forward` rejects invalid input shapes, while the public attention and MLP constructors validate dimensions and checkpoint weights. These checks keep malformed checkpoint metadata from creating oversized host buffers or MLX graphs.

### 3.5 Commit complete reference tensors

The two safetensors fixtures contain normalized NHWC input and all three expected output tensors rather than sparse probes. Each fixture records its public model ID, immutable checkpoint revision, library versions, dtype, device, and input convention. Future consumers therefore have a stable end-to-end CPU oracle at the issue's relative RMS tolerance of `1e-3`.

## 4. Architecture and Data Flow

```text
source image
    -> checkpoint BitImageProcessor policy
    -> f32 NHWC pixels
    -> patch convolution + class/register/mask token handling
    -> DINOv2 blocks with LayerScale
    -> final LayerNorm
    -> last_hidden_state
       + normalized class pooler_output
       + register-free hidden_patch_tokens
```

Dense consumers can instead provide `[0,1]` NHWC images and a requested token grid to `Dinov2Encoder`. That path performs antialiased bilinear resizing, ImageNet normalization, selected normalized intermediate layers, and reshaping of patch tokens into NHWC feature grids.

## 6. Limits

The full public giant checkpoint was not executed. Giant preset values and SwiGLU remapping/sanitizer behavior have unit coverage, but this report makes no genuine giant forward, real-weight parity, or memory claim. Metal runtime parity, DINO training/classification heads, `/v1/embeddings`, and the RF-DETR windowed variant remain outside this PR. No throughput benchmark was performed.

## 7. Learning Points

- A shared backbone should expose both full-sequence and spatial-only views because register tokens are valid transformer context but are not image-grid locations.
- Image processor parity includes integer resize behavior before normalization; matching only the floating-point network does not establish end-to-end parity.
- Scoped checkpoint loading lets composite dense models reuse a backbone without consuming or renaming unrelated head weights.
- Full-tensor fixtures reveal systematic drift that sparse probes can miss and preserve enough metadata to reproduce the oracle later.
