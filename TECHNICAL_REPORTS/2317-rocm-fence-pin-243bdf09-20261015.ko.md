# 기술 보고서: PR #2317 - fix(rocm): update Fence::wait and Fence::update signatures for MLX 243bdf09

**작성일**: 2026-10-15
**상태**: 완료
**언어**: C++
**위험도**: 낮음

---

## 요약

PR #2304의 MLX `243bdf09` 핀 업그레이드에서 변경된 업스트림 `mlx/fence.h` 시그니처에 맞춰 `src/lib/mlxcelverse/overlays/rocm/mlx/backend/rocm/fence.cpp`를 갱신합니다. `Fence::wait`가 목표 카운터 값인 `uint32_t value`를 인자로 받아 `fence->event.wait(value)`를 호출하도록 하고 `Fence::update`가 `fence->count`(`uint32_t`)를 반환하도록 수정하여 ROCm 빌드 및 `make verify-rocm` 전체 게이트(`12,384 passed, 0 failed`)를 복구했습니다.

---

## 1. 문제 정의

### 1.1 배경

PR #2304(`9bfabbab`)는 HIP 툴체인이 없는 호스트에서 MLX 핀을 `59d600b5`에서 `243bdf09`로 업그레이드했습니다. 업스트림 MLX `243bdf09`의 `mlx/fence.h`는 소비자 스트림이 최신 카운터가 아닌 입력 배열 평가 시점의 카운터 값을 대기하도록 `Fence::update`의 반환형을 `uint32_t`로, `Fence::wait`의 시그니처를 `(Stream stream, const array& x, uint32_t value)`로 변경했습니다.

### 1.2 기존 문제점

- **ROCm 컴파일 실패**: `mlx/backend/rocm/fence.cpp`가 이전 시그니처(`void Fence::wait(Stream s, const array&)`, `void Fence::update(Stream s, const array&, bool cross_device)`)를 유지하고 있어 `cargo build --features rocm` 실행 시 `error: no declaration matches` 컴파일 오류가 발생했습니다.

---

## 2. 구현 상세

- **`src/lib/mlxcelverse/overlays/rocm/mlx/backend/rocm/fence.cpp`**:
  - `Fence::wait(Stream s, const array&, uint32_t value)`가 `fence->event.wait(value)`를 대기하도록 수정하고, #1804의 GPU 스트림 오류 감지 및 `rocm::describe_device_error` 예외 전파를 그대로 유지했습니다.
  - `Fence::update(Stream s, const array&, bool cross_device)`가 `uint32_t`(`fence->count`)를 반환하도록 수정했습니다.
- **`src/lib/mlxcelverse/overlays/rocm/LOCAL_FIXES.md`**:
  - 48번 항목(`Retarget compatibility at 243bdf09`)에 `mlx/backend/rocm/fence.cpp` 변경 내역을 기록했습니다.
