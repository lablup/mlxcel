# PR #2517: 간헐적 mllama exact-zero assert와 webui 라우터 레이스 수정

**작성일**: 2026-10-21
**상태**: 완료
**위험도**: Low
**언어**: Rust (테스트), TypeScript (테스트)

---

## 요약

이슈 #2467의 간헐적 테스트 실패 두 가지를 테스트 코드만으로 수정했다. mllama 패리티 테스트의 exact-zero assert는 형제 비교가 이미 쓰던 문서화된 1e-6 재연합 허용오차를 사용하고, WebUI 라우터 하니스는 리프레시 클릭 후 세션 키 프롬프트가 5초 안에 마운트된다고 가정하는 대신 401 카탈로그 응답 자체를 기다린다. Item-2 근본 원인은 테스트 측 타이밍 가정이다: 클릭의 강제 스냅샷이 다음 2초 폴 틱으로 미뤄져 401이 CPU 부하 하에서 5초 창 밖에 착지할 수 있었다. DOM 신호는 한 번도 늦지 않았고, 제품 코드는 변경되지 않았다. 하니스는 CPU 부하 7회를 포함해 연속 20회 통과.

## 1. 문제 정의

### 1.1 배경

두 개의 플레이키 테스트가 체인-impl 런 동안 로컬 게이트를 막았다 (mllama는 PR #2507 브랜치에서 3회, main 컨트롤 런에서 3회 실패). 이슈 #2467은 #1067의 선례(같은 1-ulp 감소 순서 클래스)에서 제기되었다.

### 1.2 기존 문제점

- **Item 1**: `tests/mllama_parity.rs`의 `ragged_multi_image_states_concatenate_real_rows`는 `max_abs_diff == 0.0`을 assert했지만 병렬 감소가 합을 재연합하는 지점에서 main에서 1.1920929e-7 (1 ulp)로 한 번 실패했다. 6회 재실행은 통과.
- **Item 2**: `webui/tests/router-real.harness.ts`의 `injectRealUnauthorizedCatalog`는 원샷 401 라우트를 장착하고 refresh를 클릭한 뒤 세션 키 필드를 5초 기다렸는데, 간헐적으로 타임아웃했다.

### 1.3 위험성

| 위험 | 영향 | 가능성 |

| CI 동결 중 플레이키 테스트가 로컬 게이트 신뢰를 침식 | Medium | High (반복 관찰) |

## 3. 기술적 선택과 그 이유

### 3.1 Item 2 근본 원인: 늦은 DOM이 아니라 지연된 스냅샷

**컨텍스트:** 5초 DOM 대기가 간헐적으로 만료.

**선택:** 계측된 런(페이지 수준 요청/응답 트레이스)으로 근본 원인 규명. `WebUiSynchronizer.refresh()` (webui/src/state/sync.ts:162)는 관찰 틱이 이미 진행 중이면 조기 반환해서 "Refresh server state" 클릭이 `needsFullSnapshot`만 설정하고 강제 전체 스냅샷을 다음 2초 폴 틱(`visiblePollMs`, 39행)으로 미룬다. 원샷 라우트는 그 이후 틱의 카탈로그 GET까지 장착 상태로 남아 401이 (진행 중 틱 잔여 + 최대 2초 + 부트스트랩 지연) 후에 착지하고, CPU 부하 하에서 5초 창을 넘을 수 있다. 트레이스는 클릭이 부트스트랩 GET 2 ms 후 착지(클릭 시점 틱 진행 중)하고 401-프롬프트 지연이 약 22 ms임을 보인다.

**수정:** "401 처리됨"을 의미하는 신호를 기다린다: 원샷 라우트를 장착하기 전에 (상태 401, 동일 origin, 카탈로그 pathname) 술어로 `page.waitForResponse`를 등록하고, 클릭, `await`, 세션 키 가시성 assert 순. 타임아웃 상승이 아님.

### 3.2 Item 1: 새 상수가 아니라 재사용

`TILE_SELECTION_REASSOCIATION_TOL` (1e-6, #1067) 재사용. doc 주석이 이제 파일 안 두 비교를 모두 명명. 계보는 `src/models/mllama/text.rs`의 #953 `RAGGED_REASSOCIATION_TOL`과 일치.
