# PR #3413: Mamba1 및 Falcon-Mamba 선택적 스캔

**날짜**: 2026-11-25

**상태**: 통합 소스 CUDA 검증 통과, 통합 전 정확한 소스 SHA에서 ROCm 검증 통과

## 요약

이 PR은 Mamba1과 Falcon-Mamba 모델을 OpenXLA/IREE에서 네이티브로 실행하도록 지원합니다. 설정 파싱, 체크포인트 검증, 가중치 순서, f32 순환 상태, 청크 한정 프리필, 배치 디코드, 독립 Transformers 참조값, 등록된 전체 모델 디코드 골든을 함께 추가합니다.

프리필 믹서는 128행 청크 안에서만 순환 피연산자를 만들고, 각 청크에는 로그 깊이의 아핀 접두 스캔을 적용합니다. 따라서 4096토큰 그래프에서도 완전한 `[4096, d_inner, state_size]` 텐서를 만들지 않으며, 레이어별 전달 상태는 `[d_inner, state_size]`로 유지됩니다.

## 문제 정의

기존 순환 경로는 Mamba2의 그룹 상태 공간 구조를 지원했지만, Mamba1은 서로 다른 대각 순환식을 사용합니다. 각 채널은 고유한 감쇠, 입력 투영, 스킵 매개변수를 가지며 B와 C는 토큰마다 달라집니다. 합성곱 이력과 순환 상태는 프리필과 배치 디코드 모두에서 보존되어야 합니다. Falcon-Mamba는 B, C, dt 투영에 가중치 없는 RMS 정규화도 적용합니다.

행을 하나씩 펼치는 StableHLO 구현은 프롬프트 용량에 비례해 그래프 깊이와 연결 연산 수가 증가합니다. 또한 모든 순환 피연산자를 먼저 만든 뒤 청크로 자르면 4096토큰, 1536채널, 상태 크기 16 모델에서 완전한 `[T,D,N]` 값이 그래프에 남습니다.

## 변경 요약

설정 계층은 Hugging Face 필드와 기존 state-spaces 별칭을 모두 사용해 `mamba`와 `falcon_mamba`를 인식합니다. 표준 `use_bias`와 `use_conv_bias`는 `bias`와 `conv_bias`보다 우선합니다. 지원하지 않는 LayerNorm 설정은 거부하며, 실제로 사용하는 블록 및 믹서 엡실론은 유한한 양수여야 합니다.

이미터에는 Mamba1 체크포인트 이름, 텐서 형상, 상태 할당, 합성곱 상태 전달, 프리필, 디코드를 추가했습니다. 주변 값이 다른 자료형이어도 순환식은 f32로 계산합니다. 공유 순환 ABI는 통합 베이스의 Mamba2와 Nemotron-H 기능인 압축 KV 인덱스, 그룹 정규화, 하이브리드 레이어 일정, MoE 설정과 호환됩니다.

Python 오라클과 Rust 모델 검사 하네스는 공식 Mamba 체크포인트와 시드가 고정된 합성 Falcon-Mamba 모델을 검증합니다. 작은 등록 픽스처는 전체 모델 Mamba 디코드를 실행하고 StableHLO 바이트를 고정합니다.

## 기술적 선택

### 아핀 순환 쌍을 로그 깊이로 합성

각 스텝을 `h_t = a_t * h_(t-1) + u_t`를 나타내는 `(a_t, u_t)`로 표현합니다. 포괄 스캔은 간격을 두 배씩 늘리면서 `(a_r * a_l, u_r + a_r * u_l)`로 쌍을 합성합니다. 순환 순서를 유지하면서 각 한정 블록을 선형 체인에서 로그 깊이로 낮춥니다.

### 믹서 청크 루프 안에서 순환 피연산자 생성

모델 전용 프리필 경로는 먼저 `x`, `dt`, B, C를 한 청크로 자릅니다. 그 뒤에만 브로드캐스트와 곱셈으로 `log_a`와 `bx [chunk,D,N]`를 만듭니다. 범용 스캔은 이 한정된 값만 받습니다. 완전한 텐서를 만든 뒤 자르는 방식이 아니라 이 생산자 경계가 용량 크기의 `[T,D,N]` 할당을 방지합니다.

### 순환 상태와 민감한 계산을 f32로 유지

감쇠, 아핀 합성, 상태 전달, B/C/dt 정규화, 리드아웃 누적은 f32를 사용합니다. 전달 상태 형상은 `[layers,d_inner,state_size]`이고 합성곱 이력은 별도로 저장되므로, 분할 프리필과 단일 토큰 디코드는 전체 프리필과 같은 수치 계약을 따릅니다.

### 지원하지 않는 설정을 조기에 거부

`rms_norm = false`, SiLU가 아닌 활성화, 잘못된 차원, 유한한 양수가 아닌 활성 엡실론은 그래프 생성 전에 거부합니다. 이전 bias 별칭은 허용하되 표준 키를 덮어쓸 수 없습니다.

## 검증

통합 실행 소스는 병합된 PR #3411을 베이스로 한 `abd1520fd669624cb668bd558b98e332d0955093`입니다. `cargo test -p mlxcel-xla --lib -- --test-threads=4`에서 555개가 통과하고 21개가 무시되었습니다. Mamba1, Mamba2, Nemotron-H 등록 골든의 바이트 일치 검사도 통과했습니다. 포맷 검사와 `-D warnings`를 사용한 집중 clippy가 통과했습니다. 환경 변수 문서 검사기는 발견한 396개 중 265개 문서화, 131개 허용 목록으로 통과했고 Python 테스트 15개도 모두 통과했습니다.

NVIDIA GB10에서 정확한 통합 소스의 용량 4096 CUDA 프로브는 `gpu-lock` 아래에서 5.03초에 컴파일되고 0.319초에 실행되었습니다. 프로세스 최대 RSS는 203200 KiB였습니다. 독립 CPU 오라클 대비 최대 절대 오차는 출력 `3.651e-7`, 최종 순환 상태 `1.141e-8`, 합성곱 상태 `1.371e-6`이었습니다. 시간 로그는 `/tmp/epic564-plan/3348-cuda-cap4096-integrated-abd1520f-time.log`, 결과 묶음은 `/tmp/issue3348-cap4096-integrated-abd1520f`에 있습니다. 이는 정확성과 컴파일 자원 관찰이며 처리량 주장에 해당하지 않습니다.

구조적 용량 프로브는 4096토큰 그래프에 `[4096,D,N]` 텐서가 없음을 확인했습니다. StableHLO는 3,116행, 320 KiB였으며 직접 CPU 컴파일은 최대 RSS 228.2 MiB에서 10.64초, 실행은 0.862초가 걸렸습니다.

IREE local-task에서 공식 `state-spaces/mamba-130m-hf` 리비전 `1e76775f628fbf1350fbe4dbb3d971ba64af25a1`은 전체 프리필, 분할 프리필, 디코드 모두에서 독립 Transformers 5.12.1 CPU fp32 참조와 일치했습니다. 최악의 최대 절대 오차는 `1.488e-4`였고 argmax가 같았습니다. 시드가 고정된 합성 `FalconMambaForCausalLM`은 B/C/dt RMS 정규화를 포함했으며 전체, 분할, 디코드에서 최악의 최대 절대 오차 `3.725e-7`과 같은 argmax를 기록했습니다.

ROCm gfx1151 검증은 정확한 소스 `3a1688f7daaf9bae8bea09997b804e6509357c25`에서 수행되었습니다. 라이브러리 테스트 551개 통과 및 21개 무시, local-task/HIP 믹서 프로브 12개 경우, 실제 Mamba와 합성 Falcon의 참조 및 CLI 40/40 토큰 일치, B4/N8 배치, 취소, 슬롯 재활용, 동시 서버 요청 4개, 용량 4096 컴파일, 하이브리드 테스트 5개, Mamba2 회귀, 실제 Nemotron-H 통합 검증이 통과했습니다. 모든 ROCm 장치 작업은 ROCm 가드를 사용했습니다. HTTP API는 토큰 ID를 노출하지 않으므로 렌더링된 텍스트를 비교했으며, 최적화된 `test-fast` 바이너리는 성능 주장의 근거로 사용하지 않았습니다. [ROCm 검증 기록](https://github.com/lablup/mlxcel/pull/3413#issuecomment-7147199610)에 명령과 원시 증거 출처가 있습니다.

ROCm 실행 이후 브랜치를 PR #3411 위로 리베이스했습니다. Mamba1 스캔, 파서, 순환 이미터, Python 오라클 blob은 `3a1688f7`과 바이트 단위로 같습니다. 통합으로 추가된 것은 분리된 Nemotron-H MoE 경로와 CI 허용 목록 수정입니다. 통합 소스에서 CUDA, 전체 라이브러리 테스트, 등록 골든을 다시 실행했습니다. ROCm은 이 수치 소스 중립 통합 후 다시 실행하지 않았으므로 두 정확한 SHA의 증거 경계를 명시적으로 구분합니다.

## 학습 사항

소비자만 청크로 제한해서는 생산자가 이미 용량 크기 텐서를 만든 경우를 막을 수 없습니다. 토큰 투영을 순환 피연산자로 브로드캐스트하기 전부터 안전 경계를 적용해야 합니다.

순환 모델 검증에는 수치 참조와 상태 전이 검증이 모두 필요합니다. 전체 프리필 일치만으로는 잘못 전달된 합성곱 꼬리, 재활용 슬롯의 오래된 상태, 분할 프리필과 디코드의 차이를 탐지할 수 없습니다.
