# PR #3392: Inkling 2 네이티브 배치 디코드와 패딩 프리필

**날짜**: 2026-11-24
**상태**: Draft PR 오픈 (#3377 종료). 좁은 범위의 테스트 통과, M3 Ultra(512 GB)에서 `models/inkling-2-mini`와 `models/inkling-2-mini-4bit`로 검증.

## 요약

Inkling 2는 B > 1을 행마다 별도 포워드로 처리했기 때문에 동시 요청에서 배치 이득이 없었고, 패딩 프리필도 거절했습니다. 이 PR은 모든 행을 한 번의 포워드로 처리하고, 서버가 콜드 프롬프트 묶음을 한 번의 패딩 패스로 프리필할 수 있게 합니다. 동시 요청 8개에서 서버 총 처리량은 네이티브 체크포인트 25.9에서 62.7 tok/s로, 4-bit 버전 30.3에서 62.7 tok/s로 늘었습니다. B = 1은 main과 바이트 단위로 같고, B = 4와 B = 8은 결정된(decided) 트레이스 위치 전부에서 B = 1과 일치합니다.

## 1. 문제

`batched_decode_kind()`가 `PerRowFallback`을 반환했습니다. `forward_batched_with_ids`가 행을 잘라 `forward_with_sequence_id`를 부르므로 디코드 비용이 배치 크기에 비례해 늘었습니다. Mini의 48개 레이어 방문마다 시퀀스별 `InklingLayerCache`(시간순 KV 캐시와 f32 컨볼루션 히스토리 4개)가 있고, 히스토리 길이가 행마다 달라 그대로 쌓을 수 없습니다.

| 위험 | 영향 | 대응 |
|---|---|---|
| 길이가 다른 행 상태를 한 텐서로 합침 | 짧은 행의 문맥 오류 | 왼쪽 패딩으로 쌓음. 패딩은 컨볼루션이 읽는 `kernel - 1`행에 닿지 않음 |
| 행별 trim이 정확하지 않게 됨 | 추측 디코딩 롤백이나 패딩 제거가 행을 망가뜨림 | 각 행은 단일 행 포워드가 남길 히스토리를 정확히 돌려받음 |
| B = 1 출력이나 커널 변경 | 단일 요청 사용자 회귀 | 한 행은 단일 시퀀스 그래프 유지 |
| 실제 위치가 패딩을 읽음 | 잘못된 프리필 | 오른쪽 패딩, 인과적 마스크와 컨볼루션, 정확한 행별 trim |

## 2. 설계

### 2.1 배치 포워드 (`src/models/inkling2/batched.rs`)

`forward_rows`는 `with_batched_sequence_states`로 행 상태를 열고(콜드 프리필 행은 새 캐시를 만듦) 행마다 캐시 세트 하나로 기존 hidden 패스를 실행합니다. 프로젝션, 짧은 컨볼루션 4개, 어텐션 residual 혼합, Mini의 메시지 뱅크와 컨트롤러, 전문가와 헤드는 `[B, L]`을 처리합니다. 어텐션 코어(행 오프셋별 log scaling, KV 추가, 슬라이딩 trim, banded 상대 위치 마스크, sink 열, SDPA)는 #2673 이후의 Inkling 1처럼 행마다 실행합니다. `Inkling2Attention::forward`를 배치 부분과 `attend`로 나눴습니다.

`with_stacked_state`가 컨볼루션 슬롯 하나를 처리합니다. 행이 하나면 상태를 그대로 넘깁니다. 여러 행이면 짧은 히스토리 앞에 0 행을 붙여 `[B, R_max, C]`로 쌓고, 컨볼루션 후 행 `i`는 쌓인 다음 히스토리의 최신 `min(kernel - 1 + margin, R_i + L)`행을 가져갑니다. 이는 단일 행 포워드가 남기는 행과 같습니다. 모든 히스토리가 최소 `kernel - 1`행을 가지므로 패딩은 읽히지 않습니다.

### 2.2 바뀌지 않은 경로

`route_batched_decode_with_ids`가 한 행을 `forward_with_sequence_id`로 보내므로 B = 1은 기존 그래프를 실행합니다. #3369 게이트는 그대로입니다. 짧은 컨볼루션 커널은 계속 4행까지 받고(배치 히스토리를 stride로 읽음), head preparation과 grouped experts는 `B == 1`이라 B > 4는 ops 컨볼루션을 씁니다. DSpark verify 포워드가 부르는 `hidden_with_captures`는 같은 패스의 한 행 래퍼가 되었습니다.

### 2.3 패딩 프리필

스케줄러는 묶음을 오른쪽 패딩하고 각 행의 패딩을 `trim_state`로 제거합니다. Inkling 2의 마스크와 컨볼루션은 모두 인과적이라 실제 위치는 패딩을 읽지 않고, 슬라이딩 KV 여유분은 포워드 길이까지의 trim을 이미 감당합니다. 컨볼루션 히스토리는 추측 verify 밖에서는 여분 16행만 남기므로, 토큰 둘 이상의 배치 포워드는 `conv::WideHistoryScope`에 들어가 추가한 행 수만큼 남깁니다. `supports_batched_prefill`과 `supports_padded_prefill`은 `Inkling2VlModel`을 통해서도 true입니다. 넓어진 히스토리는 묶음 포워드부터 다음 디코드 스텝이 줄일 때까지 유지됩니다.

## 3. 검증

| 항목 | 결과 |
|---|---|
| 작은 모델, B = 3 디코드, 3/12/30 토큰 행, 한 행 trim, 한 행 이탈 | 단일 행 디코드와 2e-4 이내로 일치 (관측 3e-5, f32) |
| 작은 모델, 48로 오른쪽 패딩한 묶음 (패딩 43/25/8) | 마지막 행 로짓, KV, 컨볼루션 꼬리, 이후 4 디코드 스텝이 패딩 없는 프리필과 일치 |
| 변이 시험: 쌓인 히스토리의 반대쪽에 패딩 | 두 테스트 모두 실패 (차이 약 3) |
| B = 1 트레이스, main 대 PR | 두 체크포인트 모두 바이트 동일 |
| B = 1 대 B = 4 / B = 8 트레이스 | 네이티브 top-1 2/256, 3/256, decided 0/98; 4-bit 7/256, decided 0/98; 불일치 최대 gap 0.19 |
| 128 토큰 그리디 | 두 체크포인트 모두 main과 PR 동일 |

서버 처리량, ABAB, 501 토큰 프롬프트, 128 토큰, `--parallel 8`, 총 tok/s (2회 평균):

| 체크포인트 | C1 main / PR | C4 main / PR | C8 main / PR |
|---|---|---|---|
| inkling-2-mini | 26.5 / 26.5 | 26.6 / 48.6 | 26.0 / 62.6 |
| inkling-2-mini-4bit | 30.7 / 30.7 | 30.9 / 50.6 | 30.3 / 62.9 |

C8에서 첫 토큰까지 시간은 배치 프리필 묶음 덕분에 약 4.2초에서 3.6초(네이티브)로 줄었습니다. 테스트 선택자: `--lib inkling` (168), `--lib coverage_tests` (18), `--lib prefill_cohort` (23), `--lib pad_trim` (4).

## 4. 한계와 후속 작업

- temperature 0의 자유 생성 동시 요청은 단독 요청 답과 바이트 단위로 같지 않습니다. 47~238자 뒤 근소한 동점에서 갈라지며, `--max-batch-prefill 1`에서도 같은 위치에서 갈라지므로 원인은 배치 디코드 연산(B행 행렬곱)이고, 트레이스가 측정하는 범주입니다.
- 어텐션 코어는 여전히 행마다 한 번 실행됩니다. 프로파일에서 문제가 되면 행별 마스크를 쓰는 왼쪽 패딩 배치 SDPA로 이 루프를 없앨 수 있습니다.
- Inkling 2 Small은 여기서 측정하지 않았습니다(#3373). 경로는 루프만 없을 뿐 같습니다.
