# PR #3252: PLaMo 2.1 VL (`plamo2vl`) port

**Date**: 2026-11-23
**Status**: PR open (draft), closes #1380; verified on M3 Ultra against mlx-vlm 0.6.8 on the 4-bit conversion

## Executive Summary

PLaMo 2.1 VL (`pfnet/plamo-2.1-2b-vl`, `pfnet/plamo-2.1-8b-vl`) is Preferred Networks' Japanese/English vision-language model: a SigLIP-so400m tower over dynamic image tiles, an MLP adapter, and the PLaMo 2 hybrid Mamba + attention decoder. This PR adds it to the CLI (`--image`) and the server (`image_url` parts). The decoder is the existing `Plamo2Model`; the new code is the tower wiring, the adapter, the Eagle2-style tiler, the prompt template, tokenizer support for the image ids, and a loader that accepts both the HF export and the mlx-vlm conversion layouts.

On `plamo-2.1-2b-vl-mlx-4bit` the port matched mlx-vlm 0.6.8 in prompt token counts and greedy answers. The text-only `plamo-2-1b` output is byte-identical to origin/main.

## 1. Architecture of the Port

| Area | Change |
|---|---|
| Tower | `SigLipVisionModel` (384 px, patch 14, 27 layers, tanh GELU, no CLS). Runs once over all tiles; the post-layernorm output `[tiles, 729, 1152]` is used as is. The attention-pooling `head.*` is dropped at load. |
| Adapter | `Plamo2VlImageProjector`: `RMSNorm(weight + 1) -> + bias0 -> Linear -> + bias1 -> erf GELU -> Linear -> + bias2`. `linear1` has no bias of its own; `linear1` and `linear2` may be quantized. |
| Decoder | `Plamo2Model` with RoPE bases read from the VL text config (`rope_theta`, `rope_local_theta`, `full_attention_idx`) and the tied head handled for a quantized embedding. Every `LanguageModel` hook on `Plamo2VlModel` delegates to it. |
| Merge | Projected rows are scattered in order onto the `<plamo:image>` (100002) positions with `merge_llava`. |
| Tokenizer | The image ids 100000..100015 exist only in `tokenizer_config.json` / `added_tokens.json`; the PLaMo tokenizer appends config-declared ids past its 100000-row `tokenizer.jsonl`. Generation never samples the three image ids (`output_suppressed_token_ids`). |
| Processor | `Plamo2VlProcessor`: port of the checkpoint's `_dynamic_preprocess_eagle2`. See 2.2. |
| Prompt | The checkpoint ships no chat template. mlxcel carries the fixed Japanese instruction template (`以下はタスクを説明する指示で...` / `### 指示:` / `### 応答:`) on CLI and server and frames each image as `<siglip2:img> + <plamo:image> * (729 * tiles) + </siglip2:img>`. |
| Loader | `normalize_plamo2_vl_weight_keys` maps both layouts to one form. HF: `model.*`, `image_proj.biasN._bias`, a tied `lm_head.weight`. mlx-vlm: `language_model.model.*` with a quantized tied embedding, `image_proj.biasN.bias`. On a quantized checkpoint the bf16 tower and adapter are cast to f16 on Apple Silicon; the text model's tensors are left as the text loader sees them. |
| Wiring | `ModelType::Plamo2VLM`, detection, registry, `LoadedModel`, VLM runtime and its preparation summary, memory estimate, tensor-parallel family map, server chat template. |

## 2. Technical Decisions and Departures

### 2.1 BOS only when the tokenizer config says so

`<|plamo:bos|>` (id 1) leads the prompt only when `tokenizer_config.json` sets `add_bos_token`. `PlamoTokenizer.__init__` defaults the key to false; the HF export sets it true and the mlx-vlm conversions drop it. Each checkpoint therefore gets the prompt its own processor builds, which is why the 4-bit conversion yields 767 tokens for a 512x512 image and the bf16 export 768. Id 1 is also the stop id (the text config carries no `eos_token_id`; the top-level one is inherited).

### 2.2 Tiling is the ratio-factor rule, not InternVL's

Candidate grids are visited in ascending tile count. The grid maximizing `min(ar, cols/rows) / max(ar, cols/rows)` wins, and on a tie the larger grid wins only when the image covers more than half of it. The image is resized bicubically to the grid and cropped row-major, with a full-image thumbnail when more than one crop exists. A context budget starts at 24 tiles and shrinks (by 2, by 1 below 3) until `sum(2 + 729 * tiles) < 3072`, so one image ends at 1 to 4 tiles. The issue text predicted a 2x1 grid plus a thumbnail for 1000x300; the reference rules give 3x1 plus a thumbnail, 4 tiles, and the tests pin the reference value.

### 2.3 Full KV cache instead of sliding-window attention

The upstream model uses sliding-window layers. This port keeps the full KV cache that `Plamo2Model` already uses. It costs memory on very long prompts only; one image is at most 2954 tokens. Windowed caches are left out of this PR.

### 2.4 `supports_batching` delegated

`Plamo2VlModel` returns whatever the text model reports for `supports_batching`, `batched_decode_kind`, the sequence-state layout and the snapshot hooks, so the VL model never claims a capability the mixed Mamba / KV state does not have. `last_row_logits` is implemented (the #3090 coverage test requires it).

### 2.5 Hardening added during finalization

- The loader refuses a processor whose `num_image_token()` differs from the tower's rows per tile `(image_size / patch_size)^2`. `get_input_embeddings` takes the prompt's placeholder count and returns an error when the projected feature rows differ, comparing array shapes only (no host sync).
- `preprocess_with_tiles` reads sizes with `DynamicImage::dimensions()` and converts one image to RGB at a time inside the tiling loop, instead of materializing every RGB copy first.
- `Plamo2VlProcessor::new` returns a `Result`: `downsample_ratio` must be finite and in (0, 1], `size.width` positive, and the stride math is checked, so `patch_size * (1 / ratio)` cannot overflow and NaN cannot zero `num_image_token`. `tile_budget` uses saturating arithmetic.
- The loader checks the configured `image_proj_hidden_size` against `image_proj.linear1.weight` dimension 0, which is the output width for plain and packed quantized weights alike, and fails with both numbers in the message.

Behavior on the shipped checkpoints is unchanged (ratio 1.0, 729 tokens per tile, hidden size 2048).

## 3. Verification

M3 Ultra, 512 GB. Reference: mlx-vlm 0.6.8 on the same 4-bit checkpoint, greedy.

| Case (`plamo-2.1-2b-vl-mlx-4bit`) | Tiles | Prompt tokens | mlxcel answer | mlx-vlm |
|---|---|---|---|---|
| solid red 512x512, "この画像の色は何色ですか。" | 1 | 767 | 赤 | same tokens, same answer |
| `tests/fixtures/test_image.png`, "Describe this image." | 1 | 765 | "The orange background is highlighted." | same tokens, same answer |
| solid blue 1000x300 | 4 | 2954 | 青 | same tokens, same answer |
| solid green 1920x1080 | 3 | 2225 | 緑 | not run |

- Server `/v1/chat/completions` with an `image_url` part returned 赤 (767 tokens) and 青 (2954 tokens).
- bf16 `plamo-2.1-2b-vl` loads through the HF key layout, answers 赤, and its prompt is 768 tokens, matching the HF processor's 768.
- `plamo-2-1b` (text only): greedy output byte-identical to origin/main.
- Unit tests cover the tiler grids and budgets, the prompt builder, the normalizer for both layouts, the adapter against a hand computation, the tokenizer's added ids, the chat template, detection, and the hardening checks (`downsample_ratio` rejection, saturating budget, hidden-size mismatch, feature-row mismatch). The `last_row_logits` and batched-decode coverage tests pass.

## 4. Unverified and Open Items

- **bf16 generation parity against transformers.** Not done. The HF model needs the CUDA-only `causal_conv1d`, and mlx-vlm 0.6.8 needs transformers 5, which cannot import the checkpoint's remote code. The bf16 evidence is the loaded answer and the prompt-token match.
- **Solid green 1920x1080** was not run through mlx-vlm.
- **`downsample_ratio` other than 1** is rejected at load rather than supported; no shipped checkpoint uses it.
- **Sliding-window attention** is not applied (2.3).
