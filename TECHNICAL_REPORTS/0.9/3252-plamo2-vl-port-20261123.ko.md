# PR #3252: PLaMo 2.1 VL (`plamo2vl`) 포팅

**날짜**: 2026-11-23
**상태**: PR 열림 (draft), #1380 종료 예정. M3 Ultra에서 4비트 변환본을 mlx-vlm 0.6.8과 비교해 검증함

## 요약

PLaMo 2.1 VL(`pfnet/plamo-2.1-2b-vl`, `pfnet/plamo-2.1-8b-vl`)은 Preferred Networks의 일본어/영어 비전-언어 모델입니다. 동적 이미지 타일 위에서 동작하는 SigLIP-so400m 타워, MLP 어댑터, PLaMo 2 하이브리드 Mamba + attention 디코더로 구성됩니다. 이 PR은 CLI(`--image`)와 서버(`image_url` 파트)에 이 모델을 추가합니다. 디코더는 기존 `Plamo2Model`을 그대로 쓰고, 새로 추가한 코드는 타워 연결, 어댑터, Eagle2 방식 타일러, 프롬프트 템플릿, 이미지 id를 위한 토크나이저 지원, 그리고 HF 원본과 mlx-vlm 변환본의 키 배치를 모두 받아들이는 로더입니다.

`plamo-2.1-2b-vl-mlx-4bit`에서 프롬프트 토큰 수와 greedy 답변이 mlx-vlm 0.6.8과 일치했습니다. 텍스트 전용 `plamo-2-1b`의 출력은 origin/main과 바이트 단위로 동일합니다.

## 1. 포팅 구조

| 영역 | 변경 |
|---|---|
| 타워 | `SigLipVisionModel`(384 px, patch 14, 27층, tanh GELU, CLS 없음). 모든 타일에 대해 한 번 실행하며, post-layernorm 출력 `[tiles, 729, 1152]`을 그대로 사용합니다. attention-pooling `head.*`는 로드 시 버립니다. |
| 어댑터 | `Plamo2VlImageProjector`: `RMSNorm(weight + 1) -> + bias0 -> Linear -> + bias1 -> erf GELU -> Linear -> + bias2`. `linear1`은 자체 bias가 없고, `linear1`/`linear2`는 양자화될 수 있습니다. |
| 디코더 | VL 텍스트 설정(`rope_theta`, `rope_local_theta`, `full_attention_idx`)에서 RoPE base를 읽는 `Plamo2Model`. 양자화된 임베딩의 tied head도 처리합니다. `Plamo2VlModel`의 모든 `LanguageModel` 훅은 이 모델로 위임합니다. |
| 병합 | 투영된 행을 `merge_llava`로 `<plamo:image>`(100002) 위치에 순서대로 흩뿌립니다. |
| 토크나이저 | 이미지 id 100000..100015는 `tokenizer_config.json` / `added_tokens.json`에만 있습니다. PLaMo 토크나이저는 100000행짜리 `tokenizer.jsonl` 뒤에 설정에 선언된 id를 덧붙입니다. 세 개의 이미지 id는 생성 중 샘플링되지 않습니다(`output_suppressed_token_ids`). |
| 프로세서 | `Plamo2VlProcessor`: 체크포인트의 `_dynamic_preprocess_eagle2` 포팅. 2.2절 참고. |
| 프롬프트 | 체크포인트는 채팅 템플릿을 제공하지 않습니다. mlxcel이 CLI와 서버 모두에서 고정된 일본어 지시 템플릿(`以下はタスクを説明する指示で...` / `### 指示:` / `### 応答:`)을 사용하고, 각 이미지를 `<siglip2:img> + <plamo:image> * (729 * tiles) + </siglip2:img>`로 감쌉니다. |
| 로더 | `normalize_plamo2_vl_weight_keys`가 두 배치를 하나로 맞춥니다. HF: `model.*`, `image_proj.biasN._bias`, tied `lm_head.weight`. mlx-vlm: 양자화된 tied 임베딩을 가진 `language_model.model.*`, `image_proj.biasN.bias`. 양자화 체크포인트에서는 Apple Silicon에서 bf16 타워와 어댑터를 f16으로 변환하며, 텍스트 모델 텐서는 텍스트 로더가 보는 그대로 둡니다. |
| 연결 | `ModelType::Plamo2VLM`, 감지, 레지스트리, `LoadedModel`, VLM 런타임과 준비 요약, 메모리 추정, 텐서 병렬 패밀리 매핑, 서버 채팅 템플릿. |

## 2. 기술적 결정과 차이점

### 2.1 토크나이저 설정이 요구할 때만 BOS 추가

`<|plamo:bos|>`(id 1)는 `tokenizer_config.json`이 `add_bos_token`을 설정한 경우에만 프롬프트 앞에 붙습니다. `PlamoTokenizer.__init__`은 이 키의 기본값을 false로 두고, HF 원본은 true로 설정하며, mlx-vlm 변환본은 키를 버립니다. 따라서 각 체크포인트는 자신의 프로세서가 만드는 프롬프트를 받습니다. 512x512 이미지에서 4비트 변환본이 767토큰, bf16 원본이 768토큰인 이유입니다. id 1은 종료 id이기도 합니다(텍스트 설정에 `eos_token_id`가 없어 최상위 값을 상속합니다).

### 2.2 타일링은 InternVL이 아닌 비율 계수 규칙

후보 그리드는 타일 수 오름차순으로 순회합니다. `min(ar, cols/rows) / max(ar, cols/rows)`를 최대화하는 그리드가 선택되며, 동률이면 이미지가 그리드 면적의 절반을 넘게 채울 때만 더 큰 그리드가 선택됩니다. 이미지는 bicubic으로 그리드 크기에 맞춰 리사이즈한 뒤 행 우선으로 자르고, 크롭이 둘 이상이면 전체 이미지 썸네일을 추가합니다. 컨텍스트 예산은 24타일에서 시작해 `sum(2 + 729 * tiles) < 3072`가 될 때까지(2씩, 3 미만에서는 1씩) 줄어들므로 이미지 한 장은 1~4타일이 됩니다. 이슈 본문은 1000x300에 대해 2x1 그리드와 썸네일을 예측했지만, 참조 규칙은 3x1과 썸네일(4타일)을 내며 테스트는 참조 값을 고정합니다.

### 2.3 슬라이딩 윈도우 대신 전체 KV 캐시

원본 모델은 슬라이딩 윈도우 레이어를 씁니다. 이 포팅은 `Plamo2Model`이 이미 쓰는 전체 KV 캐시를 유지합니다. 비용은 매우 긴 프롬프트의 메모리뿐이며, 이미지 한 장은 최대 2954토큰입니다. 윈도우 캐시는 이 PR에서 제외했습니다.

### 2.4 `supports_batching` 위임

`Plamo2VlModel`은 `supports_batching`, `batched_decode_kind`, 시퀀스 상태 레이아웃, 스냅샷 훅을 텍스트 모델의 값 그대로 반환하므로, Mamba/KV 혼합 상태가 지원하지 않는 기능을 VL 모델이 주장하지 않습니다. `last_row_logits`는 구현되어 있습니다(#3090 커버리지 테스트 요구 사항).

### 2.5 마무리 단계에서 추가한 보강

- 로더는 프로세서의 `num_image_token()`이 타워의 타일당 행 수 `(image_size / patch_size)^2`와 다르면 로드를 거부합니다. `get_input_embeddings`는 프롬프트의 플레이스홀더 수를 받아, 투영된 특징 행 수가 다르면 오류를 반환합니다. 배열 shape만 비교하므로 호스트 동기화가 없습니다.
- `preprocess_with_tiles`는 `DynamicImage::dimensions()`로 크기를 읽고, 모든 RGB 사본을 먼저 만들지 않고 타일링 루프 안에서 이미지를 하나씩 RGB로 변환합니다.
- `Plamo2VlProcessor::new`는 `Result`를 반환합니다. `downsample_ratio`는 유한하고 (0, 1] 범위여야 하고 `size.width`는 양수여야 하며 stride 계산은 검사됩니다. 따라서 `patch_size * (1 / ratio)`가 오버플로하거나 NaN이 `num_image_token`을 0으로 만들 수 없습니다. `tile_budget`은 포화 산술을 씁니다.
- 로더는 설정의 `image_proj_hidden_size`를 `image_proj.linear1.weight`의 0번 차원(일반/패킹 양자화 가중치 모두에서 출력 폭)과 비교하고, 불일치하면 두 값을 담은 메시지로 실패합니다.

배포된 체크포인트(ratio 1.0, 타일당 729토큰, hidden size 2048)의 동작은 바뀌지 않습니다.

## 3. 검증

M3 Ultra, 512 GB. 기준: 같은 4비트 체크포인트에서 greedy로 돌린 mlx-vlm 0.6.8.

| 경우 (`plamo-2.1-2b-vl-mlx-4bit`) | 타일 | 프롬프트 토큰 | mlxcel 답변 | mlx-vlm |
|---|---|---|---|---|
| 단색 빨강 512x512, "この画像の色は何色ですか。" | 1 | 767 | 赤 | 토큰, 답변 동일 |
| `tests/fixtures/test_image.png`, "Describe this image." | 1 | 765 | "The orange background is highlighted." | 토큰, 답변 동일 |
| 단색 파랑 1000x300 | 4 | 2954 | 青 | 토큰, 답변 동일 |
| 단색 초록 1920x1080 | 3 | 2225 | 緑 | 실행 안 함 |

- 서버 `/v1/chat/completions`에 `image_url` 파트를 보내 赤(767토큰)과 青(2954토큰)을 받았습니다.
- bf16 `plamo-2.1-2b-vl`은 HF 키 배치로 로드되어 赤로 답하며, 프롬프트는 768토큰으로 HF 프로세서의 768과 일치합니다.
- `plamo-2-1b`(텍스트 전용): greedy 출력이 origin/main과 바이트 단위로 동일합니다.
- 단위 테스트는 타일러 그리드와 예산, 프롬프트 빌더, 두 배치의 정규화, 어댑터(수계산 대조), 토크나이저 추가 id, 채팅 템플릿, 감지, 그리고 보강 검사(`downsample_ratio` 거부, 포화 예산, hidden size 불일치, 특징 행 불일치)를 다룹니다. `last_row_logits`와 배치 디코드 커버리지 테스트도 통과합니다.

## 4. 미검증 및 미해결 항목

- **transformers 대비 bf16 생성 패리티.** 수행하지 못했습니다. HF 모델은 CUDA 전용 `causal_conv1d`가 필요하고, mlx-vlm 0.6.8은 transformers 5가 필요한데 이 버전은 체크포인트의 원격 코드를 import하지 못합니다. bf16 근거는 로드 후 답변과 프롬프트 토큰 일치입니다.
- **단색 초록 1920x1080**은 mlx-vlm으로 실행하지 않았습니다.
- **`downsample_ratio`가 1이 아닌 경우**는 지원하지 않고 로드 시 거부합니다. 배포된 체크포인트는 사용하지 않습니다.
- **슬라이딩 윈도우 attention**은 적용하지 않았습니다(2.3).
