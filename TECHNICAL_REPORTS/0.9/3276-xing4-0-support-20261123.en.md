# PR #3276: Add Xing4.0 (xing4_0) support

**Date**: 2026-11-23
**Status**: Draft PR (closes #2356). Unit suites pass; real checkpoints verified on an M3 Ultra for `xing4.0-29b-a4b-mlx-8bit` (parity gate) and `xing4.0-29b-a4b-optiq-4bit`, with a before/after trace on `moonlight-16b-a3b-instruct-4bit` for the shared DeepSeek-V3 code

## Executive Summary

Xing4.0 is a 29B-total, 4B-active MoE whose decoder is DeepSeek-V3 (MLA attention, `noaux_tc` sigmoid routing over 64 experts top-4 plus one shared expert, YaRN RoPE), wrapped in a manifold hyper-connection residual stream of width `hc_mult = 4`. mlx-vlm implements it (`mlx_vlm/models/xing4_0`); mlx-lm does not. This PR ports it into `src/models/xing4_0.rs` by composing the existing `deepseek_v3` attention, MoE and sanitize, and adds only the hyper connection, the stream bookkeeping and the head.

Three gaps surfaced on the way, and each is closed here. `DeepSeekV3Attention` ignored YaRN entirely, so Xing gets an opt-in frequency table that leaves every other family's path byte-identical. The OptiQ 4-bit export stores the MLA projections and some expert planes at 8 bits under a 4-bit default, which aborted the process inside `quantized_matmul`, so both loaders now take each plane's width from its shapes. The checkpoint's tokenizer config omits `add_bos_token` and relies on the `Xing4_0Tokenizer` constructor's default of true, which mlxcel now honors. With these changes the 8-bit trace has 0 of 1190 decided top-1 disagreements against mlx-vlm, and perplexity is within 0.08%.

## 1. Problem Statement

### 1.1 The hyper connection

Between blocks the state is `[B, L, hc, D]` rather than `[B, L, D]`. Each sublayer (attention, then MLP) runs the same connection:

1. RMS-normalize the flattened `[hc * D]` state in f32 and mix it through `hc_fn` (`[(2 + hc) * hc, hc * D]`) in the activation dtype, promoting the result to f32.
2. Split the mix into `pre` (`hc`), `post` (`hc`) and `comb` (`hc x hc`). `pre = sigmoid(pre * s0 + b)` with no eps, `post = 2 * sigmoid(post * s1 + b)`, `comb = comb * s2 + b`.
3. Sinkhorn on `comb`: clip to [-30, 30], `exp(x - rowmax)`, then exactly `iters` rounds of row-normalize followed by column-normalize, each `x / (sum + eps)`.
4. Collapse the stream with `sum(pre * x, axis=2)`, run the sublayer on the collapsed `[B, L, D]`, and expand with `post * out + comb @ x`.

Embeddings enter repeated `hc` times. The head takes the mean over the streams and then the final norm.

DeepSeek-V4 has a hyper connection that looks similar. Its version uses softmax rows, adds eps to `pre`, starts with a column pass, and expands with `comb.T @ x`. Each of these is a plausible porting mistake, and none of them produces obviously broken text, so the validation includes negative arms for them (section 4).

### 1.2 Gaps in the shared code

| Gap | Effect on Xing4.0 | Effect elsewhere |
|---|---|---|
| `DeepSeekV3Attention` always called `fast_rope` at `rope_theta` | Wrong positional frequencies (the checkpoint carries a YaRN block) | The same for real DeepSeek-V3 and Kimi K2 YaRN checkpoints; not fixed here |
| `QuantizedMultiLinear::from_weights` stored the declared bits verbatim | OptiQ 4-bit: `embed_q` at 8 bits aborted in `quantized_matmul` | Any per-path override on an MLA family |
| `deepseek_v3::SwitchGLU` used one width for all three expert planes | OptiQ 4-bit: 8-bit expert planes aborted in `gather_qmm` | The same for DeepSeek-V3 per-path exports |
| SentencePiece path defaulted `add_bos_token` to false | No `<_start>` anchor; the trace diverged from the reference on position 0 | None (class-scoped rule) |

## 3. Design Decisions

**Composition over a copy.** Xing reuses `deepseek_v3::DecoderLayer::from_weights` and destructures it, so the MLA attention, the router and the experts are the same code DeepSeek-V3 runs. The cost is a few `pub(crate)` test helpers in `deepseek_v3.rs` and one new builder method on the attention.

**An opt-in RoPE table rather than a general YaRN fix.** Fixing YaRN for every DeepSeek-V3 family would change the output of released checkpoints (DeepSeek-V3, Kimi K2) without a trace on them. The table is installed only by Xing. Moonlight's before/after trace is byte-identical.

**Shape-derived widths only where the declared width cannot run.** Both loaders return the declared width whenever the shapes agree with it. The only layouts whose behavior changes are ones that previously aborted the process, and those now either load at the solved width or fail at load with the plane's name.

**fp16 MLA latent only.** `xing4_0` joins `MLA_LATENT_CACHE_FAMILIES` but not the quantized-latent list. The quantized latent has not been measured on this family.

## 4. Validation

Teacher-forced logit trace over `docs/architecture.md`, plan `64 40 8 1536` (2560 positions, BOS-anchored), scored by `scripts/compare_logit_traces.py --decided 2`:

| Comparison | Decided top-1 disagreements | Perplexity |
|---|---|---|
| mlxcel 8-bit vs mlx-vlm 8-bit | 0 / 1190 | 7.9571 vs 7.9506 (+0.08%) |
| vs mlx-vlm with `comb.T` expand | 180 / 760 | 45.10 for that arm |
| vs mlx-vlm with V4 Sinkhorn | 6 / 1156 | 8.49 for that arm |
| vs mlx-vlm without YaRN | 6 / 1159 | 8.31 for that arm |
| mlxcel OptiQ 4-bit vs mlx-vlm 8-bit | 0 / 1190 | 8.0360 (+1.07%) |
| mlxcel 8-bit vs mlx-vlm, single-token decode steps (48 positions) | 0 / 11 | +0.69% |

The negative arms show the trace is measuring the details that matter. The reference itself disagrees with its own negative arms on 494, 15 and 5 decided positions respectively. mlxcel's 0 against the reference is therefore a real separation, not tolerance hiding the difference.

Shared code: the `moonlight-16b-a3b-instruct-4bit` trace (plan `64 20 8 512`) built from `c0bcf575` and from this branch is byte-identical. It was repeated after each loader change.

End to end:
- `mlxcel generate --temp 0` is coherent on the 8-bit checkpoint (about 19 tok/s, 29.2 GB resident) and on OptiQ 4-bit (about 22 tok/s, 19.2 GB). Both answer `17 * 23` with 391.
- `mlxcel-server` on the 8-bit checkpoint returns coherent non-streaming and streaming chat completions.

Unit suites: `models::xing4_0` (16), `models::deepseek_v3`, `models::deepseek_v32`, `models::glm4_moe_lite`, `models::longcat`, `models::detection`, `models::registry`, `tokenizer::tests`, `coverage_tests`, and mlxcel-core `mla::`, `one_bit` and `layers::`. The GLM4 MoE Lite and LongCat latent-path tests that assert on the global MLA stats counters fail when the two modules run in parallel and pass with `--test-threads=1`. This happens with or without this change. Clippy with `-D warnings` and every contract check pass.

## 5. Known Limitations and Follow-ups

- Real DeepSeek-V3 and Kimi K2 YaRN checkpoints still run plain RoPE. Opting them in needs its own long-context trace.
- The OptiQ export logs one reconciliation warning per per-path layer at load (about 360 lines), as the existing `UnifiedLinear` path already does.
- Out of scope: MTP drafting, a fused Sinkhorn kernel (the loop adds about 6 small ops per iteration per sublayer), tensor-parallel sharding of the hyper connection, and a quantized latent cache for this family.
