# PR #3306: DeepSeek-V3와 LongCat MLA에 YaRN rope_scaling 적용

**날짜**: 2026-11-23
**상태**: 드래프트 PR (#3295 종료). 좁은 범위의 단위 테스트, clippy, fmt, CI 스크립트 통과. 실제 체크포인트로 mlx-lm과 비교한 trace 결과는 아래에 있다.
**위험도**: 중간 (MLA 다섯 계열이 공유하는 rope 코드. 그중 세 계열은 변경 전후 trace가 바이트 단위로 같다)

## 요약

`DeepSeekV3Attention`과 LongCat ngram MLA는 `rope_scaling` 설정과 관계없이 `q_pe` / `k_pe`를 일반 `base^(2i/d)` 주파수로 회전했다. 그 결과 DeepSeek-V3 계열과 LongCat-Flash-Lite의 모든 YaRN 체크포인트에서 저주파 쌍이 `factor`배 빠르게 회전했다. 이 PR은 공유 타입 `MlaRope`(`src/models/mla_rope.rs`)를 추가해 두 계열에 연결하고, 기존 사본 세 개(V3.2 `DsaRope`, LongCat sparse rope, Xing4.0 테이블)도 이 타입으로 옮긴다. GigaChat3-10B-A1.8B(`deepseek_v3`, YaRN 64, 원 컨텍스트 4096)에서 4096 이후의 결정적 위치 불일치는 수정 전 971/1264에서 수정 후 0/1264가 되었다.

## 1. 문제

upstream은 MLA 회전을 `initialize_rope(..., scaling_config=rope_scaling)`로 만들고, `yarn`과 `deepseek_yarn`에는 `YarnRoPE`를 쓴다. mlxcel의 DeepSeek-V3 attention은 이 블록을 softmax 스케일 보정(`get_attention_scale`)에만 썼고, LongCat ngram MLA는 아예 읽지 않았다. 두 테이블은 고주파 쌍에서 일치하므로 짧은 프롬프트에서는 문제가 보이지 않는다. 그러나 `original_max_position_embeddings`를 넘어가면 출력이 나빠진다. 수정 전 GigaChat3의 4096 이후 perplexity는 3047로, 참조의 16.65와 크게 다르다.

## 2. 변경 요약

| 영역 | 변경 |
| --- | --- |
| 공유 타입 | `MlaRope`: `resolve` / `from_block`(별칭 변환, `RopeScalingKind::resolve`, override를 반영한 plain base), `plain`, `duplicate`, `apply`, `apply_batched`. YaRN magnitude는 회전하는 차원에만 곱한다. |
| DeepSeek-V3 | `rope_base` / `rope_table`을 `rope: MlaRope`로 교체. attention과 decoder layer에 `from_weights_with_rope` 추가. 모델과 pipeline stage executor는 테이블을 한 번만 만든다. |
| LongCat | `LongcatFlashMLA`가 rope를 가진다. ngram 모델은 rope를 한 번만 만들고, sparse 모델은 자체 rope를 내부 MLA와 LSA indexer에 넘긴다. |
| 이동 | V3.2 `DsaRope`는 별칭이 되었고 `from_args` 검사는 유지된다. `SparseRope`는 `sparse_rope()`가 되었다. Xing4.0은 `MlaRope`를 쓰되 `linear` 거부는 유지한다. Youtu는 `MlaRope::plain`을 넘긴다. |
| 문서 | `supported-models.md`(V3, LongCat, Xing), `llama-server-compat.md`의 override 적용 범위, Used-by 목록, override 오류 메시지. |

## 3. 기술적 결정

### 3.1 타입은 하나로, 원 컨텍스트 기본값은 계열별로 유지

기존 사본 세 개의 차이는 블록에 `original_max_position_embeddings`가 없을 때 넘기는 `train_ctx` 하나뿐이었다. upstream `YarnRoPE`는 이 값이 없으면 4096을 쓰고 `max_position_embeddings`는 읽지 않는다. 그래서 DeepSeek-V3와 LongCat ngram은 `None`을 넘긴다. V3.2는 `None`, sparse와 Xing4.0은 `max_position_embeddings`를 계속 쓴다. 이 호스트의 체크포인트는 모두 원 컨텍스트를 명시하므로, 여기서 측정한 결과는 이 선택의 영향을 받지 않는다.

### 3.2 Youtu는 plain 유지

Youtu도 DeepSeek-V3 attention을 쓰지만, 항등으로 환원되는 블록(`yarn`, factor 1)만 허용한다. 이 블록으로 테이블을 만들면 plain 주파수와 반올림 오차 범위에서만 같은 factor 1 테이블이 생긴다. 그래서 `MlaRope::plain`을 넘겨 기존의 `fast_rope` 호출을 그대로 유지한다.

### 3.3 plain base 동작 변경 한 가지

기존 `SparseRope`의 테이블은 `--rope-freq-base`를 따랐지만, plain 회전은 이 옵션이 있어도 `rope_theta`를 썼다. `MlaRope`는 `DsaRope`와 Xing4.0처럼 테이블과 plain 회전 모두에 override를 적용한다. 이 차이는 override를 지정했고 테이블이 없는 경우에만 나타난다.

## 4. 검증

mlx-lm 1bf8da0을 참조로 teacher-forced `examples/logit_trace`를 실행했다. 음성 대조군은 main에서 빌드한 수정 전 바이너리다.

| 체크포인트 | 구간 | 결정적 위치 불일치 | 수정 전 | perplexity / 참조 |
| --- | --- | --- | --- | --- |
| GigaChat3-10B-A1.8B, 8-bit | 8192 위치 | 0 / 2774 | 989 / 2774 | 14.582 / 14.572 |
| 동일 | 4096 이후 | 0 / 1264 | 971 / 1264 | 16.688 / 16.652 |
| longcat-flash-lite-4bit | 36864 위치 | 39 / 20486 | 1709 / 20486 | 25.45 / 25.82 |
| 동일 | 32768 이후 | 6 / 2446 | 671 / 2446 | 17.92 / 17.49 |

- `deepseek_v3` 로더가 비양자화 MoE 체크포인트를 읽지 못해서, GigaChat3는 로컬에서 affine 8-bit로 양자화해 사용했다. upstream mlx-lm은 MTP 레이어 인덱스를 61로 고정하고 있어서, 인덱스 26의 MTP 레이어를 제거하는 shim이 필요했다.
- LongCat에서 mlx-lm으로 36864 토큰을 한 번에 forward하면 16384 이후 위치의 logit이 모두 같은 값(균일 분포)으로 나온다. 그래서 참조는 mlx-lm KV 캐시로 prefill했다. prefill 단위를 2048과 4096으로 바꿔도 결과 행이 동일하다.
- 변경 전후 바이트 단위로 같은 행: `moonlight-16b-a3b-instruct-4bit`(블록 없음), `xing4.0-29b-a4b-mlx-8bit`, `longcat-flash-lite-sparse-4bit`.
- 단위 테스트: 체크포인트 세 개의 형상에서 float64로 포팅한 `YarnRoPE`와 테이블 비교, 별칭, 블록이 없을 때의 바이트 동일성, magnitude, 합성 `deepseek_v3` YaRN 설정에서 원 컨텍스트 이후 `q_pe`가 바뀌는지, 테이블이 모든 레이어와 batched decode에 적용되는지, ngram 모델이 테이블을 가지는지.

## 5. 미검증 및 남은 항목

- LongCat에 남은 결정적 위치 불일치(gap 4.5 이하)는 위치가 뒤로 갈수록 늘어난다. 12288 이전에는 4096 위치 청크당 0~1개, 12288 이후에는 4~10개이고, 32768에서 계단처럼 늘지는 않는다. 참조는 prefill 단위를 바꿔도 결과가 변하지 않아 자체 노이즈가 없다. 따라서 이 잔차는 이슈의 기준인 "참조 자체의 노이즈"를 넘는다. 원인은 아직 밝히지 못했다.
- 실제 DeepSeek V3.2와 Kimi-K2 체크포인트로는 trace를 돌리지 않았다. V3.2 rope 테스트는 수정 없이 통과한다.
- `deepseek_v3` 로더가 비양자화 MoE 체크포인트를 읽지 못한다(`switch_mlp.*.scales`를 찾는다). 이 PR과는 별개의 문제다.
- LongCat latent 테스트 세 개는 이 PR과 무관하게 병렬 실행 시에만 실패한다. 원인은 전역 MLA stats 카운터다(#3298).

## 6. 배운 점

- 긴 컨텍스트를 trace하려면 그 길이에서도 유효한 참조가 필요하다. LongCat에서 mlx-lm의 단일 forward는 16384 이후 오류 없이 잘못된 값을 냈고, 청크별 perplexity로 이를 발견했다.
- 모든 위치의 회전을 바꾸는 변경에서는 수정 전 결과를 노이즈 기준으로 쓸 수 없다. 수정 전 결과는 trace가 버그를 잡아내는지만 보여 준다.
