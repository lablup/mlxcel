# Technical Report: PR #3281 - Add Hy4 (`hy_v4`) support

**Date**: 2026-11-23
**Reviewer**: -
**Status**: PR open (closes #2354); validated on the real checkpoint, with follow-ups listed in section 7
**Languages**: Rust, Python (trace script), Bash (validation script)
**Risk Level**: Low (new model family; the DeepSeek-V3.2 forward path is untouched)

---

## Executive Summary

Tencent Hy4 (`model_type: hy_v4`, `mlx-community/Hy4-preview-4bit`) failed to load with `Unsupported model type: hy_v4`. This PR adds it as a child module of `deepseek_v32`, so it reuses the V3.2 MLA, DSA indexer, MoE loaders and the shared `DsaRope`, and adds Hy4's own parts: an identity hyper-connection residual, a gated MLA with learnable attention sinks, and indexers shared across layers.

On an M3 Ultra (512 GB) the 4-bit checkpoint loads in 59 to 61 s, holds 403.6 GB resident (peak footprint about 435.6 GB) and decodes at 14.3 to 14.5 tok/s. Against mlx-vlm there are 0 of 125 disagreements on decided positions (0 of 55 with a 4096-token context where the indexer selects). The server splits `<think:opensource>...</think:opensource>` into `reasoning_content`. Tool calls, the `hy_v4_mtp` drafter and a quantized-latent trace with the indexer selecting are left open.

## 1. Problem Statement

### 1.1 Background

Issue #2354 asks for Hy4 support. The model is a DeepSeek-V3.2 derivative (MLA with absorbed `embed_q` / `unembed_out`, a DSA lightning indexer, a noaux_tc MoE) with three changes that no existing family has together.

### 1.2 Existing Issues

- **No loader**: `hy_v4` was not in the registry or the detection table.
- **No sink-capable MLA**: no V3.2 attention kernel takes an attention sink, and the output needs a per-head sigmoid gate.
- **Shared indexers**: `indexer_types[i]` is `full` (the layer owns an indexer and caches its key beside the latent) or `shared` (no indexer, no indexer key in the cache; the layer reuses the selection of the nearest earlier `full` layer). The cache layout and the memory estimate (`kv_arch`) differ per layer.
- **Reasoning tags**: the first server smoke returned the raw `<think:opensource>` tag in `content`.

### 1.3 Risk Assessment

| Risk | Impact | Likelihood |
|------|--------|------------|
| Silent numeric drift (RoPE pairing, sinks, gate, `swiglu_limit`) that unit tests on a synthetic checkpoint cannot see | High | Medium |
| Change to the shared V3.2 forward breaks `deepseek_v32` | High | Low (the forward is untouched; only a module declaration is added) |
| The 433 GB checkpoint exhausts memory or swaps | Medium | Low (no swap observed) |
| A quantized latent over the DSA indexer degrades top-k selection | Medium | Unmeasured on Hy4 |

## 2. Architecture

```
tokens -> embed -> h [B, L, hc_mult, hidden]
  per block:
    x   = hyper.collapse(h)            (pre gate)
    a   = gated sink MLA(norm(x))      (full or shared indexer)
    h   = hyper.expand(h, a)           (post gate)
    x   = hyper.collapse(h)
    m   = MoE(norm(x))
    h   = hyper.expand(h, m)
  head: hyper head collapse -> norm -> lm_head
```

### 2.1 Identity hyper connection (`hy_v4_hyper.rs`)

The residual carried between blocks has shape `[B, L, hc_mult, hidden]` (`hc_mult` is 4 in the checkpoint). Each sublayer collapses it with a learned `pre` gate and folds its output back with a learned `post` gate:

```
x    = rms_norm(flatten(h), no weight) @ hc_fn.T      [B, L, 2 * hc]
pre  = sigmoid(x[..., :hc] * hc_scale[0] + hc_base[:hc]) + hc_eps
post = hc_magnitude * sigmoid(x[..., hc:] * hc_scale[1] + hc_base[hc:])
in   = sum(pre[..., None] * h, axis = hc)
h'   = h + post[..., None] * out[:, :, None, :]
```

This is the DeepSeek-V4 hyper connection with the `comb` output dropped. The streams are never mixed, so there is no Sinkhorn step and `hc_fn` has `2 * hc` rows instead of `(2 + hc) * hc`. `deepseek_v4_hyper.rs` is not reusable, because its shape check rejects these tensors. The math runs in float32 over an f32 copy of the residual, and only the collapsed input and the expanded residual are cast back. The `hc_*` tensors ship as float32 and stay float32. The transformers reference also adds `hc_eps` to `post`; mlx-vlm does not, and this port follows mlx-vlm (the term is 1e-6 against a gate of order 1).

### 2.2 Gated MLA with sinks (`hy_v4_attention.rs`)

The attention forward is Hy4's own. Every step runs MLX's SDPA with sinks, then multiplies the per-head output by `sigmoid(linear_gate(x))`. The MLA projections (`embed_q`, `unembed_out`, latent norm) come from `deepseek_v32`.

### 2.3 Shared indexer layers

- A `full` layer runs the lightning indexer, caches `[kv_latent | indexer key]` and publishes its top-k.
- A `shared` layer caches the latent alone and attends to the published selection: a gather at decode, a sparse mask at prefill, and a dense fallback while `kv_len <= index_topk`.

`kv_arch` sizes the indexer key on `full` layers only, so the memory estimate matches the cache.

### 2.4 MoE (`hy_v4_moe.rs`)

noaux_tc routing scored in float32, then the stacked `switch_mlp.{gate,up,down}_proj` experts with the `swiglu_limit` clamp on the routed experts. The routing and the `SwitchGLU` forward are restated here instead of parameterizing the V3.2 ones (see 3.8).

### 2.5 Composition with `deepseek_v32` and `DsaRope`

`hy_v4` is declared as a child module of `deepseek_v32`, which gives it access to the private MLA, indexer and MoE pieces and their loaders without widening visibility. The only change in `deepseek_v32.rs` is the module declaration, so no V3.2 before/after trace was needed. RoPE uses the shared `DsaRope`. The scope is the mlx-community affine conversion; the original mxfp8 `tencent/Hy4-preview` layout (`kv_b_proj`, fused `gate_up_proj`) is refused.

The loader fails with a message on `hc_*` shapes that disagree with `hc_mult * hidden_size`, an `indexer_types` of the wrong length or value, and indexer weights that disagree with `indexer_types`.

## 3. Technical Decisions

### 3.1 Interleaved RoPE

**Context:** mlx-vlm rotates interleaved pairs (`traditional=True`, inherited from its V3.2 attention); the transformers reference rotates half-split pairs. The first commit followed mlx-vlm and left the question open until a real-checkpoint run.

**Alternatives Considered:**

| Option | Result on the real checkpoint |
|--------|-------------------------------|
| Half-split (transformers) | mean NLL 3.9121 over 256 positions |
| **Chosen: interleaved (mlx-vlm)** | mean NLL 2.1995 over 256 positions |

**Rationale:** the same tokens are far more likely under interleaved pairing, so the checkpoint was trained that way. The `rope_half_split` arm of `MLXCEL_HY4_ARM` stays for re-running the comparison.

### 3.2 `swiglu_limit` on the routed experts

The checkpoint config sets `swiglu_limit` to 10.0. Transformers clamps the routed experts with it; mlx-vlm applies nothing. It is applied here, to the routed experts only, because it is part of the model as trained. The `no_swiglu_limit` arm reproduces mlx-vlm. The two arms agree at every decided position (0/125 each), with perplexity +0.47% for the no-limit arm and +0.53% for the shipped model against mlx-vlm.

### 3.3 `lm_head` is not run in fp32

Transformers sets `enable_lm_head_fp32`. The MLX checkpoint ships `lm_head` 4-bit with bf16 scales, and mlx-vlm runs it in the activation dtype. This port does the same. Casting a quantized head to f32 would not recover precision that was dropped at quantization.

### 3.4 Quantized latent

| Option | Pros | Cons |
|--------|------|------|
| Add `hy_v4` to `QUANTIZED_LATENT_FAMILIES` (`auto` picks int8) | Smaller cache by default | Not proven where the indexer selects |
| **Chosen: keep it out, accept explicit `--mla-latent-quant int8\|int4`** | Same stance as `deepseek_v32`; users can opt in | Opt-in only, labelled experimental |

**Rationale:** the decided-position gate passes (below), but both latent traces ran behind 512 tokens, where `kv_len <= index_topk`, so the indexer's top-k overlap over a quantized slot was not exercised. That is the gate DeepSeek-V3.2 missed (#3163). `auto` keeps fp16. `hy_v4` joins the latent-pair and DSA key families so the explicit option works; the CLI prints an experimental note with the measured numbers.

### 3.5 Per-row batched decode fallback

No batched kernel takes Hy4's sinks, hyper residual and shared-selection handoff. Batched decode uses the per-row fallback, which is correct and slower than a native batch. `HyV4Model` is listed in `EXPECTED_PER_ROW_FALLBACK` in `batched_decode_coverage_tests.rs`.

### 3.6 Reasoning tags

The server registers `<think:opensource>` / `</think:opensource>` at the same five sites as K2-Horizon, so `reasoning_content` is split from `content`. The delimiters are ASCII table entries, `<think:opensource>` does not prefix-collide with `<think>`, and the Hy4 tokenizer has no `<think>` token that would shadow the pair in the thinking-budget lookup.

### 3.7 Parity arms

`MLXCEL_HY4_ARM` selects `no_sinks`, `no_gate`, `no_swiglu_limit` or `rope_half_split`. An arm that must fail proves the trace can see the feature; an arm that must pass shows a decision is invisible at decided positions. A non-UTF-8 value is now an error instead of being read as unset.

### 3.8 Restated MoE

`hy_v4_moe.rs` restates the V3.2 `MoEGate` routing and `SwitchGLU` forward with f32 routing and the clamp. This keeps the V3.2 forward byte-identical at the cost of duplicated code, a deliberate trade recorded for a later refactor.

## 4. Validation

M3 Ultra, 512 GB, `iogpu.wired_limit_mb` 491520, `mlx-community/Hy4-preview-4bit`.

### 4.1 Memory and speed

| Run | Peak footprint | Notes |
|-----|----------------|-------|
| `generate -p "Hello" -n 50` | 434.1 GB | 403.6 GB resident, 14.26 to 14.48 tok/s over three runs |
| `mlxcel-server` | 434.2 GB | `/v1/chat/completions` returned 200, 40 tokens |
| Logit traces | up to 435.6 GB | no swap in any run |

Load takes 59 to 61 s. The generate smoke returns coherent text. The server's first response carried the raw reasoning tag in `content`, which led to the tag split in 3.6.

### 4.2 Logit parity against mlx-vlm

Decided positions are those where the reference's top-two logit gap is at least 2. The gate is the decided-position disagreement count.

| Arm | Decided disagreements | Perplexity vs reference |
|-----|-----------------------|-------------------------|
| Shipped model | 0 / 125 | +0.53% (1/256 top-1 overall, at a gap of 0.06) |
| `no_swiglu_limit` | 0 / 125 | +0.47% |
| Shipped, `LONG=1` (4096 tokens, indexer selecting) | 0 / 55 | -0.99% |
| `no_swiglu_limit`, `LONG=1` | 0 / 55 | -1.01% |
| `no_sinks` (must fail) | 78 / 125 | perplexity 7528 |
| `no_gate` (must fail) | 124 / 125 | perplexity 1.6e6 |

The two arms that must fail do fail, so the trace is sensitive to sinks and the gate.

### 4.3 Quantized latent vs fp16 latent

| Latent | Decided disagreements | Top-1 agreement | Perplexity |
|--------|-----------------------|-----------------|------------|
| int8 | 0 / 124 | 98.0% | +1.00% |
| int4 | 0 / 124 | 95.7% | +0.68% |

Both generate coherent text and report `effective int8; applied to 78 of 78 layers`. Both ran at 512 tokens, where the indexer selects nothing.

### 4.4 Tests

Synthetic-checkpoint unit tests cover shared-layer selection and cache layout, hyper-connection math, sink semantics, the parity arms, prefill and decode agreement, int8/int4 latent, bf16 stability, plain default RoPE and the reasoning split. Review ran the `hy_v4` selector (39 tests), `coverage_tests`, the latent-option, `kv_arch` and DSA resolver tests, clippy with `-D warnings`, `cargo fmt --check` and the `scripts/ci` contract checks. No model or test was run for this report.
