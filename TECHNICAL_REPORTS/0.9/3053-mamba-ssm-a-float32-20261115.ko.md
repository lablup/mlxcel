# 기술 리포트: PR #3053 - f16 로드에서도 유한하도록 Mamba의 SSM A를 float32로 유지

**작성일**: 2026-11-15
**상태**: PR 열림 (draft, #3046 해결)
**검토자**: -
**언어**: Rust
**위험도**: 낮음

---

## 요약

`mlx-community/mamba-130m-hf-bf16`은 Apple Silicon에서 로드는 되지만 토큰을 하나도 생성하지 않았습니다. Apple Silicon은 bf16 체크포인트를 로드 시점에 f16으로 변환하는데, `MambaBlock::forward`는 `A = -exp(A_log)`를 그 f16 dtype에서 계산했습니다. f16은 11.09를 넘는 값의 `exp`를 표현하지 못하며, 이 체크포인트에는 그 값을 넘는 `A_log` 항목이 1530개 있어 `A`에 `-inf`가 생겼습니다. f16 `softplus` step이 0으로 반올림된 채널에서는 decay가 `exp(0 * -inf) = NaN`이 되었고, 첫 토큰에서 모든 logit이 NaN이 되었으며, greedy 샘플링은 이 모델의 EOS인 토큰 0을 골랐습니다.

이 PR은 transformers와 같이 `A_log`의 float32 복사본으로 로드 시점에 `A`를 한 번 계산합니다. bf16과 float32 모델은 여전히 activation dtype의 `A`를 읽으므로 출력이 이전과 비트 단위로 같습니다. f16 모델은 `A`를 float32로 읽습니다. fused Metal 커널은 그대로 받아 쓰고, graph scan은 `delta * A`와 그 `exp`를 float32로 계산한 뒤 decay만 f16으로 되돌립니다. 실제 체크포인트에서 bf16 모델은 이제 24개 토큰을 생성하며, fused 커널, graph scan, CPU 모두에서 같은 가중치의 transformers 출력과 일치합니다.

---

## 1. 문제 정의

### 1.1 배경

Mamba의 selective scan은 상태 전이를 `A_log`로 저장하고 `A = -exp(A_log)`를 사용합니다. scan은 각 timestep마다 채널별 decay `exp(delta * A)`를 계산하고(`delta = softplus(dt_proj(...))`) 이전 상태에 곱합니다. `A`는 음수, `delta`는 양수이므로 decay는 (0, 1] 구간에 있습니다.

Apple Silicon에서 mlxcel은 `MLXCEL_KEEP_BF16`이 없으면 bf16 체크포인트를 로드 시점에 f16으로 변환합니다(`bf16_to_f16_at_load`, `convert_bf16_weights`). `mamba-130m`의 모든 텐서는 저장된 값 자체로는 f16에 들어갑니다(최대 `A_log`는 26.0으로 65504보다 훨씬 작음). 오버플로는 `exp` 이후에만 발생합니다.

### 1.2 기존 문제점

bf16 체크포인트를 f16으로 변환한 뒤의 실패 경로는 다음과 같습니다.

1. `A = -exp(A_log)`가 f16으로 실행됩니다. f16의 최대 유한값은 65504 = `exp(11.09)`입니다. `A_log`는 19.5까지 올라가며, 24개 레이어 중 23개에 걸쳐 589824개 중 1530개 항목이 11.09를 넘으므로 해당 `A`는 `-inf`가 됩니다.
2. `dt_proj.bias`는 -20.6까지 내려갑니다. 이 채널에서 `softplus`는 약 `exp(-20.6)`, 즉 1e-9 정도를 반환하는데, 이는 f16의 최소 subnormal(약 6e-8)보다 작아 정확히 0으로 반올림됩니다.
3. 0인 `delta`와 `-inf`인 `A`가 만나면 decay는 `exp(0 * -inf) = exp(NaN) = NaN`입니다.
4. NaN은 상태로, 이어서 `y`로, 첫 토큰의 모든 logit으로 퍼집니다.
5. 전부 NaN인 logit에 대한 greedy argmax는 인덱스 0을 반환합니다. 이 모델에서 토큰 0은 `eos_token_id`이므로 오류 없이 출력 없이 생성이 끝납니다.

float32 체크포인트와 `MLXCEL_KEEP_BF16`에서는 버그가 나타나지 않았습니다. float32와 bf16 모두 `exp(19.5)`(약 2.9e8)를 표현할 수 있기 때문입니다.

### 1.3 위험성

| 위험 | 이전 | 이후 |
|------|------|------|
| Apple Silicon의 bf16 Mamba 체크포인트 | 조용히 0개 토큰 출력 | 정상 출력 |
| bf16 / float32 수치 | 기준 | 비트 단위 동일 (A를 activation dtype으로 반올림) |
| f16 graph scan 수치 | NaN | float32 decay를 f16으로 한 번 반올림 |
| 같은 패턴을 가진 다른 SSM 모델 | 노출 | 여전히 노출 (8절 참고) |

## 2. 기술적 검토 사항

### 2.1 보안 관점

해당 없음. 입력 처리, 파싱, unsafe 코드에 변경이 없습니다.

### 2.2 성능 관점

- `A`는 forward 호출마다 `exp`와 `negative`를 실행하는 대신 로드 시점에 레이어마다 한 번 계산됩니다. 호출당 bf16과 float32 모델은 `astype` 하나, f16 모델은 `copy` 하나를 실행하며, 이는 기존의 elementwise 연산 두 개를 대체합니다.
- 메모리: 로드된 dtype의 `A_log` 대신 float32 `A`를 저장합니다. `mamba-130m`에서는 589824개 항목 곱하기 4바이트로 전체 약 2.4 MB이며, 이전에는 약 1.2 MB였습니다. 무시할 수 있는 수준입니다.
- f16 graph scan은 step마다 decay의 `astype`이 하나 늘어납니다. fused 커널 경로는 float32 `A`를 읽는 것 외에는 변하지 않았습니다.

벤치마크는 돌리지 않았습니다. 이 변경은 scan의 나머지 부분에 비해 측정 가능한 수준으로 핫 루프를 건드리지 않습니다.

### 2.3 호환성/의존성 관점

- 새 의존성, 설정, CLI 변경이 없습니다.
- fused selective scan은 이미 상태를 float32 레지스터에 두고 `mamba1_scan_kernel_accepts`로 `A`를 받습니다. 검증 결과 f16 activation과 함께 float32 `A`를 받아 처리합니다.
- 구조체 필드가 `a_log`에서 `a`로 바뀝니다. `mamba_tests.rs`의 테스트 fixture 두 개(`tiny_mamba_block`, `varied_mamba_block`)가 `ssm_a_from_log`를 호출하도록 수정되었습니다.

### 2.4 코드 품질 관점

- dtype 결정이 한 곳(`MambaBlock::scan_a`)에 있어 두 scan이 같은 `A`를 읽습니다.
- `ssm_step`의 f16 decay 변환은 dtype이 다를 때만 실행되므로 bf16과 float32에서는 아무 작업도 하지 않습니다.
- clamp나 mask를 쓰지 않습니다. NaN을 사후에 가리는 대신 오버플로를 원인 지점에서 제거합니다.

## 3. 기술적 선택과 그 이유

### 3.1 f16에서 clamp하지 않고 로드 시점에 float32로 A 계산

**검토한 선택지:**

| 선택지 | 결과 |
|--------|------|
| `A_log`(또는 `A`)를 f16 범위로 clamp | 모델이 바뀜: clamp된 `A`는 학습된 값보다 느리게 감쇠 |
| decay의 NaN을 0으로 치환 | 증상만 가림. `delta`가 0이 아닌 경우 오버플로된 1530개 항목에 여전히 틀린 `A` 사용 |
| `A_log`를 f16 변환에서 제외해 bf16 또는 float32로 유지 | 표현 문제는 해결되지만 호출마다 `exp`를 계산하며, 로드 시점 정책과 계속 맞춰야 함 |
| 로드 시점에 `A = -exp(float32(A_log))`를 한 번 계산 | transformers(`-torch.exp(self.A_log.float())`)와 일치하며 로드 dtype 정책과 무관 |

PR은 마지막 선택지를 택했습니다. `ssm_a_from_log`는 `A_log`를 float32로 변환하고 `-exp`를 계산한 뒤, 다른 가중치와 함께 실체화되도록 결과를 evaluate합니다.

### 3.2 bf16과 float32를 비트 단위로 동일하게 유지

`scan_a`는 f16을 제외한 모든 dtype에서 float32 `A`를 activation dtype으로 반올림합니다. bf16에서는 이전 코드가 만들던 값과 정확히 같습니다. MLX의 bf16 `exp`는 내부적으로 float32로 계산한 뒤 한 번 반올림하므로, float32 `-exp(A_log)`를 반올림한 것과 같기 때문입니다. 이로써 변경이 고장 난 경우에만 국한되고, 기존 bf16과 float32 출력은 다시 검증할 필요가 없습니다.

### 3.3 f16에서는 decay만 f16으로 되돌림

f16 graph scan에서 `delta * A`는 f16 `delta`와 float32 `A`를 섞으므로 MLX가 곱과 그 `exp`를 float32로 승격합니다. 그 다음 decay를 f16으로 되돌립니다. decay는 (0, 1]에 있으므로 이 변환은 오버플로할 수 없고, 상태와 `y`, 그 이후 모든 값은 이전처럼 f16에 머뭅니다. `delta = 0`이고 `A`가 매우 큰 음수인 채널은 이제 float32에서 `exp(0 * -2.9e8) = exp(-0) = 1`을 얻으며, 이는 수학적으로 올바른 decay입니다.

## 4. 구현 상세

### 4.1 아키텍처 변경

```
로드:     A_log (임의 dtype) --astype f32--> -exp --> A (f32, evaluate됨), MambaBlock에 저장
Forward:  scan_a(x_conv): f16 -> copy(A)로 f32 유지, 그 외 -> astype(A, x dtype)
          fused 커널: 받은 A를 그대로 읽음
          graph scan: decay = exp(delta * A), x dtype과 다르면 변환
```

### 4.2 주요 코드 변경

**파일: `src/models/mamba.rs`**
```rust
pub(crate) fn ssm_a_from_log(a_log: &MlxArray) -> UniquePtr<MlxArray> {
    let a_log = mlxcel_core::astype(a_log, mlxcel_core::dtype::FLOAT32);
    let a = mlxcel_core::negative(&mlxcel_core::exp(&a_log));
    mlxcel_core::eval(&a);
    a
}
```
**변경 이유:** `A`를 계산하는 유일한 지점이며, 학습된 모든 값을 담을 수 있는 dtype을 씁니다.

```rust
fn scan_a(&self, x: &MlxArray) -> UniquePtr<MlxArray> {
    let dtype = mlxcel_core::array_dtype(x);
    if dtype == mlxcel_core::dtype::FLOAT16 {
        mlxcel_core::copy(&self.a)
    } else {
        mlxcel_core::astype(&self.a, dtype)
    }
}
```
**변경 이유:** bf16과 float32를 비트 단위로 동일하게 유지하고, f16에는 float32 `A`를 줍니다.

`ssm_step`에서는 decay와 activation의 dtype이 다를 때(f16일 때만) decay를 activation dtype으로 변환합니다.

**파일: `src/models/mamba_tests.rs`**

- `mamba_f16_converted_bf16_checkpoint_produces_finite_logits`: 네 채널의 `A_log`가 19.5이고 두 채널의 `dt_proj.bias`가 -30인 2레이어 모델을 만들고, 모든 텐서를 bf16으로 저장한 뒤 실제 `convert_bf16_weights`를 실행하여 `MambaModel::load`가 만들 것과 같은 f16 텐서로 모델을 구성합니다. 토큰 4개를 prefill하고 1개를 decode하여, 기본 디바이스(GPU의 fused 커널)와 CPU(graph scan) 모두에서 logit이 유한하고 둘의 차이가 5e-2 미만인지 확인합니다.
- `mamba_ssm_a_is_float32_and_finite_for_an_f16_a_log`: f16 `[0, 11, 19.5]`에 대한 `ssm_a_from_log`가 상대 오차 1e-6 이내로 float32 `[-1, -exp(11), -exp(19.5)]`를 반환하는지 확인합니다.

### 4.3 데이터 모델 변경

`MambaBlock.a_log`가 `MambaBlock.a`(float32)로 바뀝니다. 저장되는 상태나 파일 형식에는 변경이 없습니다.

## 5. 학습 포인트

### 5.1 dtype에 들어가는 텐서도 연산 하나 뒤에 오버플로할 수 있다

**개념:** 모델이 가중치에 `exp`처럼 값을 키우는 연산을 적용한다면, 모든 가중치가 대상 dtype에 들어가는지만 확인해서는 부족합니다. f16의 범위는 `exp(11.09)`에서 끝나지만 bf16과 float32는 훨씬 넓습니다. 저장된 모든 텐서에 안전한 변환이라도 파생 텐서는 무한대가 될 수 있습니다.

**이 PR에서의 적용:** `A_log`의 최댓값은 26.0으로 f16에 여유 있게 들어가지만 `exp(A_log)`는 들어가지 않습니다. 수정은 값을 키우는 연산을 범위를 좁히는 변환보다 앞으로 옮기며, 이는 transformers가 쓰는 순서입니다.

### 5.2 NaN은 정상 종료처럼 보일 수 있다

전부 NaN인 logit에 greedy 샘플링을 하면 인덱스 0이 나옵니다. 토큰 0이 EOS라면 모델은 오류 없이 빈 출력으로 정상 종료한 것처럼 보입니다. "토큰 0개" 보고를 받으면 첫 logit이 유한한지부터 확인하는 것이 빠릅니다.

### 5.3 기준 구현과 일치한다는 것은 같은 가중치에서 일치한다는 뜻이다

이슈는 bf16 출력이 f32 체크포인트와 같기를 요구했습니다. 이는 성립할 수 없습니다. bf16 체크포인트는 f32 체크포인트를 bf16으로 반올림한 것과 정확히 같고(242개 텐서 중 242개), 그 반올림된 가중치로 실행한 transformers도 6번째 토큰에서 f32와 갈라집니다(`,` 대 `.`). 올바른 기준은 동일한 가중치에서 기준 구현과 일치하는 것이며, 이 PR은 토큰 단위로 이를 만족합니다.

**예제 코드:**
```python
# 같은 계산에 대한 transformers의 기준 구현
A = -torch.exp(self.A_log.float())
```
