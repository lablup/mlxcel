# PR #3449: OpenXLA/IREE PLaMo 2 하이브리드

**날짜**: 2026-11-26

**상태**: CPU/CUDA 수락 검증 통과, ROCm 재검증은 외부 진행 대기

## 요약

PLaMo 2가 원본 `pfnet/plamo-2-1b` 가중치로 OpenXLA/IREE에서 실행된다. Mamba2 변형 블록 8개와 sliding-window attention 블록 8개가 번갈아 나오고 각 블록 뒤에 MLP가 붙으며, 기존 하이브리드 KV·recurrent 상태 계약을 그대로 쓴다. 수락 검증 중 짧은 시퀀스 오라클로는 보이지 않는, 상속된 RoPE scaling 오류를 찾았고, HF가 경계를 포함하는 방식으로 정의한 window 경계를 고정했다.

## 문제

`from_json_str`가 `plamo2`를 거부했다. 이슈는 PLaMo 2를 dt/B/C RMSNorm이 붙은 Mamba2로 설명했지만, 체크포인트와 HF 코드는 그보다 많은 것을 요구한다. 블록마다 offset이 서로 다른 정규화 4개, head별로 z/x가 교차된 입력 projection, 컨볼루션 뒤에서 projection되는 B/C/dt, gated 출력 정규화 없음, 가중치 없는 head별 RMSNorm 뒤의 학습된 head별 Q/K 배율, 그리고 `age <= W`인 key를 유지해 기존 XLA local mask보다 한 칸 넓은 2048토큰 window다. HF remote code는 CUDA 전용 `mamba_ssm`이 필요해 HF CPU 오라클을 만들 수 없다.

## 변경 내용과 기술적 결정

`SsmKind::Plamo2`(`ssm_plamo2.rs`)는 공용 conv와 selective-scan 헬퍼로 mixer를 만들고, SSD 내부와 Mamba1은 건드리지 않는다. 정규화 offset 4개는 그래프에서 가중치에 더하고 공용 `GemmaFf` 4-정규화 배치를 그대로 쓰므로 다른 계열의 그래프는 바뀌지 않는다. Q/K 배율은 `[heads, head_dim]` 형태를 지원하도록 확장했다. Plamo2는 `sliding_window = W + 1`로 저장해, 공용 mask 코드를 바꾸지 않고 기존 `age < sliding_window` mask로 HF의 경계 포함 window를 재현한다.

dt time step은 MLX eager 오라클을 따라 `softplus(dt + dt_bias)`를 (0.001, 100)으로 clamp한다. HF CPU 경로에는 clamp가 없다. 패딩된 prefill 행은 여전히 `dt = 0`이다. 설정이 처음에는 Llama-3.2 기본값에서 `RopeScaling::Llama3`(factor 32)를 상속했는데, 이제 plain RoPE를 쓰고 단위 테스트로 이를 확인한다.

## 검증과 증거 범위

40토큰 오라클은 MLX eager CPU 실행(F32, revision `92c75fd6`)이다. 구조적 독립성은 HF 수식을 float64로 다시 구현하고 순차 scan을 쓰는 `plamo2_oracle.py`에서 온다. local-task와 CUDA 모두에서 실제 체크포인트가 40/40 일치했고, 하이브리드 합성 정합성(최악 6.9e-6, 1.0e-5)과 window 검사(prefill, decode, ragged decode, 최악 4.2e-6, 5.4e-6)를 통과했다. window 검사는 같은 가중치를 W = 2047, 2048, 2049로 로드해 각각 자기 기준 mask를 따르는지, 세 궤적이 서로 다른지 확인하므로 한 칸 차이가 우연히 통과할 수 없다. 합성 head의 절반은 dt clamp 하한에 걸리도록 두어, clamp를 빼면 허용 오차 3e-4에서 실패한다.

CUDA에서 `validate_arch.sh --batch 4 --requests 8 --maxcap 24 --oracle`가 exit 0으로 끝났고, 서버 HTTP 4건과 SSE 4건이 CLI 표시 문자열 및 토큰 수와 일치했다. lib 테스트는 기존 golden을 모두 바이트 단위로 유지했고, fmt, clippy, 프롬프트 캐시/APC 가드, 환경변수 문서 검사, Used by 검사를 통과했다. 증거는 `spike/openxla/plamo2_reference/`에 있다.

검증하지 않은 것: ROCm `hip`, CLI/서버 검사에서 토큰 id의 Python 재디코딩(체크포인트에 `tokenizer.jsonl`만 있음), 단일 시퀀스 window 검사의 로짓(그 경로는 토큰만 확인하고 로짓은 ragged 경로에서 확인), clamp된 dt의 HF 수치 동등성.

## 배운 점과 후속 작업

다른 모델의 기본값 위에 만든 계열 설정은 덮어쓰지 않은 모든 필드를 상속하며, 위치 인코딩도 예외가 아니다. 짧은 오라클은 저주파 RoPE 오류를 잡지 못하므로, 새 계열의 수락 검증에는 긴 위치 검사가 들어가야 한다. Falcon-H1도 같은 기본값 위에서 `rope`를 덮어쓰지 않아 교정이 필요하다. 머지 전에 Jamba(#3448) 뒤로 rebase하고, 최종 head에서 외부 ROCm 재검증을 요청한다.
